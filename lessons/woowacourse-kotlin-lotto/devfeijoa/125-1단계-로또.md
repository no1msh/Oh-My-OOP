### 2. `LottoResult` — 이름과 책임 불일치

```kotlin
class LottoResult(...) {
    fun calculate(...): Map<Rank, Int> = ...
    fun profitRate(...): Double = ...

```

> LottoResult 라는 이름이라 어떠한 결과 값들을 가지고 있을 거라 기대했는데, 결과를 계산하는 객체였네요! 이 객체는 너무 많은 역할을 하고 있다는 느낌이 들어요.

→ 이름 `LottoResult` = 보유, 실제는 계산. 두 책임 (계산 + 표현) 분리.

### 3. `LottoStore`와 `LottoGenerator` 차이?

```kotlin
val tickets = lottoStore.getTickets(...)
// vs
val tickets = lottoGenerator.generate(...)
```

> 아래 두 코드에서 많은 차이점이 있었나요?

→ "Store" (보유) vs "Generator" (생성) — 도메인 의미 다름. 학생이 *Store*를 *Generator*처럼 쓴 경우.

## 얻은 교훈

- **이름은 *반환 결과*가 아니라 *책임*을 표현**. `LottoResult`가 계산만 = god-object. *Result*는 보유, *Calculator*는 계산, *Formatter*는 표현.
- **현실 어휘 차이** — Store vs Generator. 비유로 도메인 의미 검증.
- **함수 하나만 가진 클래스** = top-level fun 또는 도메인 객체의 메서드.
