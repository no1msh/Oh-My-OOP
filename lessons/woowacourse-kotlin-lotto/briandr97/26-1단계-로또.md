## 못한 점 + 핵심 지적

### 1. `Bank` object god-helper

```kotlin
object Bank {
    fun calculate(...): Int = ...
    fun statistics(...): Map<Rank, Int> = ...
}
```

> Bank object가 하는 역할이 WinStatistics나 WinningResult에 없는 이유가 뭘까요? 애초에 저희가 일급 컬렉션을 만들거나 원시값을 포장하는 이유가 뭘까요?

→ Bank가 외부 비교/통계 책임 = god-object. WinStatistics 같은 도메인 객체로 위임.

### 2. enum 추가 시 코드 수정 필요

```kotlin
when (rank) {
    Rank.FIRST -> ...
    Rank.SECOND -> ...
    // Rank 추가 시 매번 추가
}
```

> Rank값이 추가될때마다 매번 이 코드를 수정해줘야 할까요? 힌트: enum 클래스에서 제공하는 함수를 이용해보세요.

→ `Rank.entries.forEach { ... }`로 자동 순회.

### 3. `Judgement` object도 god-helper

```kotlin
object Judgement {
    fun rank(lotto: Lotto, winning: WinningLotto): Rank = ...
}
```

> Judgement object가 하는 역할이 WinningNumbers, 혹은 WinningResult나 ComparingResult에 없는 이유가 뭘까요? 객체에 메시지를 전달하는 것이 아니라 값을 직접 꺼내어(get) 조작한다면 애초에 저희가 일급 컬렉션을 만들거나 원시값을 포장하는 이유가...

## 얻은 교훈

- **god-object 패턴의 다른 이름들** — `Bank`, `Judgement`, `Analyzer`, `Calculator`, `Manager` 모두 외부에서 데이터 꺼내 처리. 도메인 객체 메시지로.
- **enum 자동 순회 = OCP** — `entries.forEach`로 enum 추가 시 코드 무수정.
- **원시값 포장의 *목적***은 *행위 부여*. 데이터만 wrapping 후 외부에서 꺼내 처리 = 포장의 의미 잃음.
