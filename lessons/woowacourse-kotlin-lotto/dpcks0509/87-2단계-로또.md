## 학생 자가 의문 + 리뷰어 답변

### 1. 도메인 init 검증 vs 입력 검증 (이중일?)

학생:

> 입력을 받을때 입력값 검증을 통해 잘못된 값이 들어오면 오류를 발생하도록 구현을 해놓아도 model 안에서도 init, require를 통해서 값을 검증하는 것이 좋은 방법인 건지, 이중일을 하는 불필요한 행동인지 궁금합니다.

→ 도메인 init은 *invariant 보장*. 외부 검증과 *목적이 다름*. 둘 다 가능.

### 2. toString 남용?

> model에 대한 출력을 할때 저는 toString을 통해서 출력에 대해 컨트롤 하였는데 다른 크루들은 toString을 많이 안써서

→ 백엔드 = OutputView, 안드로이드 = toString OK. 회색지대.

### 3. object vs class 기준

> view에 대한 파일들을 object로 선언한 크루도 있고 class로 선언한 크루도 있던데

→ 상태 무 + 인스턴스 1개 = object.

### 4. 테스트 패키지 구조 main과 동일하게

> `test/kotlin` 내부의 패키지 구조를 `main/kotlin` 의 패키지 구조와 동일하게 해주세요.

## 얻은 교훈

- **도메인 init 검증 ≠ 입력 검증**. 목적이 다름 (invariant 보장 vs 입력 형식).
- **테스트 패키지 = 메인 패키지 미러링**. 찾기 쉬움.
