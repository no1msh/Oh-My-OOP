## 못한 점 (설계 관점)

### 1. 2단계 요구사항을 모두 Controller에

리뷰어 핵심 지적:

> 2단계 요구사항을 모두 컨트롤러에서 반영한 느낌이에요. 마치 자동차 경주와 1단계에서 배운 내용을 다 잊어버린 것처럼 보여요. 오늘 수업에서 배운 내용을 잘 기억해보시고 다시 구현해주시면 좋을 것 같습니다!

### 2. 수동 로또 입력에서 매수보다 많이 입력해도 통과

```
구입금액을 입력해 주세요.
1400
수동으로 구매할 로또 수를 입력해 주세요.
1
수동으로 구매할 번호를 입력해 주세요.
1,2,3,4,5,6
```

> 위 처럼 입력하면 어떻게 될까요? 예상한 동작일까요?

→ 1400원 → 1장 구매 가능. 수동 1장 정상. 하지만 *경계*가 약한 검증.

## 얻은 교훈

- **단계 추가 = 도메인 분배 재검토**. 1단계에서 배운 책임 분배를 *2단계 새 요구사항*에 다시 적용. Controller에 모이는 건 도메인을 잊은 신호.
- **경계 케이스 테스트**. 수동 로또 수 == 매수 == 1 같은 *최소 경계*. 입력 검증의 정확성.
