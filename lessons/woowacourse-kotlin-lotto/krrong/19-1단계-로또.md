## 못한 점 (설계 관점)

### 1. `LottoNumber` 도메인 누락 → `Set<Int>` 그대로 노출

```kotlin
class Lotto(val numbers: Set<Int>) { ... }
```

리뷰어 핵심 지적:

> 로또에서 사용하는 숫자는 결국 Int 타입이라고 볼 수 있겠습니다. 그렇다면 외부에서 가져온 이 숫자들이 로또 번호라는 것을 어떻게 알 수 있을까요
> ```kotlin
> val lotto = Lotto(...)
> val number = lotto.numbers.first()
> foo(number)
>
> fun foo(number: Int) {
>    // number가 로또 번호인가? 그럼 또 검증해야되나?
> }
> ```

→ `LottoNumber` 값 객체로 추출하면 타입 시스템이 검증을 보장.

### 2. `RandomGenerator` 이름의 모호함

```kotlin
interface RandomGenerator {
    fun generate(): Set<Int>
}
```

> 단순히 RandomGenerator라는 이름이 1부터 45 사이의 중복되지 않은 숫자 6개를 반환한다는 것을 알 수 있을까요?

→ `LottoNumberGenerator`처럼 *무엇을* 생성하는지 명시. 인터페이스 계약을 시그니처/이름으로 드러내기.

### 3. `LottoStatistics`의 `compareNumbers`/`compareBonusNumber`가 public — 테스트만 위해 노출

```kotlin
class LottoStatistics(val winningLotto: WinningLotto) {
    fun compareNumbers(lotto: Lotto): Int { ... }     // ⚠ 테스트만 호출
    fun compareBonusNumber(lotto: Lotto): Boolean { ... }   // ⚠ 테스트만 호출
    fun compare(lotto: Lotto): Rank = ...
}
```

> 이 함수들은 테스트 코드에서만 사용되고 있어요. 테스트 코드를 위해 구현 코드가 public으로 노출되어서는 안됩니다.

### 4. 함수 이름 모호 — `compare()`, `yield()`

```kotlin
fun compare(lotto: Lotto): Rank = ...
fun yield(): Double = ...
```

> compare(), yield()라는 함수 이름으로 하여금, 어떤 결과를 반환하는지 알 수 있을까요?

`compare`는 일반적으로 `-1/0/1` 반환을 시사. 도메인 어휘로 `match(lotto): Rank`, `profitRate(): Double`이 더 명확.

### 5. **Tell-Don't-Ask 위반 — Statistics가 외부 객체의 정보로 직접 비교**

```kotlin
class LottoStatistics(val winningLotto: WinningLotto) {
    fun compareNumbers(lotto: Lotto): Int {
        val winningNumbers = winningLotto.getWinningNumbers()  // ⚠ winningLotto의 정보를 꺼냄
        return lotto.numbers.filter { number ->                 // ⚠ lotto의 정보도 꺼냄
            winningNumbers.contains(number)
        }.size
    }
}
```

리뷰어 가이드 (Tell-Don't-Ask의 모범):

> 몇개가 일치하는지 요청해서 결과를 받아오도록 해보세요. 객체지향 프로그래밍에서는 이 개념을 메시지를 보낸다 라고 표현합니다.
> ```kotlin
> val matchedRank: Rank = winningLotto.match(lotto)
> ```

→ Statistics가 직접 계산하지 말고 WinningLotto에게 메시지 전달.

### 6. Rank 집계 자료구조 부재

```kotlin
fun compare(lotto: Lotto): Rank = Rank.valueOf(...)
// ⚠ 각 Rank에 몇 개 일치하는지를 어떻게 셀까?
```

> Rank에 해당하는 값에 총 몇개의 당첨 갯수가 있는지를 확인하는 방법으로 적절한 자료구조는 무엇일까요?

→ `Map<Rank, Int>` 또는 더 깔끔하게 `groupingBy { it }.eachCount()`.

### 7. `WinningLotto`가 1~45 범위 검증 직접 수행 (중복)

```kotlin
class WinningLotto(val lotto: Lotto, val bonusNumber: Int) {
    init {
        require(!lotto.numbers.contains(bonusNumber)) { ERROR_CONTAIN_BONUS_NUMBER_IN_LOTTO }
        require(bonusNumber in MINIMUM_LOTTO_RANGE..MAXIMUM_LOTTO_RANGE) { ERROR_BONUS_NUMBER_RANGE }
    }
}
```

`Lotto` 내부에서도 `numbers in 1..45` 검증. `LottoNumber` 값 객체가 있으면 양쪽에서 사라짐.

### 8. `let` 오용

```kotlin
fun valueOf(countOfMatch: Int, matchBonus: Boolean): Rank {
    return values().find { it.countOfMatch == countOfMatch }.let { matchResult ->
        if (matchResult == SECOND && !matchBonus) return@let ...

```

> let에 대한 올바른 사용방법이 아닙니다. when 문을 이용해서 표현 해 보도록 하세요.

## 리뷰어 의견 요지

리뷰어 @laco-dev의 메시지:

1. **`LottoNumber` 도메인 추출**이 모든 안티패턴의 출발점 — 범위 검증 중복, 일반 Int 노출, "이 Int가 로또 번호인가?" 의문 모두 해결.

2. **Tell-Don't-Ask = 메시지 전달**. Statistics가 두 객체의 정보를 꺼내서 비교 = feature-envy. `winningLotto.match(lotto): Rank` 한 메시지.

3. **함수명 = 도메인 어휘**. `compare`처럼 일반 어휘 회피, `match`, `profitRate` 등.

4. **테스트만을 위한 public 노출 금지** — racingcar에서도 반복 등장.

5. **인터페이스 이름이 *계약*을 드러내야** — `RandomGenerator`만으로는 "무엇을 생성하는지" 모름.

## 얻은 교훈

- **`LottoNumber`는 lotto 미션의 *마스터 키***. 1-45 범위, 중복 검증, 보너스 비교 모두 이 한 값 객체로 해결.
- **Tell-Don't-Ask의 lotto 적용** = `winningLotto.match(lotto): Rank`. Statistics 같은 외부 객체가 비교 로직을 갖지 말고, 도메인 소유자(WinningLotto)에게 메시지.
- **함수명 컨벤션 차이**: `compare()` = 비교(-1/0/1), `match()` = 일치 확인. 도메인 어휘를 신중히.
- **인터페이스 이름 = 계약 요약**. `RandomGenerator`보다 `LottoNumberGenerator`가 의도 명확.
- **`Map<Rank, Int>` 자료구조** = lotto 통계의 표준. 등수별 개수를 한 자료구조로.
