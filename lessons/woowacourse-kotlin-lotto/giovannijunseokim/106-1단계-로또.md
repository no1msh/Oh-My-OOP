## 못한 점 (설계 관점)

### 1. Controller가 mutable `lateinit var` 보유

```kotlin
class LottoController {
    lateinit var winningLotto: WinningLotto
    lateinit var boughtLottos: Lottos
    
    fun buyLottos() { ... }
    fun readWinningLotto() { ... }
    fun showResult() { ... }
}
```

> 외부에 열려있어 수정될 위험이 있겠어요. `private`로 막아주면 어떨까요?

→ `lateinit var` + public = 상태가 외부에서 변경 가능 + 사용 순서 강제 어려움.

### 2. Application과 Controller 분리 의미?

```kotlin
fun main() {
    val lottoApplication = LottoApplication()
    lottoApplication.run()
}

class LottoApplication {
    val controller = LottoController()
    fun run() {
        controller.buyLottos()
        controller.readWinningLotto()
        controller.showResult()
    }

```

> `Application`과 `Controller`의 역할이 나눠진 이유가 있을까요?

→ 둘 다 흐름 제어. 분리의 정당화가 약하면 하나로.

### 3. `LottoResult` 순서에 의존

```kotlin
companion object {

        return values()[matchCount]  // ⚠ enum 선언 순서에 의존

```

> 만약 `LottoResult` 상수들이 순서가 바뀐다면 이 코드는 어떻게 될까요?

### 6. `LottoNumber`를 매번 새 인스턴스로

```kotlin
val numbers = (1..45).map { LottoNumber(it) }  // ⚠ 100개 로또면 100*6 = 600개 인스턴스
```

> 만약 100개, 1000개 이상의 로또 숫자를 생성한다면 어떨까요? 인스턴스 100개, 1000개가 필요할까요?

→ 1-45 범위의 LottoNumber는 *고정된 45개*. 캐싱/팩토리 메서드로 재사용.

```kotlin
class LottoNumber private constructor(val value: Int) {
    companion object {
        private val cache = (1..45).associateWith { LottoNumber(it) }
        fun of(value: Int): LottoNumber = cache[value] ?: throw IllegalArgumentException(...)
    }
}
```

### 7. `get()` 커스텀 프로퍼티 vs 함수의 기준 모호

```kotlin
val numberOfLottos: Int get() = ...  // 또는 fun numberOfLottos(): Int
```

> `get()` 커스텀 프로퍼티를 사용하는 것과, 함수를 사용하는 것, 이 두 가지는 어떨 때 각각 사용할까요?

→ Kotlin 컨벤션: 상태 조회/단순 계산은 property, 부수효과/연산 비용 있는 건 함수.

## 리뷰어 의견 요지

리뷰어 @hyemdooly의 가르침:

1. **lateinit var + public 회피** — private 적용 + 가능하면 생성자 주입.

2. **enum의 *순서 의존* 회피** — `values()[index]`는 silent bug 위험. 명시적 매칭으로.

3. **금액 도메인의 책임** — Lottos가 금액 검증/계산까지 가지면 god-object 시작.

4. **인스턴스 재사용 압박 시뮬레이션** — 1000개로 늘면 부담? 캐싱 검토.

## 얻은 교훈

- **enum의 *순서 의존*은 silent bug**. `values()[N]`은 enum 재배치 시 다른 값을 반환 — 컴파일러 경고도 없음. 명시적 `find { ... }`로.
- **고정 범위의 값 객체는 캐싱 후보**. LottoNumber(1-45)는 시스템 전체에서 45개만 존재 = `flyweight` 패턴 후보.
- **`Lottos`(일급 컬렉션)는 컬렉션 관리만**. 금액, 등수, 통계 같은 부수 도메인은 별도 객체.
- **도달 불가 코드의 테스트 커버리지 ≠ 신뢰**. 도달 불가하면 *코드 자체를 제거*. sealed class로 컴파일러가 보장하게.
- **lateinit var = invariant 시간차 파괴**. 객체가 생성 시점부터 *완성된 상태*를 갖도록.
