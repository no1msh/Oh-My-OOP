리뷰어 (*인용 가치 매우 높음*): "*LottoMachine도 외부로부터 받아서 사용하면 어떨까요*? 지금은 하나의 로또 머신이 방법을 주입받아서 사용하고 있는데, *자동 로또 머신과 수동 로또 머신으로 나눠볼 수도 있을 것 같*아요. 즉, *LottoMachine을 만들 때 generator를 주입받는 방법도 있을 것 같*아요!

그럼, *사용자한테 입력받는 경우에는 어떻게 처리하나요? 라는 질문*이 있을 것 같은데요.

## 얻은 교훈

- **Controller *직접 생성 X*** — DI (생성자/세터/인터페이스). *생성 책임 외부*.
- **테스트 *fake = 테스트 코드*에** — *프로덕션 오염* 회피. PR #21 동일.
- **테스트 어려움 = *책임 분리 신호*** — *RandomGenerator 의존*이 *LottoShop 테스트*를 막으면 *책임 위치 의심*.
- **테스트 *expect 하드코딩 = 문서*** — *동어 반복 회피* + *명세 가시성*. PR #147 동일.
- **변수명 *대조*** — `winLotto` vs `boughtLottos`. *대구 (對句)*가 가독성.
- **논리적 오류 vs null 반환** — *논리 오류 = 예외*, *형식 오류 = null*. *PR #148 (etama123) 4단계 정리*와 같은 결.
- **`Shop` *살 때 받기*** — *손님 정보를 처음부터 보유*보다 *주문 시 받기*가 자연 흐름.
- **에러 메시지 *sealed class*** — *InputView*에서 *상태별 매핑*.
- **`fun interface` *SAM 학습*** — *함수 하나만*인 interface는 *fun interface*로.
- **`LottoGenerator { view.readManualLotto() }` *람다 위임*** — *함수형 인터페이스*가 *View 책임*을 *Domain에 위임*. *추상화 vs 의존 방향* 토론 거리.
- **리뷰어의 *학생 의견 인정*** — *지오의 의견 읽고 이해됨*. *권위로 가르치지 않고 대화*.
