## 못한 점 + 핵심 지적

### 1. Controller가 runCatching으로 검증

> runCatching을 사용한 이유가 궁금합니다 해당 내용을 보면 inputView에 대한 Validation 실패인데 과연 해당 내용을 체크해주는게 Controller에서 담당해야할 기능인지에 대해서도 고민해볼 필요가 있을 것 같습니다!

### 2. `operator` 함수 사용

```kotlin
class Lotto {
    operator fun contains(number: LottoNumber): Boolean = ...
}
```

> operator 함수의 활용 좋습니다~ 고민해볼 내용이 operator 함수로 작성하신 이유가 궁금합니다

→ `number in lotto` 표현 가능. 의도가 명확해야 일관성.

### 3. `let { }` 가독성 — apply 대안

```kotlin
return getRankMap().let { ... }
```

> let 을 사용하는 것도 좋기는 하지만 좀더 의미를 명확하게 아래처럼 하는 방법도 있을 것 같아서 참고 부탁드립니다~
> 1. getRankMap().apply { ... }

→ `let` (변환), `apply` (this 설정), `run` (스코프 + 반환), `also` (부수효과) 의도 명확히.

## 얻은 교훈

- **`operator fun`은 도메인 어휘로 자연스러울 때만**. `in`, `+`, `*` 같은 표준 의미 일치할 때.
- **scope function 차이** — let/apply/run/also/with 각각 의도.
- **Controller의 검증 vs InputView/도메인** — racingcar/lotto 반복 패턴.
