## 못한 점 (설계 관점)

### 1. Controller가 *runCatching*으로 검증

```kotlin
fun run() {
    val purchaseMoney = runCatching {. }.getOrElse {. }
}
```

리뷰어: "*runCatching을 사용한 이유가 궁금*합니다🤔 *해당 내용을 보면 inputView에 대한 Validation 실패인데 과연 해당 내용을 체크해 주는 게 Controller에서 담당해야 할 기능인지에 대해서도 고민*해 볼 필요가 있을 것 같습니다!" — *Controller가 검증 책임*인가 *InputView/도메인*인가. PR #36 (galcyurio)과 같은 *Elizarov 글* 시리즈.

### 2. `operator fun contains` *의도 메타-질문*

```kotlin
class Lotto {
    operator fun contains(number: LottoNumber): Boolean =.
}
```

리뷰어: "operator 함수의 활용 좋습니다~ 고민해 볼 내용이 *operator 함수로 작성하신 이유가 궁금*합니다🤔" — *Kotlin idiom* `number in lotto` 표현을 *도메인 어휘 일치*로 정당화해야.

### 3. `let { }` 가독성 — *apply/forEach* 대안

```kotlin
return getRankMap().let {. }
```

리뷰어: "*let을 사용하는 것도 좋기는 하지만 좀 더 의미를 명확하게* 아래처럼 하는 방법도 있을 것 같아서 참고 부탁드립니다~ 1. *getRankMap().apply {. }* 2. *getRankMap().ranks.forEach {. }*" — *scope function*의 의도 (변환/this 설정/부수효과)를 *어휘 일치*로.

### 4. `fun interface LottoGenerator` *키워드 이유*

```kotlin
fun interface LottoGenerator {
    fun generate(): List<LottoNumber>
}
```

리뷰어: "*LottoGenerator interface 앞에 fun 키워드가 붙은 이유가 궁금*합니다🤔" — *SAM (Single Abstract Method)*로 *람다 변환 가능*. 의도 명시.

### 5. `value class` vs `data class` — 메타-질문 반복

리뷰어: "*value class를 사용해 주셨군요*👍 수정이 필요한 것은 아니고 같이 고민해 보면 좋을 것 같아서 코멘트 남겨 두었습니다~ *value class와 data class는 어떤 차이점이 존재*할까요?? 해당 내용을 *value class로 작성하신 이유*가 궁금합니다!"

## 얻은 교훈

- **Controller *검증 책임*은 *얇아야*** — *InputView*는 *형식*, *도메인*은 *논리*. *Controller의 runCatching*은 *어느 단계 검증인지* 모호.
- **`operator fun contains`는 *도메인 어휘 일치*가 정당화** — *Kotlin idiom*만 보고 도입하면 *어휘 충돌*.
- **`let` 보다 *의도 명확*** — `apply` (this 설정), `forEach`, `also` (부수효과). *Kotlin scope function*은 *부수 의도 차이*가 핵심.
- **`fun interface` = *SAM 명시*** — *람다로 즉시 사용* 가능. *명시적 단일 메서드*.
- **`value class`는 *최적화 + 타입 안전*** — `data class`는 *힙 + copy/equals 자동*. *작은 래퍼*에 부적합.
- **`1..45` *상수 확장성*** — *변경 가능성*이 *낮아도 단일 변경 지점* 가치.
- **`InputView` *class vs object*** — *변경 가능성*이 *class* 선택 기준.
- **테스트 *랜덤 시나리오*** — *주어진 값*과 *랜덤 시나리오* 모두. *Random 외부 주입*이 *재현 가능 랜덤*.
- **매직 넘버 *모두 상수화*** — *-1, 10, 1*도 *의미*가 있으면 상수.
- **EOF / 디버깅 코드 = *PR 셀프 리뷰 항목***.
- **`DEFAULT_LOTTO` test fixture** — *공통 데이터 재사용*. PR #21 *MethodSource 지역성*과 함께 *테스트 가독성*의 균형.
- ***도메인 의존 정당화 = invariant*** — `BonusLottoNumber`가 `winningNumbers` 의존하는 건 *중복 방지 invariant* 표명. 결합도라기보다 *모델링*.
- **방어적 코딩 = *알 수 있는 + 알 수 없는 예외*** — *방어 범위 자각*이 *과방어 회피*.
