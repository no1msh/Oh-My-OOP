### 5. *재실행 패턴* — 사용하지 않는 반환값

## 얻은 교훈

- **`try-catch 미사용` 요구사항 = *catch의 다른 형태가 아닌 본질***. *runCatching*도 *예외 사용*. 정상 흐름은 *null + while* 또는 *Result*.
- **`View`가 도메인 타입 반환 OK** — *Presentation → Domain 의존*은 허용 (PR #21 galcyurio도 같은 의견).
- **`sealed class` + *단일 인터페이스*가 *2개 인터페이스 + when 분기*보다 자연** — PR #144 jiyuneel과 동일 패턴.
- **`nullable` 반환 → *Result/Success/Failure 상태***. nullable은 *원인 정보 손실*.
- **재시도 ≠ 사용자 피드백** — `runCatching { ... }.getOrElse { recurse() }`는 *오류 메시지 출력*과 *재시도*를 분리.
- **팩토리 함수 = *생성자보다 의도가 명확*할 때만** — `BonusLottoNumber.of(n)`와 `BonusLottoNumber(n)`이 같은 효과면 *팩토리 무용*. 분기 (`Range A → typeA, Range B → typeB`)나 *서로 다른 입력 변환*일 때 가치.
- **`tailrec` *꼬리 재귀 최적화*** — JVM에서 *스택 오버플로 회피*.
- **`data object` = *toString/equals 자동* (Kotlin 1.9)** — *Sentinel 객체* (NONE, EMPTY 등)에 유용.
- **`inline` 함수 *고차 함수 호출 비용 회피*** — 람다 객체 생성 → 인라인.
- **재시도 *종료 조건*** — 입력이 없으면 *무한 재귀*. *try N times* 또는 *EOF 처리*.
- **테스트 *fixture*** — `@BeforeEach`로 *공통 setup*. 또는 *factory function*.
- **자동/수동 generator 통합 = *Open-Closed*** — *제 3 종류 추가*에도 인터페이스 무변경.
- **Elizarov 글 = *Kotlin 예외 처리 정전*** — PR #36 (galcyurio)과 같은 인용. *우테코 리뷰어 공통 지식*.
