## 못한 점 + 핵심 지적

### 1. Lotto가 값 + 검증만 (행위 없음)

```kotlin
class Lotto(val numbers: List<LottoNumber>) {
    init { require(numbers.size == 6) }
}
```

> 로또 객체가 값을 가지고, 검증하는 것 이외에 별다른 역할을 맡고 있지 않고있네요. 이 객체가 할 수 있는 일들을 다른 곳으로부터 가져와 모아두는 건 어떨까요?

→ Lotto가 *외부에 의해* 비교/매칭되는 *수동적 객체*. `lotto.match(winningLotto)` 같은 행위 부여.

### 3. 에러 메시지에 입력값 미포함

```kotlin
require(value > 0) { "잘못된 금액입니다" }
```

> 어떤 값이 들어와서 Exception이 발생했는지 메시지를 담아주는 건 어떨까요?

### 4. Rank 매칭 — 모든 값 순회

```kotlin
fun findRank(count: Int, bonus: Boolean): Rank {
    return values().first { it.count == count && it.bonus == bonus }
}
```

> 모든 값을 순회할 필요가 있을까요? 특정 경우에만 조건문을 처리하고, 나머지를 처리하게 구성해보는 건 어떨까요?

→ when으로 *특수 케이스* (5개 + 보너스 = SECOND) 분기.

## 얻은 교훈

- **값 객체에 행위 부여 필수** — 값만 있으면 *수동적 객체*.
- **flyweight 패턴** = 고정 범위 값 객체 재활용.
- **에러 메시지에 *입력값*** 포함 → 운영 디버깅 비용 ↓.
- **when 분기 vs 전체 순회** — 특수 케이스가 적으면 when이 명시적.
