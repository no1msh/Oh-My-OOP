## 못한 점 (설계 관점)

### 1. `1`, `45` *하드코딩* — 상수 미참조

```kotlin
data class LottoNumber(val number: Int) {
    init {
        require(number in MINIMUM_NUMBER..MAXIMUM_NUMBER) { ERROR_NUMBER_IN_RANGE.format(number) }
    }

    companion object {
        private const val MINIMUM_NUMBER = 1
        private const val MAXIMUM_NUMBER = 45
        private const val ERROR_NUMBER_IN_RANGE = "로또 숫자는 1부터 45사이어야합니다. \n 잘못된 값: %d"  // ⚠ 1, 45 다시 등장
    }
}
```

리뷰어: "위의 상수에 따라 *정책이 변경될 수도 있으니 1, 45를 하드코딩하는 대신 상수를 참조*해 주세요." — *단일 변경 지점* 원칙. 후속: `"로또 숫자는 ${MINIMUM_NUMBER}부터 ${MAXIMUM_NUMBER}사이어야합니다."`.

### 5. `data class` + `private constructor` 충돌 → value class

```kotlin
class LottoNumber private constructor(val number: Int) {
    override fun equals(other: Any?) =.
    override fun hashCode() =.
}
```

리뷰어: "data class로 선언하면 *생성자를 private으로 선언해도 copy() 함수를 통해 생성이 가능*해서 class로 변경하신 것 같네요. 이럴 때는 *value class를 활용*하시면 좋습니다. 아래와 같은 장점이 있습니다.
> - data class의 equals(), hashCode(), toString()도 똑같이 구현된다.
> - copy() 함수를 사용할 수 없어서 *value class의 생성자를 private으로 선언할 수 있다*.
> - 컴파일러에서 *최적화를 할 수 있어서 성능상 이득*이다."

→ *생성자 통제 + equals 자동*은 *value class*가 최적.

### 8. Tell, Don't Ask — `numbers.contains` → `lotto.contains`

```kotlin
data class Lotto(.) : List<LottoNumber> by numbers {
    private fun List<LottoNumber>.isNotDuplicated(): Boolean = this.distinct().size == this.size
    fun contains(lottoNumber: LottoNumber): Boolean = numbers.contains(lottoNumber)
    fun count(predicate: (LottoNumber) -> Boolean): Int = numbers.count { predicate(it) }
}
```

리뷰어: "*바깥에 정보를 넘겨주는 대신에 Lotto에서 메시지를 받아 처리*하도록 만들어 보세요." + "*contains() 함수로 operator overloading이 가능*합니다. 이렇게 하면 외부에서 *lottoNumber in lotto*와 같이 작성할 수 있습니다."
```kotlin
operator fun contains(lottoNumber: LottoNumber): Boolean = numbers.contains(lottoNumber)
```
→ *Kotlin idiom* 사용해 *도메인 어휘*를 *언어 어휘*에 매핑.

## 얻은 교훈

- **상수 *모든 등장 자리* 참조** — 에러 메시지 안에서도 `${MINIMUM_NUMBER}부터 ${MAXIMUM_NUMBER}`. *단일 변경 지점*.
- **인터페이스 이름 + 메서드 명 중복 회피** — `NumberGenerator.generateNumbers()`는 *컨텍스트 어휘 반복*. `.generate()`로 충분.
- **일급 컬렉션 ≠ `List` 인터페이스 위임** — `: List<T> by numbers`로 위임하면 *모든 컬렉션 메서드*가 외부 노출. *도메인 메서드만 선택적 노출*이 의도.
- **List 자체 노출 시 *방어적 복사*** — `numbers.toList()`. *원본 컬렉션 누출*을 막음.
- **`data class` + `private constructor` 충돌 → *value class*** — `copy()` 노출 막으면서 equals/hashCode 자동.
- **`LottoStore.sell()`** — 메서드 이름은 *클라이언트가 보낼 메시지*. `buyLotto`는 *판매자에게 사라*가 되어 어색.
- **`!!` 사용 회피** — null 처리 또는 NonNull 타입. `result[x]!!`는 *Map 초기화 가정*에 의존.
- **`operator fun contains` 활용** — *Kotlin idiom*으로 도메인 어휘가 *언어 표현*에 자연스럽게 매핑. `if (lottoNumber in lotto)`.
- **테스트 클래스 이름 오타** — `gLottoResultTest` 같은 *손가락 미끄러짐*은 *PR 셀프 리뷰*가 잡아야.
- **`Flyweight` 패턴 학생 자발적 도입** — `valueOf(number)`로 1-45 *캐싱 객체*. *value class*와는 충돌 (가벼움 자체가 그 역할).
