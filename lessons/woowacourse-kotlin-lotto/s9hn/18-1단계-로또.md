### 4. Rank 2등/3등 같은 countOfMatch (5개)

```kotlin
enum class Rank(val countOfMatch: Int, val money: Int) {
    SECOND(5, 30_000_000),
    THIRD(5, 1_500_000),  // ⚠ 같은 countOfMatch
}
```

> 2등과 3등의 countOfMatch가 일치하네요, Rank에서 2등과 3등을 어떻게 분리를 할수 있을까요? Bonus볼의 여부도 Rank의 책임이 아닐까요?

→ Rank가 matchBonus를 *판별 데이터*로 가지면 명확.

### 5. `BonusNumber`에 getter/setter

```kotlin
class BonusNumber {
    private var number: Int = 0
    fun getNumber(): Int = number
    fun setNumber(v: Int) { number = v }
}
```

> 코틀린에서는 getter, setter 함수를 잘 쓰지 않습니다! 공식 문서를 가볍게 읽어보시면 좋을거 같아요!

→ Kotlin property가 자동 생성. 자바식 메서드 작성 = 코틀린 idiom 위반.

### 6. `LottoAdministrator` feature-envy

```kotlin
class LottoAdministrator(.) {
    fun matchCount(lottoNumber: Lotto, winningNumber: Lotto): Int {
        return lottoNumber.numbers.filter { it in winningNumber.numbers }.size
    }
}
```

> lottoNumber와 winningNumber 객체의 numbers를 가져와서 확인하는 함수네요, 객체의 데이터를 쓰기보다, 메세지를 전달하여 책임을 위임해보면 어떨까요?

→ `winningLotto.match(lotto): Rank`.

## 얻은 교훈

- **값 객체 만든 후 *그 타입으로 다루기***. Count 만들고 Int 반환 = wrapping 의미 없음.
- **Kotlin property = 자동 getter/setter**. `var number: Int`만 쓰면 자바의 `getNumber/setNumber` 자동 생성. 직접 작성 ≠ Kotlin idiom.
- **5개 일치 두 케이스 = Rank가 matchBonus 데이터 보유**. enum의 판별 데이터.
- **`LottoAdministrator` 같은 외부 비교자 = feature-envy 신호**. `winningLotto.match(lotto)` 메시지로.
