### 2. *정상 Flow에 `runCatching`* — try-catch 남용

```kotlin
override fun getMoney(): PurchaseLottoMoney {
    while (true) {
        println(INPUT_MESSAGE_FOR_PURCHASE_MONEY)
        val money = validateMoney(readln().toIntOrNull()) ?: continue
        runCatching { PurchaseLottoMoney(money) }
            .onSuccess { ... return it }
            .onFailure { println(it.message) }
    }
}
```

리뷰어: "전체적으로 *runCatching()을 사용*해 주셨는데 *프로그램의 정상 Flow에 해당되는 경우들은 모두 제거*해 주세요." + "프로그램의 *정상적인 Flow에서 예외를 던지고 try-catch를 통해 처리하는 방법은 지양*해야 합니다. *논리 오류일 때 예외를 던지라는 것은 런타임에 예외도 발생하지 않아서 로그로도 안 남는 최악의 상황을 그나마 예외라도 던지게 만들어서 로그에 수집되게 만들라는 의미*입니다."

학생 질문 (좋은 메타-질문): "생성자 호출 부분에서 *runCatching을 모두 사용*해 주었는데 *이렇게 하면 안 되는 걸까요*? 아니면 *runCatching 로직을 함수 매개변수를 가진 메소드로 분리해서 생성자를 호출할 때 재활용*해서 코드의 중복을 줄이라는 말씀이신가요??" 리뷰어: "*잘못된 입력이 들어왔을 때, 재입력을 받는 것은 충분히 예상 가능한 정상적인 Flow*입니다. 그렇기 때문에 *예외를 던져서 그것을 try-catch하는 식으로 코드를 작성하는 것은 예외 처리 기능을 잘못 사용*하는 것입니다. *유효성 검사를 한 뒤에 제대로 된 응답인 경우에만 생성자를 호출*하도록 만들어 보세요." + "*논리 오류인 경우에 예외를 던지는 것들은 프로그램 전역적으로 설정된 예외 처리기를 통해 로그가 남도록* 만들면 좋습니다. 코틀린에서는 *Thread.setUncaughtExceptionHandler()를 이용*해서 catch 되지 않은 Exception들을 잡아서 추가 처리를 해 줄 수 있습니다." + [Roman Elizarov - Kotlin and Exceptions](https://medium.com/@elizarov/kotlin-and-exceptions-8062f589d07) 링크.

### 4. `if`/`when` *중괄호 생략* — 공식 컨벤션


리뷰어: "[공식 컨벤션](https://kotlinlang.org/docs/coding-conventions.html#control-flow-statements)에 따르면 *if문과 when문은 2줄 이상이면 중괄호를 사용*합니다."

## 리뷰어 의견 요지

- **`runCatching` = *정상 Flow가 아닌 경우*만**. 입력 재시도는 *명시적 null 반환 + while*.
- **논리 오류의 예외 = *로그 + UncaughtExceptionHandler***.
- **`if/when` 2줄 = *중괄호 필수***.
- **`toString()` View 침투 금지** — *대괄호 포맷*도 View.
- **컬렉션 반환 vs *객체 메시지*** — `Ticket.matchTicketCount(winningLotto)`.
- **단순 래퍼 클래스는 *행동 추가*가 정상**.
- **`deepCopy` 명시적 네이밍**.
- **`validateXxx` = Boolean 관행**.

## 얻은 교훈

- **다른 클래스가 상수 필요 → *책임 위치 재검토*** — *private 해제*는 결합도 신호. `1000원`이 *판매소* 책임인가 *금액 도메인* 책임인가.
- **`runCatching`은 *예측 불가 오류*에만** — *재입력*은 *정상 Flow*이므로 *null 반환 + while*.
- **논리 오류 = *예외 + 전역 핸들러*** — 로깅을 위한 *최후 안전망*.
- **`if/when` 2줄 이상 = 중괄호** — Kotlin 공식 컨벤션. PR #49 잭슨도 같은 지적.
- **`toString()`은 View 책임** — *대괄호 포맷*도 도메인이 알면 *다국어/A-B 테스트* 시 도메인 변경.
- **컬렉션 반환 vs *결과 객체*** — `Map<Rank, Int>` 노출보다 `LottoResult.profitRate()`가 *Tell, Don't Ask*.
- **단순 래퍼 = *행동 추가 가능 신호*** — `Ticket`이 *값만 보유*하면 `lottos.count { winning.match(it) }`이 외부에 흩어짐.
- **`deepCopy` 명시** — `copy()`는 *얕은*. *깊은*은 이름으로 드러내야.
- **`validateXxx` = Boolean** — *검증 + 생성*을 한 함수에 두는 것은 *책임 결합*. 분리가 관행.
- **학생의 *메타-질문*은 *효율적 대화*** — "두 가지 해석 중 어느 쪽이신가요?" + 이미지 첨부는 *왕복 횟수*를 줄임.
- **Roman Elizarov의 Kotlin and Exceptions** — Kotlin 진영 공식 *예외 처리 철학*. 정상 흐름 ≠ 예외.
