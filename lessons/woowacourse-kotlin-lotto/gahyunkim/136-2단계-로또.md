## 못한 점 + 핵심 지적

### 1. 두 `amount` 검증을 Validator가 직접

```kotlin
class Validator {
    fun validate(amount1: Int, amount2: Int) { ... }  // ⚠ 원시값 검증
}
```

> amount는 원시값 포장하지 않아도 될까요?

→ `PurchaseAmount`, `ManualCount` 같은 값 객체. 외부 Validator 대신 각자 init 검증.

### 2. `amount` 네이밍 — 가격 vs 장수 혼동

```kotlin
class Purchase(val amount: Int) { ... }  // amount가 장수? 금액?
```

> 로또 장수를 `amount`로 네이밍하게 되면서, 이 변수는 가격이라는 의미가 담긴 이름이 더 적절하지 않을까? 생각이 듭니다!

### 3. `LottoFactory`가 단순 통과

```kotlin
class LottoFactory(...) {
    fun create(lottos: List<Lotto>): List<Lotto> = lottos  // ⚠ 그대로 반환
}
```

> 로또들을 받아서 그대로 리턴하고 있네요

→ Factory가 *생성*도 *변환*도 안 함 = 죽은 추상.

## 얻은 교훈

- **원시 amount 두 개 = 두 도메인 값 객체로** — Validator 외부화 회피.
- **`amount` 모호** — 가격이면 `price`, 장수면 `count`. 도메인 어휘.
- **죽은 추상 회피** — Factory가 통과만 하면 제거.
