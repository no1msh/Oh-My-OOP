## 못한 점 (설계 관점)

### 1. `PurchaseAmount` 만들었지만 *Int 반환*

```kotlin
class PurchaseAmount(val value: Int) { ... }
fun calculateCount(amount: PurchaseAmount): Int = amount.value / PURCHASE_UNIT  // ⚠
```

리뷰어: "*PurchaseAmount 클래스를 만들어 주셨는데, Int 타입을 리턴해 주게 된다면 해당 클래스를 사용하는 의미가 반감*될 것 같아요." — *값 객체 만들었으면 그 객체로 다루기*.

### 2. *PURCHASE_UNIT을 Controller가 앎*

```kotlin
val count = amount.value / PURCHASE_UNIT  // ⚠
```

리뷰어: "*PURCHASE_UNIT는 PurchaseAmount 내부에서 알고 있으니, PurchaseAmount에서 직접 이 값을 리턴*해 주는 것은 어떨까요? *controller에서 모델에 대한 세부 사항에 되도록 의존하지 않도록* 구현해 보면 좋을 것 같아요 :)" + "*PURCHASE_UNIT이라는 상수 중복도 제거*할 수 있게 되구요." — Tell, Don't Ask.

### 3. *값 재사용 없으면 바로 return*

리뷰어: "*값을 재사용하지 않는다면 바로 리턴해도 좋겠*네요!" — 불필요한 중간 변수.

### 4. `generateLotto` *LottoStore 반환* — 시그니처 모순

```kotlin
fun generateLotto(): LottoStore = ...  // ⚠
```

리뷰어: "*generateLotto 함수인데 리턴은 LottoStore인 게 조금 어색*한 것 같아요." — *함수명-반환 타입* 일치.

### 5. *split이 도메인에* — View 책임

```kotlin
fun parse(input: String): List<Int> = input.split(SPLIT_DELIMITER).map { it.toInt() }  // ⚠
```

리뷰어: "*SPLIT_DELIMITER는 view 레벨에서 알 수 있는 값이므로, split 과정은 view에서 수행하는 것이 적절*하지 않을까요?" — PR #60 (말리빈) 동일.

### 6. *중복 방지 자료구조 (Set)*

```kotlin
class Lotto(val numbers: List<Int>) {
    init { require(numbers.distinct().size == 6) }  // ⚠ List + 검증
}
```

리뷰어: "검증을 꼼꼼하게 잘 해 주셨네요 👍 그런데, *로또 번호의 경우 특성상 값이 겹치면 안 되기 때문에 아예 중복을 막을 수 있는 자료구조를 사용*해 보는 것도 좋을 것 같아요. *내부에서는 검증이 완료되었지만, 외부에서는 자료구조만 봤을 때 중복이 됐는지 되지 않았는지 알 수 없으니 또다시 중복 처리를 이어나갈 가능성도 있구요*!" — *invariant를 타입으로 표현*. PR #77, #60 동일.

### 7. *외부에서 컬렉션 수정 가능* — 일급 컬렉션 의미 반감

리뷰어: "*외부에서 컬렉션 수정이 가능한 타입*이네요. *이럴 경우 일급 컬렉션은 단순한 wrapping class 밖에 안 되기 때문에 활용하는 이유가 반감*될 것 같아요." — *MutableList* 노출 X.

## 얻은 교훈

- **값 객체 *유지*** — `PurchaseAmount.numberOfLottos(): LottoCount`. *Int 반환*은 *값 객체 의미 반감*.
- **Controller *모델 세부 의존 X*** — `PURCHASE_UNIT` 같은 *도메인 상수*는 *도메인 객체 내부*에. PR #21, #25 동일.
- **함수명 = *반환 타입 일치*** — `generateLotto(): LottoStore`는 *의도 불일치*.
- **`split`은 *View 책임*** — *delimiter*는 *입력 형식*에 속함. PR #60 동일.
- **중복 방지 *자료구조*** = *Set*. *invariant를 타입으로*. PR #60, #77 동일.
- **`MutableList` 외부 노출 X** — *일급 컬렉션 의미*는 *불변 + 행위 부여*. *Mutable 노출*은 *wrapper 수준*.
- **Controller 상태 = *Lottos와 책임 중복*** — *상태 + 행위*가 *한 객체*에 응집해야.
- **Tell, Don't Ask** — `lottos.calculate()`, `lottos.match()`.
- **함수 위치 = *책임 일치*** — *Lotto 개수*는 *Lottos*. *Lotto 자체*는 *6개 번호*.
- **자료구조 invariant** = 검증 코드 단순. `Set.distinctBy` 불필요.
- **0 예외** — *경계값 처리*.
- **`object` 기준 *자가 정리*** — *상태 없음 + 단일 인스턴스 + 변경 가능성 낮음*. PR #80, #87 동일 패턴.
