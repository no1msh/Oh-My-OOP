### 1. PurchaseAmount가 너무 많은 관심사

```kotlin
class PurchaseAmount(...) {
    fun numberOfLottos(): Int = ...
    fun manualLottos(): Int = ...
    fun autoLottos(): Int = ...
}
```

> PurchaseAmount가 불필요한 관심사를 많이 가지게 된 것 같습니다. 구매 금액 입장에서 로또 갯수나 수동 로또 등의 정보는 알 필요가 없지 않을까요? 자동과 수동은 하나의 상위 개념으로 구조화가 되어...

### 2. `Quantity` 별도 객체 권장

> 항상 양수만 가지는 개념의 Quantity를 별도의 객체로 만들어 보세요

### 3. 자동/수동 의미 숨김

> 자동, 수동 의미가 여기저기 숨겨져있어서 이 함수가 무슨 Quantity를 반환하는지 파악이 어렵게 느껴집니다.

## 얻은 교훈

- **PurchaseAmount의 책임 = 금액**. 수량 계산은 *Quantity* 도메인.
- **`Quantity`/`Count` 값 객체** — 양수만 보장하는 타입.
- **자동/수동을 *상위 개념*으로** — Strategy 인터페이스.
