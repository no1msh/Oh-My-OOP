### 2. 정상 케이스 테스트 누락

```kotlin
@Test fun `범위 밖이면 예외`() { ... }  // 예외만 테스트
```

> 범위 밖에 있는 경우에 대한 검증을 했다면 범위 내에 에러가 발생하지 않는 검증은 불필요한 검증으로 보입니다. 오히려 create()가 정상적으로 동작했는지에 대한 검증이 필요할 것 같아요. create()의 결과가 무엇이고 제대로 그 결과가 나왔는지 확인해볼까요?

### 3. Money 테스트 — 정상 동작 미검증

```kotlin
@Test fun `1000원 단위가 아니면 에러`() { ... }
```

> Money 클래스가 어떤 값을 넣어도 에러만 발생하고 있다면 제대로 동작하는 것일까요?

→ *Happy path* 우선, *예외*는 부차.

### 4. Rank 테스트 2등만

### 5. `check` 함수명 → Kotlin API와 충돌

```kotlin
fun check(...) { ... }
```

> check는 코틀린 api로 존재하기 때문에 함수명에 사용하면 오해의 여지가 있을 수도 있을 것 같아요.

→ stdlib과 *동명* 회피.

### 6. RandomLottoGenerator가 다른 클래스 상수 참조

```kotlin
class RandomLottoGenerator {
    fun generate(): Lotto {
        (LottoNumber.MIN..LottoNumber.MAX).shuffled()  // ⚠ LottoNumber 상수 의존
    }
}
```

> 다른 클래스의 상수를 참조해서 사용하면 의존성이 생깁니다. 의존성 주입(메서드 주입)을 받으면 어떨까요?

## 얻은 교훈

- **Happy path 테스트 우선** — 예외만 검증 = 객체가 *제대로 동작하는지* 확신 못함.
- **stdlib 동명 회피** — `check`, `apply`, `let` 같은 Kotlin 함수와 같은 이름.
- **다른 클래스의 상수 참조 = 결합도 ↑**. 의존성 주입 또는 자기 상수 보유.
- **Rank 케이스 전부 테스트** — 각 등수 = 비즈니스 분기.
