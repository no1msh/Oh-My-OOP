### 2. `getTotalLottoTicket`이 *조회 + 출력*

```kotlin
private fun getTotalLottoTicket(manualLottoTickets, autoLottoTickets): LottoTickets {
    OutputView.printLottoQuantity(.)
    val totalLottoTickets = manualLottoTickets.concat(autoLottoTickets)
    OutputView.printLottoNumbers(totalLottoTickets.tickets)
    return totalLottoTickets
}
```

리뷰어: "TotalLottoTicket을 가져온다는 행위가, *출력을 같이 하고 있다면* 두 가지 역할을 하고 있다고 볼 수 있지 않을까요? 가령 정말로 로또 티켓을 가져오려고 호출했는데, *그때마다 콘솔에 찍히게 됩니다*." — `get*` 메서드는 *순수 반환*만.

## 리뷰어 의견 요지

- **`get*` = *반환만***, 출력 등 사이드이펙트 X.
- **상수 중복 = 변경 함정** — *한 곳* 소유 + import.
- **수익률은 *결과 객체*의 책임** — 다른 값 확장 시 *통일성*.
- **외부 노출 Map = *의미 모호*** — `getCount*` 같이 *의미 부여 메서드*.
- **`coerceIn`/`coerceAtMost` 표준** — 범위 클램프.
- **테스트 함수명 = 의도, 구현 메서드명 X**.
- **수동 vs 자동 = *추상화 수준 통일*** 또는 *현실 비유 따라가기* — 정답 없음, 트레이드오프.

## 얻은 교훈

- **`get*` 시그니처 = *순수 반환***. 출력/저장 같은 사이드이펙트는 별도 메서드.
- **상수의 *한 곳* 소유** — 중복 선언은 *한쪽만 바뀌어도 안 깨짐*이라는 *위험한 invariant*.
- **결과 객체에 *통일된 책임***  — 수익률을 Money에 두면 *다른 결과*가 생길 때 *어디로 가는가* 매번 결정.
- **`Map<X, Y>` 외부 노출 회피** — 호출자에게 *Y의 의미*가 모호. `getCountByRank` 같이 *의미 부여 메서드*.
- **Kotlin 표준 *범위 클램프***  — `coerceIn(0, max)`, `coerceAtMost(max)`. 직접 `if-else`보다 의도 명시.
- **테스트 함수명 = *의도 명세***, 구현 메서드명을 함수명에 두면 *리네임이 테스트 깨짐*.
- **수동 generator의 *추상화 가치*는 *옵션***. 정답이 아니라 *확장 옵션*. 현재 비용이 가치를 넘으면 *직접 변환*도 OK.
- **README도 *코드*** — 템플릿 변수 잔존 등은 *리뷰 책임*.
