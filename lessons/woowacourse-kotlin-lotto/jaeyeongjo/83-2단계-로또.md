### 1. 캡슐화 기능 사라짐

```kotlin
class LottoResult { ... }  // 일부 메서드가 다시 외부로 노출됨
```

> 이 기능은 캡슐화를 위한 역할을 잘 수행하고 있는데, 왜 다시 사라졌을까요?

→ 리팩토링 중 캡슐화 약화 발생. *변경 의도*가 명확해야.

### 2. 수동 + 자동 패턴 불일치

```kotlin
val autoLottos = AutoLottoMachine.create(budget, generator)
val manualLottos = ManualLottoMachine(numbers).get()  // ⚠ 다른 사용 패턴
```

> 수동 로또와 자동 로또의 발급 패턴이 유사한 것 같은데, 사용하는 방법이 다르게 사용되고 있네요. 번호들을 발급한다는 협력에 집중해서 본다면 단순하게 만들어 볼 수 있지 않을까요?
> ```kotlin
> AutoLotoMachine.createLottos(budget, RandomLottoNumbersGenerator())
> ```

### 3. 지갑 차감 — 발급 실패 시 일관성?

```kotlin
class LottoBudget(...) {
    fun deduct(amount: Int) { ... }  // ⚠ 차감 후 발급 실패하면?
}
```

> LottoBudget을 만들어주셔서 지갑처럼 사용되는 설계 방법 좋았습니다. 다만 지갑을 먼저 차감하기 때문에 실제 로또를 발급하는 과정에서 문제가 생긴다면 어떻게 될까요? 상태를 만들어서 관리를 하는 방법도 좋지만, 단순히 생성할 갯수만 입력받는 방법이라면 위 문제는 사라집니다.

→ 트랜잭션 무결성 의식. 또는 *수량 계산만* 받고 *지갑 보유*는 외부.

## 얻은 교훈

- **리팩토링 중 캡슐화 약화** = 변경 의도 검토 필요.
- **수동/자동 패턴 통일** — 같은 *발급 협력*이면 같은 시그니처.
- **상태 보유의 트랜잭션 부담** — 차감 후 실패 시 롤백 어려움. *수량만 받는* 무상태 함수가 더 안전.
