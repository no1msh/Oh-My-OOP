## 못한 점 + 핵심 지적

### 1. View → Domain 의존 의문

학생:

> 이럼에도 불구하고 View가 domain을 직접 의존해도 된다는 근거가 (정말! 순수한 궁금증!) 조심스래 궁금합니다

리뷰어:

> 단순하게 도메인을 출력하는 것이 UI의 역할이기 때문이에요. 도메인 없이 그냥 출력만 한다면 뭘 출력할건데? 라는 생각을 할 수 있겠죠.

→ Domain 모름 → 출력할 게 없음. View → Domain 의존은 *자연*.

### 2. `PurchasePrice`에 LOTTO_PRICE 1000원 박힘

```kotlin
class PurchasePrice(val amount: Int) {
    fun ticketCount(): Int = amount / 1000  // ⚠ 1000원이 여기?
}
```

> 로또 한장의 가격이 1,000원이라는 것을 이 곳에서 결정하는게 적절할까? 라는 생각이 드네요. A 상점에서는 1,000원 B 상점에서는 2,000원에 팔아야 한다면.? 그렇다면 로또 한장의 가격은 누구의 책임이라고 봐야 할지 애매하군요!

→ Lotto 자체 또는 *상점*의 책임이 더 자연. 구매 가격은 *그 자체*만.

### 3. `assertThrows { }` 미사용

```kotlin
try { PurchasePrice(-1) } catch (e:.) {. }
```

→ `assertThrows<IllegalArgumentException> { PurchasePrice(-1) }`.

## 얻은 교훈

- **View → Domain 의존은 OK** — Domain 없이 출력할 게 없음. *Domain → View*만 금지.
- **로또 한장 가격의 책임자 의문** — 누가 가격 정책 소유? 미션에선 단일이지만 미래 가변성.
- **`assertThrows<T> { }`** = 코틀린 idiom.
