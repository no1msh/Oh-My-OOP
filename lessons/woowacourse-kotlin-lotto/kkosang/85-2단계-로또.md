### 1. `Buyer`가 mutable `var lottos: Lottos` 보유

```kotlin
class Buyer(private val purchaseAmount: Int) {
    val numberOfLotto: Int = calculateNumberOfLotto()
    var purchasedLotto: Lottos = Lottos(emptyList())  // ⚠ 초기엔 비어있다가 나중에 채워짐
```

### 3. `INVALID_INPUT = -1`로 magic sentinel 값 사용

```kotlin
private const val INVALID_INPUT = -1

fun validatePurchaseAmount(input: String): Int {
    val purchaseAmount = input.toIntOrNull() ?: INVALID_INPUT  // ⚠ -1을 정상 흐름에 흘림
    validatePurchaseAmountRange(purchaseAmount)
    return purchaseAmount
}
```

`null`이 의미하는 "변환 실패"를 `-1`이라는 정상 정수 자리에 끼워 넣음. 호출자가 검증을 안 하면 `-1`이 그대로 도메인에 들어감.

### 4. View 안에서 try-catch + 재귀로 재입력

```kotlin
fun inputPurchaseSizeOfManualLotto(purchaseAmount: Int): Int {
    val numberOfManualLotto = br.readLine()
    return try {
        InputValidator.validatePurchaseSizeOfManualLotto(numberOfManualLotto, purchaseAmount)
    } catch (exception: IllegalArgumentException) {
        println(exception.message)
        inputPurchaseSizeOfManualLotto(purchaseAmount)  // ⚠ View가 재시도 흐름까지 보유
    }
}
```

InputView가 재시도 정책을 결정 — 입력 받기 책임 초과.

### 6. `Lotto.toString()`에 표현 형식

```kotlin

```

## 얻은 교훈

- **mutable lateinit 패턴 = invariant의 시간차 파괴**. 객체가 생성 시점부터 *완성된 상태*를 갖도록 설계. "나중에 채워진다"는 곧 "잠시 동안은 깨진 상태"라는 뜻.
- **sentinel 값 (`-1`, `""`)은 타입 시스템의 함정**. `null` 또는 sealed class로 *실패를 타입으로* 표현해야 호출자가 강제로 처리.
- **재시도 흐름의 자리 = Coordinator(Controller)**. View는 입력 받기만, 검증 실패 시 재시도 결정은 Controller가.
- **표현 형식은 OutputView로**. `Lotto.toString()`이 표현을 결정하면 출력 변경이 도메인 변경. lotto 미션 특히 출력 포맷 변경 잦음.
- **`Pair`는 일회용**. `WinningStatistic`처럼 영구적으로 들고 다니는 자료는 data class 또는 명시적 객체로.
- **`Constant.kt`는 god-folder**. 어떤 상수든 다 들어가 응집도 0. 의미별 분리 (`LottoConstants`, `MoneyConstants`).
