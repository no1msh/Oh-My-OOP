## 못한 점 (설계 관점)

### 1. `WinningLotto`가 *검증만* — 행위 부재

```kotlin
class WinningLotto(val winningNumbers: Lotto, val bonusNumber: LottoNumber) {
    init { require(!winningNumbers.getMatchBonus(bonusNumber)) }
}
```

학생: "WinningLotto를 생성하여서 winningNumbers와 bonusNumber를 저장. 하지만 객체를 만들고 나니 이 객체는 *검증만* 하는 역할만 존재하고 다른 역할은 존재하지 않음." 리뷰어: "Controller 입장에서 winningLotto에 대한 정보, profitAmount, profitRate에 대한 관심이 필요할까요? Controller는 단지 *명령만* 내릴 뿐입니다. WinningLotto가 스스로 판단하여 *당첨번호 갯수, 당첨금, 수익률* 같은 정보들을 갖고 있다면 return되는 WinningLotto만을 가지고 활용할 수 있겠네요." — *Tell, Don't Ask* 강조.

### 2. `LottoStore.generateManualLottos(List<List<String>>)` — 이중 컬렉션

```kotlin
fun generateManualLottos(manualLottoNumbers: List<List<String>>) {
    manualLottoNumbers.forEach { lottoNumbers ->
        val lotto = Lotto.lottoNumbersOf(lottoNumbers)
        lottos.add(lotto)

```

학생 자가 의문: "step1 리뷰를 바탕으로 ',' split을 view에서 하는 게 맞다는 판단. 그렇기에 List<List<String>>을 사용해서 [1,2,3,4,5,6],[1,2,3,4,5,6] 이런 식으로 받아올 수밖에 없는데." 리뷰어: "List<List<String>>을 보면 동료 개발자가 처음 이 코드를 보았을 때 이해하기 쉬울까요? 또한, LottoStore에서 Collection을 정제하는 게 좋은 걸까요? InputView로부터 입력받을 때 지금 채채가 만들어 놓은 Lotto를 활용하여, *List<Lotto>*를 받도록 하는 건 어떨까요?"

### 4. `LottoStore.lottos` 외부 노출

```kotlin
class LottoStore(.) {
    var lottos = Lottos()
        private set
}
```

`private set`이지만 *getter*가 외부 노출. Controller가 `lottoStore.lottos`를 직접 사용. → *Tell, Don't Ask* 위반.

학생: "LottoNumberGenerator는 Test 코드에서 TestNumberGenerator을 만들어서 랜덤 값을 제어하기 위한 수단으로 주생성자로 선언해서 관리하고 싶어서 class로 구현." 리뷰어: "class와 object 차이는 *인스턴스화를 통해 객체를 생성, Singleton instance로 생성하는 관점*에 있습니다. 인스턴스화를 통한 객체를 생성하게 되면 *생성하는 객체마다 다른 state*. 현재는 LottoNumberGenerator는 인스턴스화를 통한 각 객체마다의 state가 다를까요? fun generate를 통해 제어." — *상태 유무*가 1차 기준.

## 얻은 교훈

- **검증만 하는 wrapper는 객체가 아님** — `WinningLotto`가 *발행, 매칭, 통계*까지 갖고 가면 진짜 객체.
- **Tell, Don't Ask 적용 후 Controller는 *명령만***. 매번 *정보 조회 후 분기*는 책임이 잘못된 신호.
- **이중 컬렉션은 의도 모호** — View에서 `List<Lotto>`까지 변환 후 도메인에 전달.
- **공통 도메인 모델 ≠ 컬렉션 wrapping** — *Ticket*에 *발행 정보 + 구매 금액*까지 들고 가면 *여러 곳에서 사용할 공통*이 됨.
- **class vs object = 상태 유무**. *상태 없음*이면 `object`. *각 인스턴스마다 state 다름*이면 `class`.
- **`.gitkeep`은 *폴더 비어 있을 때*만 의미** — 채워졌으면 제거.
