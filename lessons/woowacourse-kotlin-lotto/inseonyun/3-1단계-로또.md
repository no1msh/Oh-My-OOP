- **`Lotto` 도메인 invariant = *3개* (개수/범위/중복)** — 모두 *init*에서. *원시값 포장 + Set*은 *invariant 일부를 타입으로 표현*.
- **장수 결정 = *도메인 책임*** — `purchaseMoney.getLottoCount()`. Controller에 두면 *Tell-Don't-Ask 위반*.
- **`Rank` 기본값 매개변수로 *노출 최소화*** — `matchBonus: Boolean = false`로 *MISS/FIRST/THIRD/FOURTH/FIFTH*에 noise 제거.
- **싱글턴 = *강한 커플링*** — *프로퍼티 주입*이 *대체 구현체 가능*.
- **`tryAndRerun` *적용 영역*** — *입력 경계*에만. *도메인 영역에 적용*하면 *의도 외 에러*까지 재실행. PR #40 동일.
- **Tell, Don't Ask** — `lotto.determine(winLotto)`. `controller.organize(lotto.value, ...)` 안티.
- **YAGNI** — *예상으로 인터페이스* 도입 시 *구현체만 사용*하면 부담. *변경 가능성이 실제*일 때만.
- **`Set` = *중복 방지 invariant*** (PR #77 hxeyexn 동일).
- **`Lottos` *복합 책임* (관리 + 생성 + 가격)** = 분리.
- **`LottoPrice` 음수 검증** — *원시값 포장의 본질*은 *invariant*. 검증 없으면 wrapper.
- **방어적 코드 *미래 팀원* 고려** — *현재는 안 깨지더라도* *수정 시 깨질 가능성*.
- **테스트명 = *실제 SUT*** — `RankTest`이지만 *LottoRankDeterminer 테스트*면 *오해 유발*.
- **`@BeforeEach` 중복 제거**.
- **`given/when/then`** — *3구역 분리*가 *유기적 객체 테스트* 가독성.
- **`List(n) { gen() }`** — Kotlin idiom (PR #113, #60 동일).
- **잭슨의 *코딩 철학 강조*** — *정답 X, 자신의 우선순위와 근거*. PR #75 말리빈과 같은 맥락.
- **PR #3 → #49 (같은 학생 진화)** — 1단계 *World god-naming*에서 *LottoStore + 책임 분배*로 성장.
