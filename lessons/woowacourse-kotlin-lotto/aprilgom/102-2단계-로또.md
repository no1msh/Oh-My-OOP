## 못한 점 + 핵심 지적

### 1. `run()`이 너무 많은 일

```kotlin
fun run() {
    // 입력 + 검증 + 발급 + 매칭 + 출력
}
```

→ 함수 분리.

### 2. `Money.divide` nullable 반환

```kotlin
class Money {
    operator fun div(other: Money): Money? =.  // ⚠ nullable
}
```

> 나눌경우 nullable하도록 설정하신 이유가 있을까요?? 이로 인하여 Money를 계산하는 부분에서 불필요한 nullcheck 하는 로직이 들어가고 있는 것 같습니다.

→ 0 나눗셈은 예외 또는 *Optional 표현 명시*. 임의의 nullable 회피.

### 3. 수동 로또 생성 객체 부재

```kotlin
class RandomLottoTicketGenerator {. }
// ⚠ 수동 생성 객체 없음
```

> 현재 RandomLottoTicket을 생성해주는 객체는 존재하지만 수동으로 로또 티켓을 만들어주는 내용은 존재하지 않는 것 같네요

→ Strategy 인터페이스로 자동/수동 통합.

### 4. `Rank.decideRank()` when 사용

```kotlin
fun decideRank(.): Rank = when (.) {. }
```

> decideRank 함수에서 Enum의 API를 활용하여 when식은 가능하면 쓰지 않고 구현해 보는 방식을 고민해보면 좋을 것 같다는 생각이 듭니다

→ `entries.find {. } ?: MISS` 패턴.

### 5. `initList` 메서드명 — 의미 불명

> 코드양이 많아질 경우 initList라는 네이밍에 대해서 고민해보는 것도 좋을 것 같습니다!

## 얻은 교훈

- **nullable의 의미는 *부재***. 0 나눗셈 같은 *오류* 표현 X.
- **자동/수동 통합** = Strategy 인터페이스 + 두 구현체.
- **enum API > when 분기** — `entries.find {. }`로 fallback.
