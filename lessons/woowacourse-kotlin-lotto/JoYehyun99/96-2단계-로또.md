## 못한 점 + 핵심 지적

### 1. `in` → `contains` 변경 이유?

```kotlin
fun hasNumber(n: LottoNumber): Boolean = numbers.contains(n)  // 이전엔 `n in numbers`
```

> in 연산자에서 contains 함수로 변경한 이유가 무엇이었나요?

→ Kotlin에서 둘은 같음. *왜* 변경했는지가 더 중요.

### 2. 자동/수동 발급 로직 중복

```kotlin
fun generateManual(numbers: List<Int>): Lotto = Lotto(numbers.map(::LottoNumber))
fun generateAuto(): Lotto = Lotto(randomNumbers().map(::LottoNumber))
```

> 자동 발급 로직에서 수동 발급 로직을 재활용해보는 건 어떨까요?

→ 자동 = "랜덤 번호로 수동 생성"으로 재해석.

### 3. LottoNumber 캐싱 검증 테스트 부재

> 늘 같은 인스턴스가 실제로 반환되고 있는지 테스트 코드로 검증해보는 건 어떨까요?

→ `assertThat(LottoNumber.of(1)).isSameAs(LottoNumber.of(1))`.

### 4. 생성자 + 팩토리 메서드 둘 다 — 의도?

```kotlin
class PurchaseAmount(val value: Int) {
    init { require(...) }
    companion object {

            require(...)
            return PurchaseAmount(input.toInt())

```

> 생성자를 사용하는 것과 팩토리 메서드를 사용하는 것 두 가지 모두 구현한 이유가 무엇일까요? 검증 로직도 굉장히 비슷하네요!
