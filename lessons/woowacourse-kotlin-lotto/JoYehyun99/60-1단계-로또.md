## 못한 점 + 핵심 지적

### 1. Controller가 비교 로직

```kotlin
fun run() {
    val results = lottos.map { lotto -> compareWithWinning(lotto) }  // ⚠ Controller에서 비교
}
```

> 로또와 당첨번호를 비교해서 결과를 만들어내는 이 로직은 도메인 로직이네요. 도메인 객체에 이 역할을 부여해보는 건 어떨까요?

### 2. `LotteryResult` 검증만 (행위 부재)

```kotlin
class LotteryResult(...) {
    init { require(...) }
    // 행위 없음
}
```

> 이 객체는 생성 검증을 하는 것 말고 큰 역할을 가지고 있지 않네요. 이 객체에게 메시지를 던져 시킬만한 일이 무엇이 있을까요?

### 3. `check~` 메서드 이름이 일관성 없음

```kotlin
fun checkSize(): Int = numbers.size
fun checkDuplicate(): Boolean = ...
```

> check~ 로 시작하는데 어떤 건 숫자를 반환하고, 어떤 건 Boolean을 반환하고 있네요! check~ 이 메서드들을 보고 드는 생각은, 무언가 체크는 하겠구나. 정도이고, 무언가를 반환할 거라는 생각이 들지는 않았어요.

→ `check`은 *검증 행위* 시사. `size`, `hasDuplicate()` 같은 *반환 의미* 명시.

## 얻은 교훈

- **`check*` 함수명은 *반환값을 시사하지 않음***. 검증/예외 던지기 정도가 자연 의미. 반환이 있으면 다른 이름.
- **도메인 객체에 *행위 부여 필수***. 값만 + 검증만 = wrapper.
