### 4. `!!` 강제 언패킹 — Null-safety 우회

리뷰어: "`(readInputMoney().value?.div(Money.MONEY_UNIT))`이 null이 아님을 보장할 수 있을까요?" + "manualLottoCount가 null이 아니라는 것을 보장할 수 있을까요?" 학생: "제 머릿속에서는 보장할 수 있었기에 이렇게 작성했지만 코드를 보는 입장에서는 그렇지 않기 때문에 변경했습니다." — *나만 아는 invariant*는 *코드에 명시*되어야.

### 5. `let` 남용 — *null 회피*가 아님

```kotlin
Rank.valueOf(

    lotto.checkMatchingBonusNumber(winningNumbers.bonusNumber)

    ranks.add(it)

```

리뷰어: "let을 잘 활용해 주셨네요. let은 mutable하면서 nullable한 경우에만 사용하는 것을 권장하며, 단순히 null을 회피하기 위해 사용하는 것은 권장하지 않습니다." — `let`은 *변환*/*scope*용, *null 가드*는 `?.also`/`if (x != null)`.

### 11. 학생 자가 의문 — `require` vs null

학생: "input에 대해 오류가 예상되는 input이라고 생각했었는데요, 그럼 이 경우에는 require 문으로 검증하는 게 맞는 방법일까요? 결국에는 require 문이 exception을 던진다고 생각해서 이런 경우에도 null로 처리를 하는 게 맞을까요?" 리뷰어 답 패턴: "부생성자를 활용하거나 팩토리 메서드를 활용해 보면 어떨까요?" — *생성자 검증*에서 예외, *팩토리*에서 null/Result.

## 리뷰어 의견 요지

1. **InputView 책임 = 입력만**, 변환은 *View와 Domain 모두 접근 가능한 곳*(Controller, Mapper).
2. **검증은 *도메인*에서** — Validator에 집중하면 *요구사항 변경 시 View+Domain 동시 변경*.
3. **함수명 = 구현부 일치** — `initializeLotto`인데 `List<Lotto>` 반환은 의미 어긋남.
4. ***내 머릿속의 invariant*는 *코드에 명시*되어야** — `!!`는 *암묵 가정*의 표현.
5. **`let`은 *scope/변환*, *null 회피*가 아님** — 적절한 용법 학습.
6. **매직넘버 = *도메인 상수*** — `3`은 *최소 당첨*, `6`은 *로또 크기*.
7. **부생성자 = 언어 기능 부족 신호** — Kotlin default value로 단순화.
8. **단순 위임 함수는 *시스템 함수 직접 호출*이 더 가독성** — 추상화 비용 > 가치면 *없애기*.
9. **함수명에 *자료형* 노출 X** — *반환 타입*은 시그니처 책임.
10. **반드시 통과하는 테스트 = 가치 0** — *깨질 수 있는 케이스*를 잡는 것이 테스트 가치.

## 얻은 교훈

- **InputView 책임 = 입력만**. 변환은 *Controller* 또는 *Mapper*. View가 도메인 객체를 만들면 *View 변경 = 도메인 변경*.
- **검증은 *도메인에서 자기 invariant***. Validator로 집중하면 *Validator + Domain + View* 세 곳이 변경에 흔들림.
- **함수명 = 구현부**. `initialize*` vs `make*` vs `get*`은 *부수효과 + 반환*의 신호가 달라야.
- **`!!`는 *암묵 가정*의 표현**. 내가 아는 *invariant*를 *코드/타입*으로 명시해야 미래 동료가 안전.
- **`let`은 scope/변환용, null 회피가 아님**. `?.also`/`if`로 의도 명시.
- **매직넘버 = 도메인 상수로**. *3*/*6* 같은 숫자는 *Lotto의 정체성* 또는 *Rank의 분류 기준*.
- **부생성자는 Kotlin에서 *드물게 필요*** — default value로 *대부분 대체 가능*.
- **단순 위임 함수의 *추상 비용***  — `readInputNumber` → `readln()`에 *추가 정보 없음*이면 호출 위치에서 직접 사용.
- **함수명에 *자료형* 노출 X** — *반환 타입*은 시그니처. `readStringList` → `readManualNumbersInput`.
- **테스트는 *깨질 수 있는 케이스*를 잡는다** — *반드시 통과*하는 테스트는 *변경 감지력 0*.
- **`require` vs null** — *생성자 검증*은 예외(invariant), *팩토리*는 null/Result. *주생성자*는 의도된 사용처에서만.
