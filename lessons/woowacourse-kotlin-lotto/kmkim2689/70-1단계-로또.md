### 1. `Rank.valueOf`의 *복잡한 분기*

```kotlin
companion object {
    private const val MIN_COUNT = 0
    private const val MISS_MAX_THRESHOLD = 2
    private val NON_BONUS_COUNTS = listOf(3, 4, 6)
    fun valueOf(countOfMatch: Int, matchBonus: Boolean): Rank = when {
        countOfMatch in MISS_RANGE -> MISS
        countOfMatch == SECOND.countOfMatch && matchBonus -> SECOND
        countOfMatch == THIRD.countOfMatch -> THIRD
        countOfMatch in NON_BONUS_COUNTS -> entries.first { it.countOfMatch == countOfMatch }
        else -> throw IllegalArgumentException(.)
    }
}
```

학생 자가 정리: "Rank 객체에 대해 어디까지 책임을 부여해야 할 것인가에 대해 논의. 한 의견은 *발행된 로또와 비교까지* 부여, 다른 의견은 *상수로만 활용*. 결국 Rank라는 명사의 의미(*순위라는 정보*)에 초점을 맞추어, 상수로만 활용." 리뷰어: "이미 고민에 대해 *훌륭한 결론*. … 한눈에 각각이 무슨 값을 가지고 있는지 들어오는 Rank에 비해, Rank1이 더 많은 코드를 읽어야 하기 때문입니다."

### 2. `runCatching + onFailure { return retry() }` — 무한 루프 + indentation 깊이

```kotlin
private fun getPurchaseExpense(): Int =
    runCatching {
        lottoGameInputView.inputPurchaseExpense()
    }.onFailure {
        if (it is IllegalArgumentException) return getPurchaseExpense()
    }.getOrThrow()
```

리뷰어: "runCatching을 활용해 onFailure 처리를 해주시는 점 멋집니다. 하지만 예외 처리는 근본적으로 *if-else 처리와 다를 바 없다*는 점을 명심하세요. *만약 이러한 예외가 발생한다면, 이러한 로직을 처리한다*라는 조건문입니다. 즉 위와 같은 상황에서는 *조건문이 중첩되어 indentation depth가 깊어진 것*과 동일한 상황입니다. 로직을 더 작은 단위로 쪼갤 필요가 있어 보입니다. 뿐만 아니라 *조건문이 들어갔다는 것은, 곧 테스트할 로직이 있다는 의미*. Controller에 있는 로직들을 model로 옮겨서 테스트 용이하도록." + "만약 `inputPurchaseExpense()`에서 IllegalArgumentException이 계속 발생하면 *무한 루프*를 돌아야 하나요? 언제 탈출할 수 있을지에 관해서는 *조건*을 생각하면 좋을 것 같습니다. 안드로이드 개발에서 *폰이 갑자기 뜨거워지면서 벽돌*."

## 리뷰어 의견 요지

- **runCatching = if-else** — *indentation depth*는 *조건문 중첩*과 같음. 로직 분리 + 테스트.
- **`return retry()`는 *무한 루프* 위험** — *탈출 조건* 또는 *최대 시도 횟수* 고려.
- **사용자 메시지 = *행동 안내*** — *정수여야 합니다*는 *너무 좁음*.
- **명사형 명명 = 자연어 따라가기** — `Lottie` → `Lottos`.
- **상수 + 메시지 = *상수 참조***로 변경 동기화.
- **value class 도입의 *기준* 명시화**.

## 얻은 교훈

- ***runCatching은 if-else의 다른 표현*** — indentation은 같음, 테스트 가능성도 같음.
- **재시도 = 탈출 조건 필요** — *무한 루프*는 *벽돌화 위험*.
- **사용자 메시지 = *행동 안내*** — 도메인 invariant를 *행동으로 옮길 수 있게* 표현.
- **명사형은 자연어 따라가기** — *Lottie* 같이 *별난 변형*은 *읽는 부담*.
- **상수 + 메시지 = 상수 참조** — 변경 동기화.
- **value class 도입은 *명시적 기준*** — 호출자에게 *왜 이 클래스가 value class인지* 보여야 함.
