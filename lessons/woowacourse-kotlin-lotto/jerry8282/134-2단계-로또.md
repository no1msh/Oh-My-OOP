## 핵심 지적

### 1. `ConvertMachine` — `Mapper`가 통용

```kotlin
object ConvertMachine { fun toLotto(...): Lotto = ... }
```

> ConvertMachine 이라는 네이밍도 좋지만, 흔히 Mapper 라는 네이밍도 많이 사용하기는 합니다!

### 2. View가 String → 도메인 객체 변환 vs Int

학생 자가 의문:

> 원래 view에서 값을 넘길 때 무조건 String 이나 List으로 넘겨주었는데 이번 리팩토링 과정에서 객체로 반환하거나 Int값으로 반환을 하였습니다. 이러한 방식이 View의 역할에 위배되는지 궁금합니다!

→ View → Domain 의존은 허용. 도메인 객체 반환 자연스러움.

## 얻은 교훈

- **변환 객체 이름의 표준 = Mapper**. ConvertMachine은 자유롭지만 컨벤션과 거리.
- **View가 도메인 객체 반환 OK**. View → Domain은 허용된 의존.
