## 잘한 점

- **현실 비유로 모델 설계 시도** — LottoResult를 *결과 확인 사이트*로, Controller를 *구입자*로 명시.

## 못한 점

### 1. 테스트만을 위해 public

```kotlin
class LottoMachine { 
    fun generateInternal(): Lotto = ...  // ⚠ Controller가 안 부르는데 public
}
```

> controller에서 직접적인 호출 없이 테스트 코드를 위해 public으로 선언된 메소드입니다...

→ 테스트만을 위해 가시성 변경 회피. internal 또는 design 조정.

### 2. InputView 메서드 중복 패턴

```kotlin
fun readPurchase(): String { println("..."); return readln() }
fun readWinning(): String { println("..."); return readln() }
fun readBonus(): String { println("..."); return readln() }
```

→ `fun getData(message: String): String { println(message); return readln() }` 추출.

## 얻은 교훈

- **현실 비유로 책임 분배 검증** — "구입자 vs 결과 확인 사이트" 같은 비유는 데이터 소유자 명확히.
- **테스트 위한 가시성 변경 금지**. 도메인 재설계가 답.
- **반복 print + readln 패턴** = 헬퍼 함수 추출.
