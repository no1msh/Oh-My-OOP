## 못한 점 (설계 관점)

### 1. feature-envy — WinningLotto가 Lotto의 numbers 꺼내 비교

```kotlin
class WinningLotto(...) {
    fun isWinning(lotto: Lotto): Boolean {
        return winningNumbers.lottoNumbers.contains(...)  // ⚠ Lotto 내부 접근
    }
}
```

> `Lotto`에게 x가 포함되어 있어? 하고 메시지를 던져보는건 어떨까요?

→ `lotto.contains(number)` 메시지.

### 2. count 함수 미활용

```kotlin
val matchCount = lotto.numbers.filter { it in winningNumbers }.size  // ⚠ filter().size
```

→ `count { ... }` 한 줄.

### 3. 등수 테스트가 1등만

```kotlin
@Test fun `1등 매칭`() { ... }
// ⚠ 2,3,4,5등, 꽝 미테스트
```

> 다른 등수들도 테스트해보면 좋을 것 같네요!

## 얻은 교훈

- **Tell-Don't-Ask** 적용 — `lotto.contains(number)`로 메시지.
- **컬렉션 함수의 의도 명시** — `filter().size` < `count {}`.
- **enum 케이스 전부 테스트** — 각 등수가 다른 비즈니스 분기.
