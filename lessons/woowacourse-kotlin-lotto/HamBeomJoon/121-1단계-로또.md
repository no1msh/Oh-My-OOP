## 못한 점 + 핵심 지적

### 1. `Constants.kt` global

> 상수는 공통으로 여러 곳에서 사용하는 것이 아니라면, 사용하는 곳에 정의해두면 어떨까요?

### 2. `LottoStore` — Controller 역할? 도메인 이름?

```kotlin
class LottoStore { ... }  // 실제는 Controller
```

> `LottoStore`가 컨트롤러 역할을 하고 있군요! 언뜻 보기에 `LottoStore`라는 네이밍은 도메인 이름 같은데... 이렇게 네이밍하게 된 이유가 있으실까요?

→ "Store"는 도메인 어휘 (가게). Controller라면 `LottoController`가 명확.

### 3. `map` vs `forEach`

```kotlin
lottos.map { it.print() }  // ⚠ 반환값 미사용
```

> 여기서 `map`은 람다식의 결과로 새로운 리스트를 만드는 함수에요. `forEach`가 더 적절해보입니다.

→ 변환 ≠ 순회. map의 반환값 안 쓰면 forEach.

### 4. `LottoTicket` — 당첨/일반 합침 + nullable bonus

```kotlin
class LottoTicket(val numbers: List<LottoNumber>, val bonus: LottoNumber? = null) { ... }
```

> 당첨 로또 번호와 구입한 로또 번호를 같은 클래스로 사용하고 있네요! 이 둘은 겹치는 역할도 있지만, nullable로 해주신 것처럼 보너스 숫자를 모두 가지지는 않아요. 그렇다면 아예 분리를 해볼 수 있을까요? 당첨 로또와 그냥 로또, 그리고 이 둘의 관계를 연관지을 수 있지않을까요?

### 5. `LottoScanner` feature-envy

```kotlin
class LottoScanner {
    fun matchCount(ticket: LottoTicket, winning: LottoTicket): Int = ...
}
```

> 숫자가 몇 개가 일치하는지, 보너스 번호와 맞는지 로또에게 직접 메시지를 던질 수 있지 않을까요?

### 6. `require` 메시지 누락

```kotlin
require(value in 1..45)  // ⚠ 메시지 없음
```

> 메시지가 없어서 에러가 난다면 왜 에러가 발생했는지 알 수 없을 것 같아요!

## 얻은 교훈

- **클래스명 = 역할 (Controller/Domain/View) 명확히** — "Store"는 도메인, "Controller"는 흐름. 헷갈리지 않게.
- **`map` vs `forEach` — 반환값 사용 여부**.
- **nullable로 두 개념 합치기 회피** = lotto 반복 패턴 (`Lotto` vs `WinningLotto`).
- **require 메시지 = 디버깅 비용 ↓**.
