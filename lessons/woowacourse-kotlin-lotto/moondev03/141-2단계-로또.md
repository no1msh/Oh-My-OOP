
리뷰어: "*로또의 최대, 최소 값이 LottoNumber, RandomLottoNumbersGenerator 모두 가지고 있어요. 최대 최소 값은 누구의 관심사일까요? 🤔 LottoNumber에서 만들어 놓은 값을 잘 활용하려면 어떻게 해야 할까요*?"

## 얻은 교훈

- **MIN/MAX *단일 출처 = LottoNumber***. *Generator는 LottoNumber.getAll() 메시지*로 요청. PR #131, #144 동일 강사 동일 가르침.
- **`Pair? + nullable`** = *두 의미 손실*. *data class*는 *필드 이름*, *Result 객체*는 *상태 표현*.
- **`a to b` Kotlin idiom** = *Pair* 생성 자연.
- **디폴트 파라미터 = *잘못된 추상화 신호*** (PR #131 동일).
- **`service` vs `model` 패키지 *의도 검증*** — *Layered Architecture*가 *DDD*인지 *책임 분배*인지.
- **`Order` 도메인 객체** — *돈 + 수동 번호 + 자동 수*를 *하나의 메시지*로. *현실 메타포* 충실.
- **CsvSource *과사용*** — *테스트 1개면 vanilla `@Test`*.
- **`Lotto.contains(x)` *의미 중립*** — 도메인은 *값 검사*만, *의미 분류*는 호출자.
- **`LottoMachine = Lotto 발급* 현실 비유** — *기계에게 로또 몇 장 줘* + *상점에서 어떤 기계 사용할지 결정*. PR #131 *Cashier-Machine 흐름*과 같은 결.
- **출력 형식 *일관성*** — `Int`와 `List`가 *섞이면* 호출자 *어떤 형식 기대*에 혼란.
- **InputView/OutputView *비대칭 점검*** — *OutputView는 Model 알고*, *InputView는 Model 모름*은 *비대칭 신호*. 둘 다 Model 가능.
- **가시성 *최소화*** — *외부 사용 없으면 private*.
- **테스트명 + 변수명 일치** — *변수명이 테스트 의도 드러내야*.
- **함수 *포함 가능성*** — *별도 함수가 의미가 약하면* 통합 검토.
