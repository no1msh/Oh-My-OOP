## 핵심 지적

### 1. LottoNumber와 RandomLottoNumbersGenerator 양쪽이 MIN/MAX 보유

```kotlin
class LottoNumber {
    companion object { const val MIN = 1; const val MAX = 45 }
}
class RandomLottoNumbersGenerator {
    val numbers = (1..45).shuffled().take(6)  // ⚠ 또 다시 1..45
}
```

> 로또의 최대, 최소 값이 LottoNumber, RandomLottoNumbersGenerator 모두 가지고 있어요. 최대 최소 값은 누구의 관심사일까요? LottoNumber에서 만들어놓은 값을 잘 활용하려면 어떻게 해야 할까요?

→ `(LottoNumber.MIN..LottoNumber.MAX)`로 단일 출처.

### 2. `Pair` + nullable 반환

```kotlin
fun buyLottos(...): Pair<Lottos, Lottos>? = ...
```

> `Pair`로 반환을 하고 있는데 게다가 값이 있을지도 없을지도 모른다? 로또를 구매하는 일을 한다고 생각해보고 조금 더 명확한 값을 반환해보도록 할까요?

→ data class + nullable 의미 명시.

### 3. ParameterizedTest 과사용

> ParameterizedTest를 사용하지 않고 한 번만 검증해도 충분해보여요!

## 얻은 교훈

- **MIN/MAX 단일 출처 = LottoNumber가 소유**. Generator는 LottoNumber 통해 접근.
- **`Pair?` (nullable Pair)** = 두 의미 잃음. data class + nullable 명시.
- **ParameterizedTest의 사용 기준** — 케이스 ≥ 2일 때만.
