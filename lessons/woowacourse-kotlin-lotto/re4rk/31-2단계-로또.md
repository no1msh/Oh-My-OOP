### 11. `assertAll` vs *여러 검증문*

```kotlin

```

리뷰어: "*검증문을 여러 개 쓰는 것과 assertAll로 감싸는 것은 어떤 차이점이 있을까요*?" 후속:
```kotlin

    { assertThat(lottoTickets.size).isEqualTo(2) },
```

## 얻은 교훈

- **메서드 시그니처 = *최소 필요 정보*** — `manual: Lottos`보다 `manualCount: Int`. *과한 인자*는 *결합도*.
- **`LottoStore` *변환 책임 위임*** — *이미 Lotto가 들어오는데 다시 변환*은 의미 약함.
- **`Factory` + `Store` *역할 중복*** = *통폐합 또는 책임 분명화*.
- **`Rank.values()` *사전 채우기 + 필터*** = 불필요. *직접 grouping + eachCount*가 자연.
- **테스트 *예측 값 비교*** — *size만 비교*는 *어떤 값이 생성되었는지 명세 부재*. *Fake Generator*로 *결정적 결과*.
- **상수 *직접 접근*** — *중간 멤버변수*는 *간접화 비용*.
- **`List<Lotto>` *일급 컬렉션*** = 도메인 행위 부여.
- **내부 메서드 *private*** — *외부 의도가 없다*는 신호.
- **`LottoStore = 발급 기능*** — *Money는 호출자 책임* (현실: *고객이 돈 보유*, *발급기는 명령*). PR #131 (krrong) *Cashier 책임 흐름*과 같은 결.
- **함수형 체이닝** — `sequence → map → groupingBy → eachCount → let { Result(it) }`.
- **`assertAll` *Soft Assertion*** — *한 검증 실패해도 나머지 실행*. *모든 실패 한눈에 확인*.
- **테스트 *반복문* 가독성 해침** — *어떤 시점*에 *어떤 값*인지 *추적 비용*. *명시적 케이스 분리*.
- **`현실 비유의 깊이*** — `발급기에게는 돈이 필요하지 않다`는 *책임 흐름 분리*의 강력한 비유. PR #131 *Wallet 비대칭*과 같은 결.
