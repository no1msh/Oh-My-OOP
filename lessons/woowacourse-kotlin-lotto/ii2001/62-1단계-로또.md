## 못한 점 (설계 관점)

### 1. `Veilfier` — 오타 + 의미 불명

```kotlin
class Veilfier { ... }
```

> Veilfier 는 어떤 뜻인가요? 검색해도 어떤 뜻인지 잘 모르겠네요

→ `Verifier`의 오타 + 의미 모호. 클래스명은 *검색해서 의미를 알 수 있어야*.

### 2. `Lotto.numbers: List<Int>` — LottoNumber 미추출

```kotlin
class Lotto(val numbers: List<Int>) { ... }
```

> Int로 단일 로또 번호에 대한 제약 사항을 충분히 표현해낼 수 있을까요? 로또 번호 하나를 객체로써 의미를 담아보는건 어떨까요?

→ lotto의 핵심 안티패턴 (PR마다 반복).

### 3. `WinningNumber` — 값만 보유, 행위 없음

```kotlin
class WinningNumber(val number: Int) {
    // 행위 없음
}
```

> 이 객체는 단순히 값을 가지고있는 것 외에 별다른 역할을 가지고 있지 않고 있네요 이 객체가 맡을만한 일이 무엇인지 찾아 이 객체에게 부여해보는 건 어떨까요?

→ 값 객체 만들었으면 *행위*도 부여. 매칭 판정, 보너스 일치 여부 등.

### 4. `Constant` god-class — 자가 의문 유도

```kotlin
object Constant {
    const val LOTTO_PRICE = 1000
    const val MIN = 1
    ...
}
```

> 이 값들을 하나의 상수 클래스로 묶은 이유가 궁금해요! 필요한 객체가 갖고 있는 것과 어떤 차이점과 장단점이 있었나요?

### 5. `LottoGenerator` 테스트 없음

```kotlin
class LottoGenerator { fun generate(): Lotto = ... }
// ⚠ 테스트 없음 (랜덤 의존)
```

> LottoGenerator에 대한 테스트 코드가 존재하지 않네요 이 객체는 어떻게 테스트 가능하게 만들어볼 수 있을까요? 자동차 경주에서의 랜덤 테스트를 어떻게 만들었는지 다시 되새겨보아요

→ NumberGenerator 인터페이스로 추상화. racingcar에서 학습한 패턴.

### 6. `LottoPrize`에 뷰 요소

```kotlin
enum class LottoPrize(val countOfMatch: Int, val prize: Int, val message: String) { ... }
```

> 도메인 로직에 뷰 요소가 들어있네요!

→ lotto의 또 다른 반복 안티패턴 — Rank/Prize enum에 표시 문자열.

## 얻은 교훈

- **클래스명 = 검색 가능한 단어** — 오타/조어는 동료가 의미 추정 어려움.
- **값 객체에 행위 부여 필수**. 값만 있는 wrapper는 *얇은 위장*. 행위가 있어야 객체.
- **이전 미션 (racingcar) 학습 적용** — NumberGenerator 추상화는 racingcar에서 받은 가르침. 동일 패턴.
