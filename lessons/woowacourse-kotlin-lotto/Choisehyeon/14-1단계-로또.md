## 얻은 교훈

- **빈 객체 + 외부 채우기 = *invariant 시간차*** — 생성 시점에 *불완전*. *완성된 객체 반환*이 *invariant 즉시 보장*.
- **`matchLottos` *양쪽 중복*** = 책임 위치 모호. *WinningLotto*가 *매칭 진입점*.
- **`Rank.from` 분기 순서 = *비즈니스 의도*** — *2등 먼저 검사*가 *bonus 동률 처리* 명세.
- **양방향 의존 = *순환 위험 + 변경 전파*** — `Lotto.match(winning)` 또는 `winning.match(lotto)` 한쪽만.
- **`hasBonusNumber()` *항상 true* = 불필요** — *invariant인 속성*은 *질문할 필요 없음*.
- **`ParameterizedTest` *1번만*** = 잘못된 도구. *vanilla `@Test`* 충분.
- **테스트 준비 = *생성자/팩토리*** — `numbers.map { ... }`보다 *Lotto(1,2,3,4,5,6)*가 *의도 즉시*.
- **주석의 *거짓말 위험*** — *컴파일러가 검증 안 함*. 코드 변경에 따라가지 않음.
- **반복 테스트 *의미 있는 횟수*** — *값만 바꾸는 반복*은 *시그널 없음*. *경계값/엣지 케이스*가 의미 있는 반복.
- **`(1..45).shuffled()` *매번 생성*** → *상수 컬렉션 재사용*. *Flyweight*의 변형.
- **생성자 위치 = *멤버 함수 가장 상위*** — Kotlin 컨벤션 (PR #3 동일).
- **체이닝 *줄 분리*** = *디버깅 가독성*. *Exception 라인 추적*.
- **`String +` → *템플릿/StringBuilder*** — *불변 문자열* 매번 생성.
- **랜덤 외부 주입** — *자동차 경주 학습*. 일관된 가르침.
- **출력 메시지 검증** — *경로 통과만으로 부족*. *어떤 내용이 출력되었는지*도.
- **`(1..count).map { gen() }` / `List(n) { gen() }`** — Kotlin idiom (PR #3, #60, #113 동일).
- **`String?.isNullOrBlank()` *Kotlin stdlib*** 활용.
- **리뷰어의 *피드백 롤백 오해 정정*** — *부분 변경 의도*를 *전체 롤백*으로 오해 가능. 대화의 정확성 신호.
