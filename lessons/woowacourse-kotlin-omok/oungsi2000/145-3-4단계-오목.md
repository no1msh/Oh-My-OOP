### 1. Dao *테스트 전략 자가 narrate* — 라이브러리 vs 자가 작성 쿼리 학생 자가 토론 정점

제이든 응답 (정점 어휘):

> *"말씀하신 것처럼, 실제 DB를 거치지 않는 테스트용 DAO(mock or fake)는 통합 테스트보다 빠르고 독립적인 테스트 환경을 만드는 데 정말 유용합니다. ... ### 6. *direct cursor 처리 → 데이터 의미 ↔ 비즈니스 결합 어휘*

제이든 (OmokBoardExt.kt — 직렬화/역직렬화):

> *"현재 밀러는 보드 상태를 한줄로 저장하고 싶으신 걸까요? database는 [moveToNext](https://developer.android.com/reference/android/database/Cursor#moveToNext()) 라는 키워드를 제공하는데요, 이는 왜 존재할까요? SQLiteDatabase는 관계형 데이터베이스로 insert를 통해 테이블의 Column에 맞춰 Row가 생성되는 형식입니다. 예를 들어, (3, 5) -> Black을 저장한다면 X = 3, Y = 5, Color = Black 을 저장하고 그 다음 수를 놓아지면 X = 4, Y = 5, Color = White 를 저장할 수 있는거죠 데이터를 가져올 땐 cursor 포인터를 통해 각 Row에 접근하여 데이터를 하나씩 꺼내옵니다. 현재 구조에서는 도메인의 타입이나 로직이 변경된다면 이곳의 직렬/역직렬 로직 또한 대량으로 수정이 필요할거에요. SQLiteDatabase를 보다 효율적으로 활용할 수 있는 방법으로 개선할 수 있을까요?"*

밀러 자가 narrate:

> *"이 부분에서 애를 많이 먹었네요. 테이블을 두 개로 쪼개어 각각, 오목 돌, 마지막으로 놓아진 돌 테이블을 분리했어요. 다 괜찮은데 디버깅 시, 뒤로 가기로 어플을 종료하면 db가 살아있는데, 앱을 강제종료하면 db가 날라가는 문제가 있어요."*

제이든 후속 (SimpleLatestStoneDao.kt):

> *"마지막으로 놓아진 돌 테이블? 은 별도로 저장하신 이유가 궁금합니다 🧐"*

→ **인사이트** (Hevton/88 *데이터 의미 ↔ 비즈니스 결합* 결의 *밀러 측 cursor 변주*): 밀러는 *보드 상태 = 한 줄 직렬화* (도메인 boardState → "BWBW..." String). 제이든의 *Row 단위 저장 (X, Y, Color)* 권장 = **데이터 의미 = 도메인 어휘 분해**. *한 줄 직렬화 = 도메인 변경 시 직렬/역직렬 대량 수정* (`change-scenario-based-abstraction` 의 *직렬화 측 변주*). Row 단위 = *도메인 변경 격리* + cursor 의 *moveToNext 의 의미 학습*. 파이로 *원천 vs 파생 데이터* 결의 *직렬화 측 변주* — *원천 데이터 (X, Y, Color) 저장 = 파생 (보드 그리기) 가 데이터로부터 다시 계산*.

특히 밀러의 *별도 테이블 (마지막 놓아진 돌)* = **데이터 정규화 부재 신호** — *마지막 돌 = 전체 돌 중 max(순서)* 로 도출 가능하나 *별도 테이블 분리* = *파생 데이터의 원천 격상*. 파이로 *원천 vs 파생* 어휘의 *밀러 자가 도달 X 사례*.

## 도메인 특수 어휘 (Android + SQLite)

- **`OmokGameActivity`**: 게임 Activity — Controller / View 양면 자가 토론 자리
- **`OmokGame`**: 도메인 모델 — *콘솔 호환성 = 외부 검증 기준* (제이든)
- **`OmokDao`** / `OmokDaoImpl`: 데이터 접근 객체 — *Contract 객체 동반 자가 의문*
- **`Contract` 객체** (구글 권장): Column 상수 + SQL 쿼리 한 자리 — *MVP 패턴 배경 어휘*
- **`OmokDbHelper`** / `FakeDbHelper`: DB Helper — *Fake 사용 정당화 자가 의문*
- **`OmokBoardEntity`**: DB Entity — *Column ↔ 프로퍼티 매핑 명시*
- **`OmokBoardExt`** (직렬화/역직렬화): 보드 상태 ↔ DB Row 변환
- **`SimpleLatestStoneDao`**: 마지막 놓아진 돌 별도 테이블 — *정규화 부재 신호*
- **`Container`**: DI 흉내 → 자가 폐기 + MainActivity 직접 생성
- **`SQLiteDatabase` / `SQLiteOpenHelper`**: Android SQLite 표준 API
- **`onUpgrade` / `onDowngrade`**: DB 버전 변경 콜백 — *gpt 코드 자가 인정*
- **`cursor.moveToNext()`**: Row 단위 순회 — *왜 존재하는가 학습 권장*
- **`use { ... }`** (Kotlin.io): Closeable 자동 close — 메모리 누수 회피
- **`Closeable`** (java.io): 자원 해제 표준 인터페이스
- **`ApplicationProvider`** (androidx.test:core): androidTest 환경 Context 제공
- **`lateinit var` + `!!`**: 비-null 강제 주입 → 키 부재 시 런타임 크래시
- **`intent.getStringExtra(key)`**: Activity 간 데이터 전달 — *경계 null 처리 필요*
- **`Log.wtf` (What a Terrible Failure)** / `Log.d/e/i`: 로그 레벨 — 중요도 분류 어휘
- **`Room`**: Android ORM — *ORM 자동 = 라이브러리 신뢰 / 직접 쿼리 = 자가 작성 의심 = 테스트 필요*
- **MVP / MVC 패턴**: 학습 단계 외 주제 — *레벨2 학습 권장*
