### 3. onStartPut — *명명의 영어 자연스러움* 검증

빙티는 페어 토론 결과로 `onEndPut` → `onStartPut` 명명을 채택. 말리빈 응답:

> *"별개로, **onStartPut은 마치 게임 맨 처음 돌을 놓을 떄 딱 한 번만 호출 될 것 같이 생긴 메서드**라, 의도를 파악하는데에 조금 시간이 걸렸네요. 또, `on+명사+동사` 이렇게 쓰는 것이 자연스러워서, 이름이 더 어색해 보인 것도 있었어요!*
> *```*
> *onButtonClick (O)*
> *onClickButton (X)*
> *```"*

→ **인사이트** (블랙잭 INSIGHTS 10 — 가상 객체 / 모호한 이름의 *영어 어순 변주*): 빙티의 `onStartPut` 은 *동사 + 동사* 어순 (`Start` + `Put`) 으로 *영어 어순의 자연스러움*을 어긴다. *Android 이벤트 핸들러 컨벤션* 의 `on + 명사 + 동사` (`onButtonClick`) — *명사가 무엇* + *동사가 무슨 액션*. 빙티의 `onStartPut` 은 *Put 명사 + Start 동사* 어순이라면 자연스럽지만 *Start + Put 두 동사* 어순이라 *호출자가 의도를 추측하는 비용* 발생.

호두/103 의 *`viewStone → showStone` 영어 의미 자가 자각* 과 *같은 결*. *영어 어휘 정확성*도 OOP 명명의 일부.

## 못한 점 (설계 관점)

### 1. 결정의 *이유 (rationale)* 가 PR body 에 명시되지 않음

빙티의 페어 토론 narrate 가 *두 의견을 잘 정리* 했으나 *왜 1번을 골랐는가* 의 결정 근거는 PR body 에 없다. 페어 합의 사항만 적힘 (*"결국 onStart만 넣는 것으로 결론이 났습니다"*).

말리빈의 *Position 캐싱 질문 뒤집기* 와 *PutEvent 명확한 이유 요구* 두 자리 모두 *결정 근거가 PR body 에 없는 것을 가리킴*.

→ **인사이트** (`decision-without-rationale` 룰 후보 보강): 빙티는 *판단 + 페어 의견 + 페어 합의*는 적었으나 *최종 채택의 이유* 는 빠뜨림. *결정 (decision)* 과 *이유 (rationale)* 분리:

- **결정**: "1번 채택 (15까지 캐싱)" / "onStart 한 개만 추가"
- **이유**: ??? (PR body 에 없음)

말리빈은 *질문 자체를 뒤집어* (*"왜 캐싱했는가"*, *"왜 분리/통합 했는가"*) *결정의 근거 자리를 만들어줌*. **학생이 PR body 에 결정을 narrate 할 때 *이유 슬롯이 비어 있으면* 자기 기준 점검의 신호**.

### 2. 라인 코멘트 부재 — LMS 마감 시간 규칙

PR #71 의 *모든 코멘트가 PR view 일반 코멘트 1개 (말리빈)*. 라인 코멘트는 0개. 말리빈의 머지 메시지:

> *규칙상 안타깝게도 바로 머지하겠습니다.*

빙티 PR body 의 페어 토론 3 토픽에 대한 *세부 코드 라인 단위 피드백*은 받지 못함. 말리빈은 *PR body 토픽에는 일반 코멘트로 답변* 했지만 *코드 자체에 대한 라인 리뷰는 X*.


### 3. *오버엔지니어링* 어휘를 학생 자가 사용

빙티 PR body:

> *"또한 두 이벤트를 모두 추가하기엔 오버 엔지니어링처럼 느껴져 결국 onStart만 넣는 것으로 결론이 났습니다."*

빙티는 *오버엔지니어링* 어휘를 *자기 코드의 한계 검증* 도구로 씀. 다만 *기준 (왜 두 이벤트 = 오버엔지니어링)* 은 적지 않음.


### 4. *3P 확장* 시나리오의 *해소* 미흡

빙티가 PR body 에 *3P 시 PutEvent 콜백 폭증* 문제를 직접 짚었으나 *해소책*은 *트레이드오프로 봐야 하나?* 의 질문 형태. 학생 자가 답을 정하지 못함.

말리빈의 답은 *"왜 이렇게 짰는지 충분히 논리적인 이유를 생각해두면 된다"* — *해소책*보다 *결정 근거 명시화*를 권장.

→ **인사이트**: *변경 시나리오 자가 질문* 의 *학생 측 한계* — *시나리오는 보았지만 그 안에서 결정의 기준이 모호*. 말리빈은 *기준을 외부에 묻는 것* 을 *기준을 자기 안에서 만드는 것* 으로 *돌려보냄*.

## 도메인 특수 어휘 (1·2단계 오목)

- **Position 캐싱 범위 (15 vs 21)**: 정적 팩토리 메서드 `Position.of(row, col)` 의 캐싱 한도. *현재 요구사항 (15x15) vs 추후 바둑 확장 (21x21)* 두 안 토론 자리.
- **GameState 상태 패턴**: 빙티의 1·2단계 핵심 추상. *Finish + Playing* 분기. 호두/68 의 *StoneState enum* 결과 *대비쌍* (sealed/상속 위계 vs enum 절제).
- **PutEvent 콜백 (onStartPut / onEndPut)**: 도메인 → View 이벤트 전달. *흑/백 콜백 분리* (1P 확장 대응) vs *통합 콜백* (3P 확장 대응) 의 트레이드오프 토픽.
- **`on + 명사 + 동사` Android 이벤트 핸들러 컨벤션**: `onButtonClick` 어순. 빙티 `onStartPut` 명명의 *영어 어순 부자연스러움* 자리.
- **페어 (빙티 + 오둥/murjune)**: PR body 의 *두 의견 narrate*. murjune 의 단독 PR #72 (batch 11) 의 *불변/가변 영역 자가 분리 선언* 어휘와 *페어 활동 시드 자리*.
- **주민등록번호 PK 비유**: 말리빈의 *변경 시나리오 현실 비유*. *예상 vs 예상 못함 양면 비용* 어휘.
- **LMS 마감 시간 규칙**: 라인 리뷰 없이 즉시 머지. PR body 토픽에는 일반 코멘트로 답변. *코퍼스 형식의 한계 신호 케이스*.
