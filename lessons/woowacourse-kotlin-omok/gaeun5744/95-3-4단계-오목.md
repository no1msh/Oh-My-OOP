### 2. *StoneDbHelper 파라미터 vs 공용 상수* 토론 — *동적 쿼리* 해소

벼리 PR body:

> *"### 2. StoneDbHelper 파라미터*
> *테이블의 이름이나 row, col 등은 `StoneDbHelper` 클래스와 `StoneDao` 클래스에서 공통으로 쓰입니다.*
>
> *공용 상수로 둔다면, 객체 어디서든 접근할 수 있기 때문에 위험하다는 생각이 들어서 고민 끝에 `StoneDbHelper`의 파라미터로 두었습니다. 왜냐하면 **해당 객체에 의존해야 접근할 수 있기 때문에, 무분별한 접근을 막을 수 있을거라 생각했습니다.**

>
> *파이로는 어떻게 생각하시나요? 혹시 해당 방법 말고도 무분별한 접근을 막을 수 있는 방법이 있다면 추천 부탁드립니다!! 😊😊"*

**파이로 = 시간 부족 학생 배려 어휘** (*"시간이 촉박하시면 꼭 리팩토링 해주지 않아도 괜찮습니다"*) — reviewer 측 *학습 약속 자리* 어휘.

### 4. *클릭마다 저장 + 게임 종료 시점 초기화* — 효율적 방식 파이로 칭찬

파이로 (`MainActivity.kt`):

> *"Activity 가 처음 생성될 때 DB 로 부터 저장된 데이터를 전부 가져오고,*
> *setOnClickListener 를 통해 클릭할 때만 dao 를 통해 데이터를 저장하고 있군요.*
> ***보드의 모든 데이터를 저장하는게 아니라 실제로 클릭된 데이터만 저장하는 거 효율적인 방식 같습니다.*** 👍"*

> *"onDestroy 와 같은 생명주기가 아니라,*
> ***게임이 종료되어서 결과를 보여줄 때만 초기화를 시키는 것도 무척 효율적인 것 같습니다.*** 👍"*

→ **인사이트** (블랙잭 INSIGHTS 7 — 도메인 vs 표현, *생명주기 ↔ 도메인 이벤트 분리*): 벼리의 두 결정:

1. **저장 시점 = setOnClickListener (도메인 이벤트)** — Android 생명주기 (`onPause`) 대신 *돌 놓는 도메인 이벤트* 에 저장. *생명주기 (플랫폼 어휘) 와 도메인 이벤트 (Stone 착수) 분리*.
2. **초기화 시점 = 게임 종료 시점 (도메인 이벤트)** — `onDestroy` (플랫폼 어휘) 대신 *게임 결과 = 도메인 이벤트* 에 초기화.

**플랫폼 어휘 (생명주기) ≠ 도메인 어휘 (게임 이벤트)** 분리 자가 적용. 호두/103 *Controller = 콘솔 출력 / Activity = Android Controller / OmokGame = 도메인 흐름* 결의 *생명주기 ↔ 도메인 이벤트 변주*.

### 5. DELETE vs DROP — AUTO_INCREMENT PK 초기화 차이 학습

파이로 (`StoneDao.kt`):

> *"제이슨이 수업 때 delete 와 drop 의 차이 대해서 설명을 해주셨는데,*
> *벼리가 이해하고 있는대로 답변 부탁드립니다.*
> *그리고 초기화를 할 때 DROP 이 아닌 delete 를 선택하신 벼리의 생각을 같이 적어주시기 바랍니다."*

벼리 답:

> *"Delete는 테이블에서 데이터를 삭제하는 명령어이고, 잘못 삭제되어도 되돌릴 수 있습니다.*
> *Drop은 테이블 객체 자체를 삭제하는 것으로 알고 있습니다!*
>
> *Delete가 로직 연산 비용적인 측면에서 좋기도 하지만, 저는 개발자의 실수로 데이터가 사라져도 다시 복귀할 수 있다는 점에서 delete를 선택했습니다!"*

벼리 후속 (자가 의문):

> *"혹시 그냥 drop/delete와 drop/delete를 이용한 초기화가 서로 다른가요...?*
> *delete를 사용한 이유는 앞의 코멘트와 같습니다!! 제가 거기에 대해서까지는 기억이 안나서,,, 혹시 둘의 차이점을 알려주시면 감사하겠습니다ㅠㅠ"*

파이로 답:
