## 얻은 교훈 (OOP / 설계)

1. **sentinel value (0, -1) → 예외 전환** — sentinel 반환은 실패 원인을 감출 수 있으므로 Fail-Fast 방식으로 드러낸다. boogi-woogi/28 및 ki960213/52의 오류 분류와도 연결된다.

2. **Activity → 도메인 `Game` 분리** — 돌 두기와 턴 전환은 도메인 로직이므로 Android 의존성이 있는 `MainActivity`에서 분리하면 콘솔과 Android가 공통으로 사용할 수 있다. Junyoung-WON/103 및 Hogu59/97에서도 관련 설계 대안을 확인할 수 있다.

3. **MVC의 책임 경계** — 화면 이벤트를 받는 Activity와 게임 규칙·턴 진행을 맡는 Game을 분리한다.

4. **`validate` 추상 동사 모호함** — 함수명에 검증 대상과 조건을 드러낸다. 예: `verifyTurnOrder`, `requireExpectedColor`, `assertCurrentPlayer`.

5. **방어적 보류와 YAGNI** — 호출되지 않는 함수는 미래 사용 가능성만으로 유지하지 말고, 현재 요구사항과 확장 시나리오를 기준으로 판단한다.

6. **`onPause()`와 게임 상태** — Activity가 일시 중단되는 시점과 사용자가 게임을 리셋하는 동작은 다르므로, `onPause()`에서 저장 데이터를 삭제하지 않는다.

## 도메인 특수 어휘 (3·4단계 = Android + SQLite)

- **0 sentinel → 예외 전환**: 예상하지 못한 0을 반환해 실패 원인을 감추지 말고 예외로 드러낸다.
- **MainActivity → 도메인 `Game` 분리**: 게임 진행과 턴 전환을 Android 의존 화면 코드와 분리한다.
- **`validate` 명명**: 검증 대상과 조건을 이름에 드러낸다.
- **`onPause()`**: Activity 중단과 게임 초기화를 구별하고 저장 데이터를 보존한다.
- **`currentPlayer`**: 읽기 전용 접근이 필요하면 `val` 또는 조회 메서드로 노출하고, 상태 변경은 Game이 관리한다.
