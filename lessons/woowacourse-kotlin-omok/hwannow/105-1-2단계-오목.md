→ **인사이트** (블랙잭 INSIGHTS 10 *모호한 이름* + `signature-name-mismatch` 룰): *canPlace* = *영어 직관: "둘 수 있는가?"* = *Boolean 반환 기대*. 실제 Unit 반환 + 내부 throw → *호출자 시그니처 불일치 + 예외 흐름 추적 비용*. 호두/68 *playOmok(): Boolean* (의미 빈약) 의 *반대편 변주* — 의미는 명확한데 *반환이 그 의미를 깸*.

`signature-name-mismatch` MCP 룰 후보의 11+ 사례 누적 + 환노 측 *canPlace* evidence 추가.

## 얻은 교훈 (OOP / 설계)

### 1. Adapter로 외부 라이브러리 의존성 격리

`Player`가 외부 라이브러리의 `Rule` 타입을 직접 사용하면 도메인 모델이 해당 라이브러리에 결합된다. `Adapter`를 경계에 두면 외부 규칙과 게임 도메인의 인터페이스 사이에서 타입과 책임을 변환할 수 있다.

### 2. *플랫폼 이식 시나리오*가 *자료구조 정당성 검증* — 콘솔→앱 진화

환노의 *2중 리스트 정당성 (출력 가공 X, O(1) 접근)* 두 가지 중 *콘솔 어휘 (출력 가공)* 가 *앱 이식 후 사라짐*. 크롱의 *"콘솔이 아닌 앱 또는 웹"* 질문 = *플랫폼 변경 시나리오 = 자료구조 정당화 도구*.

자료구조 선택은 콘솔 출력 편의 외에도 앱이나 웹으로 옮길 때의 접근 패턴과 성능 요구를 고려해 검토한다.

### 3. Listener 도입 여부와 의존 방향은 별도로 검토

`Listener`는 콜백을 모으는 인터페이스일 뿐 의존성 방향을 바꾸지는 않는다. `OmokGame`이 `View`를 직접 참조한다면 함수형 콜백으로 바꾸더라도 UI와 도메인의 결합은 남는다. 필요한 경우 도메인 이벤트를 UI가 구독하도록 경계를 둔다.

### 6. 라이브러리 강결합 진단 = 3 단계 — Player.rule + Player.stones + Adapter 도입

환노의 라이브러리 결합 자가 진단:
1. **Player.rule** — 플레이어가 룰 보유? (현실: 플레이어는 룰을 *따름*, 보유 X)
2. **Player.stones** — 플레이어가 자기 돌 리스트 보유? (현실: 보드가 돌의 위치를 가짐, 플레이어는 *둠*)
3. **WhiteRule/BlackRule 직접 사용** — 도메인이 라이브러리 어휘 직접 사용

→ 세 결합이 *Player 객체 자체의 존재 이유 (라이브러리 활용)* 에 연결. 환노의 *Player 폐기 + Stones를 Grid 로 이동 + Adapter 도입* = 세 결합 함께 해소. *현실 메타포 검증* (크롱의 *눈 가린 기억*) 이 *책임 위치 결정 도구*.

크롱 (PR body):

> *"지금까지 작성한 코드들이 안드로이드로 옮겨갈 때 어떻게 변경되는가에 초점을 맞춰서 진행해보면 많은 도움이 될 것 같아요."*

Android로 옮길 가능성이 있는 구조 변경은 미리 고려할 수 있지만, 지금 단계에서 복잡성을 늘리지 않고 이식 후 확인하는 선택도 가능하다.

## 도메인 특수 어휘 (1·2단계 환노 한정)

- **Adapter 패턴**: 외부 라이브러리의 규칙 타입과 도메인 인터페이스 사이를 변환.
- **OmokRuleAdapter (추상 클래스)**: 추상화 형태만 적용, 활용 측은 여전히 렌주룰 직접 결합.
- **Referee**: 심판 = 룰 적용자. 다른 룰 = 다른 심판 결합 어휘.
- **OmokViolation.isError**: Boolean 잉여 필드 의문.
- **Player 폐기 + Stones → Grid 이동**: 라이브러리 결합 해소 동반 결정.
- **2중 리스트 → Set 자가 변경**: 콘솔→앱 이식 후 자료구조 정당성 재검증.
- **Listener**: 콜백 전달을 묶을 수 있지만, 도메인이 View에 직접 의존하는 문제까지 해결하지는 않는다.
- **canPlace Boolean 명명 불일치**: 영어 직관 vs Unit 반환 + 내부 throw.
- **retryInput util→domain → controller**: 입력 책임 위치 재배치.
- **15x15 도메인 진리**: 국제오목연맹 (renju.net) 외부 자료 인용.
- **`'A'..'O'` 같은 표기 어휘**: PR #105 에서는 등장 X — 환노는 *원시 좌표* 그대로 사용.
