### 2. lateinit vs by lazy 학생 자가 학습 narrate

둘리 (MainActivity.kt #2021259349):

> *"`lateinit var`와 `by lazy`의 차이점은 무엇일까요? `lateinit var`를 사용했을 때 주의해야할 점이 무엇일까요?"*

포르 답 (자가 학습):

> *"`lateinit`과 `by lazy`는 값을 나중에 초기화한다는 공통점이 있습니다.*
>
> *`lateinit`은 `var` 에서만 사용할 수 있으며, 변수의 값을 별도의 시점에서 초기화할 수 있습니다.*
> *`by lazy`는 `val` 에서만 사용할 수 있으며, 변수를 처음 호출하는 시점에 초기화됩니다.*
>
> *`lateinit var`의 경우, 기본 타입에는 사용할 수 없으며 초기화 전에 접근하면 예외가 발생하므로 주의해야 합니다.*
>
> *`DbHelper`는 나중에 초기화할 필요가 없다고 판단하여 바로 초기화하도록 변경했습니다!*

```kotlin
private val dbHelper: DbHelper = DbHelper(this)
```



**시즌 종료 시점 = 2년 어휘 일관성 검증 자리** — HANDOVER §16 *vagabond95 "굳이" 어휘의 2년 전 시드 (ippnsj) → Hevton/88 학생 자가* 의 *세 번째 학생 (포르)* 시점 정착.

→ **인사이트** (블랙잭 INSIGHTS 1 — Tell-Don't-Ask): 포르의 *"외부에서는 내부 상태와 관계없이 finish 함수를 호출하는 것이 바람직"* 어휘가 **Tell-Don't-Ask 학생 자가 narrate 정점**. *외부 (Activity)* 가 *내부 상태 (Finished)* 묻고 분기 → *내부 상태 노출 + 외부 책임 폭증*. *finish 안에서 자기 상태 확인 + 행동* = *호출자 책임 없음*.

호두/103 *Tell-Don't-Ask 학생 자가 narrate* (블랙잭 #101 결의 *실제 학생*) 의 *시즌 종료 시점 변주*. 말리빈 (2chang5/22) *"객체에게 메시지를 던져 결과를 받아오는"* 어휘의 *학생 자가 응용*.

블랙잭 INSIGHTS 1 의 *시즌 종료 시점 정착 확인*. MCP 룰 후보 `change-frequency-reduction-design` 의 *호출자 책임 줄이기 변주*.
