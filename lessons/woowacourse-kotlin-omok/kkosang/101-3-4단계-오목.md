### 2. Direction enum 2단 계층 — DirectionVector 분리 (코드 예시 직접 동반)

> *"제가 생각한 느낌은 이런 느낌이었어요! 너무 어렵게 고민하게 만든 것 같아 죄송한 마음이네요 😅*
>
> *```kotlin*
> *enum class Direction(*
>     *val directionVectors: List<DirectionVector>,*
> *) {*
>     *HORIZONTAL(listOf(DirectionVector.LEFT, DirectionVector.RIGHT)), ~~~*
> *}*
>
> *enum class DirectionVector(*
>     *val dx: Int,*
>     *val dy: Int,*

→ **인사이트** (블랙잭 INSIGHTS 3 — State sealed + 예니/83 *GameResult 2단 계층* 결의 *방향 변주*): *Direction* = *분류 어휘* (HORIZONTAL, VERTICAL, DIAGONAL) + *DirectionVector* = *구체 벡터 (dx, dy)* 의 *2단 계층*. 각 *분류 (Direction)* 가 *여러 벡터 (DirectionVector List)* 를 보유 — *HORIZONTAL = LEFT + RIGHT*.

*1단 평탄 enum* (UP_LEFT, UP, UP_RIGHT, ...) 8 케이스 → *DirectionVector* 만으로 표현 가능. *2단 계층* = *Direction (분류)* 를 *DirectionVector* 위에 또 한 층. 룰 검증 시 *같은 방향 (HORIZONTAL) 의 두 벡터 (LEFT, RIGHT)* 가 *한 묶음* 으로 처리.

말리빈의 *"너무 어렵게 고민하게 만든 것 같아 죄송한 마음이네요"* 어휘가 *코드 예시 직접 동반의 정당화* — *짧은 질문으로 도달 어려운 깊이* 면 *코드 예시 직접 동반*. 라코의 *suggestion 블록 직접 코드* (호두/68 어댑터 lifecycle) 와 *같은 결의 말리빈 측 변주*.
