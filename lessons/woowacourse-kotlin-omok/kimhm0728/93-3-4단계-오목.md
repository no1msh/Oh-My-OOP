### 1. OmokGame 내부 Dao 생성자 — 도메인 로직? (Thread 2, 학생 자가 책임 한계 자가 자각)

reviewer:

> *"과연 OmokGame 내부에서 Dao를 생성자로 받아서 저장을 해주는게 맞는지 라는 의문이 생깁니다 🥲 Omok게임을 저장하는것이 도메인 로직일까요?? 🤔 해당 내용은 Android 전용이니, Activitiy로 뽑아보는 것은 어떨까요?"*

학생 자가 답변 (Thread 12):

> *"데이터를 저장하는 코드는 액티비티에만 존재하는 것이 맞는 것 같습니다! 수정했습니다."*

→ **인사이트**: *영속화 = 도메인 책임 X*. OmokGame 은 *도메인 진행 책임만*. *DB 저장 = Activity (외부 계층) 책임*. chanho0908 #132 (*도메인이 외부 의존성 자가 자각*) 결. INSIGHTS.md 인사이트 7 (의존 방향) 의 영속화 변형.

### 2. DB 매 턴 vs 앱 종료 저장 — 4안 학생 자가 정리 (Thread 8, 15)

reviewer 의문:

> *"매턴마다 클릭시에 DB에 저장하는 것이 아니라, 앱 종료시에 저장을 해보도록 하는 것은 어떨까 라는 생각이 듭니다 🤔"*

학생 자가 4안 정리:

> *"현재는 `앱을 나가지 않고 게임을 여러번 수행`하는 경우, DB에 저장하지 않아도 되는데도 매번 DB에 저장하기 때문에 이에 대한 오버헤드가 발생할 것 같습니다."*

> *"그런데 \"앱 종료시에 DB에 접근하여 저장\"하게 된다면, 액티비티에서 저장할 데이터들을 관리해야 합니다. 현재 미션에서 액티비티는 컨트롤러의 역할이기 때문에, 뷰랑 모델을 연결하는 역할만 수행해야 한다고 생각합니다. 그런데 액티비티에서 DB에 저장할 데이터들을 관리한다면, **`액티비티가 DB 로직을 너무 많이 알고 있는 것이 아닌가?`**라는 생각이 들기도 하네요."*

> *"일단 여러 방식으로 구현해보고 싶어서, `onDestroy()`에서 데이터를 저장하는 방식으로 수정해 보았습니다...!! 두루는 어떻게 생각하시는지 궁금합니다!"*

→ **인사이트 (정점)**: 학생 자가 *4안 트레이드오프 정리* + *액티비티 책임 한계 자가 자각*. 영속화 시점 = 단일 답 없음:
- (a) 매 턴 저장 — 오버헤드, 단순
- (b) 앱 종료 시 — 액티비티가 데이터 관리 = 책임 폭증
- (c) Repository 패턴 + 트랜잭션 — 가장 복잡
- (d) `onSaveInstanceState` Android 어휘

블랙잭 #97 학생 자가 *4안 비교 + 의견 요청* 결.

## 얻은 교훈 (OOP / 설계)

### 1. 역할 겹침 = 통합 후보

`omokDataStore` 가 `omokDao` 를 보유하면 *DataStore 가 Dao 추상*. Activity 가 둘 다 보유 = 어색함. *상위 추상화 단일 보유* 가 자연.

### 2. 영속화 = 도메인 책임 X

OmokGame 이 *DB 저장* 책임 가짐 = 의존 방향 위반. *Activity (외부 계층) 책임*. INSIGHTS.md 인사이트 7 + chanho0908 #132 결.

### 3. Activity 비즈니스 flag = god-object 신호

*게임 종료 여부* 같은 도메인 상태가 *Activity flag* 에 있으면 *Activity 비즈니스 책임 흡수*. 도메인 객체로 이동. INSIGHTS.md 인사이트 3 결.

### 4. 영속화 시점 = 단일 답 없음

매 턴 vs 앱 종료 vs Repository 트랜잭션 vs `onSaveInstanceState` — 4안 트레이드오프. 미션 컨텍스트에서는 *기능 요구사항*과 *오버헤드*의 균형.

### 5. lateinit var = 호출 순서 invariant 부재

Android Activity 생명주기 + lateinit = *초기화 시점 모호*. `by lazy` 또는 *생성자 주입 (가능한 경우)* 안전.

### 6. 분리 비용 > 단일 유지 비용 — 분리 결정 트레이드오프

*모든 분리가 정답 X*. *분리 비용 > 가독성 비용* 이면 단일 유지. 단일 답 거부.

### 7. 명명 = 맥락 변경 시 갱신

`Application.kt` 가 *Console + Android* 분기 시 `ConsoleOmok` 으로 명명 회복. 함수명-동작 일관성 + 패키지 명명 = *분리 의도 드러냄*.

### 8. 학생 자가 책임 한계 자가 자각 = 학습 정점

*"~~ 가 ~~ 를 너무 많이 알고 있는 것이 아닌가?"* 어휘는 INSIGHTS.md 메타 M4 (어색함 분리 신호) 의 학생 측 자가 narrate.
