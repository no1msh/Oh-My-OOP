### 1. *외부 상태 변경 = 의도된 방향이면 OK* — 제리의 자율 객체 정의 어휘

채채의 PR body 질문 (GameState):

> *"GameState(val board: Board) -> private 로 board를 제어하는 법? 현재 board를 외부에서 접근한다면 변경이 될 거 같은데요! 깊은 복사를 활용하거나 GameState에서 private val Board를 사용하는 방법까지는 고민해보았는데, 어떤 것이 더 나은 방법일까요?"*

제리 답:

> *"외부에 의해 상태가 변경 되는 것 자체는 나쁜 것이 아니며 피하기 어렵다고 생각해요. 중요한건, '내가 의도한 방향대로 상태가 변경되는 것인지 아니면 내가 의도하지 않은 방향으로도 변경이 가능한지' 일 것 같습니다."*

> *"한가지 예를 들어보면 board 의 placeStone 함수는 board 의 상태를 변경시키지만 의도한 방향으므로 괜찮습니다. 하지만, layout 의 경우 외부에서 set 이 가능하고 이것이 의도한 방향이라고 보기는 어려우므로 리펙토링의 여지가 있는 코드라고 볼 수 있겠죠 :)"*

→ **인사이트** (블랙잭 INSIGHTS 1 — Tell-Don't-Ask 의 *의도된 변경 어휘*): 채채는 *외부 접근 = 변경 위험* 으로 *깊은 복사 / private* 두 안 비교. 제리는 *불변성 자체가 목표 X* 임을 명시 — *의도된 방향의 외부 변경*은 *문제 없음*. 진짜 신호는 *의도 외의 경로로 변경 가능한가*.

- **`board.placeStone(stone)`**: 외부 호출이지만 *돌을 둔다*는 *의도된 동작* — OK
- **`board.layout = X`**: 외부 setter — *layout 외부 갈아끼움*은 *의도 외* — 리팩터링 대상

블랙잭 INSIGHTS 메타 M2 (*그저 좋다 함정*) — *모든 외부 변경 회피 = 불변 강박* 의 회피.

### 2. placeStone 의 *GameState 반환 = 일관성 함정* 자가 자각

제리 (GameState.kt line=73):

> *"placeStone 은 말그대로 돌을 놓는 행위를 했을 때, 의미가 있는 함수라고 생각해요. GameState 를 그대로 리턴한다면, API 를 사용하는 입장에서는 일관된 구현이 아니라 혼동을 느낄 수 있을 것 같습니다. 이 부분을 어떻게 개선해볼 수 있을까요?"*

채채:

> *"placeStone은 돌을 놓는 행위에 집중하고, 상태를 반환하는 것은 다른 책임으로 분리하는 것이 가독성과 클라이언트측면에서 옳다는 생각이 들게 되었습니다! '돌을 놓으니 다음 차례다' 라고 전달하는 것보다 이 로직을 분리하는 것이 단일 책임에 더 집중할 수 있고 게임 상태의 일관된 관리와 명확한 API를 제공할 수 있을 거 같습니다!"*

→ **인사이트** (블랙잭 INSIGHTS 10 + 메타 M4 — *명명 ↔ 시그니처 일치의 반환 변주*): `placeStone(): GameState` = *돌을 둔다 + 다음 상태를 알려준다* 두 책임이 *반환 타입에 노출*. 단일 책임 분리:
- `placeStone(point)` = *명령* (반환 없음)
- `nextState()` 또는 별 함수 = *질의* (현재 상태 반환)

m6z1/139 의 *checkPutState* → `putState 반환 + putStone(position) 명령` 분리와 *같은 결의 채채 측 사전 도달* — 뭉치보다 1년 전 PR (2024-03) 에서 같은 CQS 어휘를 *제리 측에서 시드*.

라코의 *행동 초점 명명* (뭉치 #139) ↔ 제리의 *클라이언트 측 일관성 어휘* — 두 reviewer 의 *명명 일관성*에 대한 *다른 진입점*. 라코 = *시그니처가 무엇을 약속하는가*, 제리 = *클라이언트가 어떻게 인지하는가*.

**MCP 룰 후보 `command-query-separation-naming`** 의 *2024 시즌 시드* — 코퍼스 시간성 양극 어휘 일관성.

## 도메인 특수 어휘 (1·2단계 채채 + 책 어휘 학습 시드)

- **BlackStoneOmokRule (library 모듈)**: 외부 라이브러리 가정 → PositionType 결합 자가 의문.
- **GameState (sealed interface) — Running (Black/White) + Finish**: 상태 패턴 + Running 공용 처리 시드.
- **Coordinate (from "A1" + Coordinate(row, col))**: 두 진입점 = 중복 검증 (요구사항 변경 시 누락).
- **OmokRule (상태 보유 → object + board 파라미터)**: 순수 함수 어휘.
- **BoardInterface = 다형성 활용 X = 인터페이스 도입 부당**.
- **GameManager → Model 패키지**: M/V/C 자가 분류.
- **이중 컬렉션 (Array<Array<PositionType>>) → 별 클래스**: 일급 컬렉션 캡슐화의 2D 변주.
- **onShow → onPosition**: View 의존 어휘 회피 (이름의 출신지).
- **엘레강트 오브젝트 책 어휘 (모든 public 인터페이스)**: 무비판 적용 → 의문 → 토론 → 자가 기준 시드.
