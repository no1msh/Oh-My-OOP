### 2. Dfs 4 객체로 8 방향 요약 — 알고리즘 추상화 어휘 정점

```kotlin
sealed class Dfs(...) {
    abstract fun search(...): Int
}

class AscendingDfs(...) : Dfs(...)   // ↗ + ↙
class DescendingDfs(...) : Dfs(...)  // ↘ + ↖
class HorizontalDfs(...) : Dfs(...)  // → + ←
class VerticalDfs(...) : Dfs(...)    // ↑ + ↓
```

파이로 (AscendingDfs.kt):

> *"이것은 제가 감탄을 한 부분인데, Board 탐색의 핵심이 되는 Dfs 알고리즘은 정말 깔끔하게 잘 구현해주신 것 같습니다. 👍 💯 Dfs 안에 search 를 추상 함수로 선언해서, AscendingDfs, DescendingDfs, HorizontalDfs, VerticalDfs 4가지로 구현해주신 것 또한 아주 멋지다고 생각했습니다. 8방향이라고 생각할 수 있음에도 4개의 객체로 요약되는 것 또한 아주 멋지네요. 네이밍도 직관적이라서, search 내부의 객체명만 보고서 무엇을 하는 객체인지 바로 알 수 있었습니다."*

→ **인사이트** (블랙잭 INSIGHTS 3 — State sealed 의 *알고리즘 측 변주*): *8 방향 (상하좌우+대각4) → 4 객체* 의 *대칭쌍 흡수*. *↗ 방향 탐색* = *시작점에서 ↗ 끝까지 + 시작점에서 ↙ 끝까지* — *한 방향 탐색 = 양쪽 끝까지 = 두 끝점의 합*. *2 끝점 1 방향* 이 *대칭쌍 흡수의 단위*.

*Dfs sealed class* + *4 구현체* = *알고리즘 = 추상, 방향 = 구현* 의 *분리*. *search* 추상 함수 + *각 구현체의 방향별 좌표 변환* — *알고리즘 본체 (방문 + 카운트 + 재귀)* 와 *방향 정보 (dx, dy)* 의 *책임 분리*.

다만 PR #64 (kmkim2689 + 말리빈) 의 *옆 동료 개발자가 Dfs 를 즉시 추측 가능?* 어휘와 *대비* — 두 reviewer 의 *같은 코드 구조에 다른 어휘*. 파이로 = *알고리즘 추상화 칭찬*, 말리빈 = *외부자 인지 비용 우려*. *우테코 reviewer 어휘 스타일의 정형 차이* — 같은 코드를 *추상화의 미덕* 으로 보는가 *명명의 도메인 어휘 거리* 로 보는가.

### 1. checkOpenThree 시그니처 ↔ 함수명 불일치

```kotlin
// ArkThreeThreeRule.kt 안
fun checkOpenThree(...): Int { ... }   // Int 반환
fun countOpenThrees(...): Int { ... }  // 같은 패턴, 다른 명명
```

파이로:

> *"여기도 when 내부에 굉장히 많은 연속된 조건들이 있습니다. `checkOpenThree` 라는 함수명으로 로직의 의도를 파악해야하는데, `countOpenThrees` 는 리턴 타입이 Int 라는게 예상되지만, `checkOpenThree` 는 함수명만 보면 리턴 타입이 Boolean 같아서 더 헷갈렸습니다."*

→ **인사이트** (블랙잭 INSIGHTS 10 — 가상 객체 / 모호한 이름의 *동사 측 변주*): 영어 동사 *check* 의 *시그니처 인상*:

- *check* = *확인하다* — *Boolean 반환* 인상
- *count* = *세다* — *Int 반환* 인상

블랙잭 INSIGHTS 7 (도메인 vs 표현 분리) 의 *외부 라이브러리 측 변주 정점*. *변경 시나리오 = 라이브러리 버전업 / 다른 라이브러리 교체* 의 *외부 변경 시나리오* — 파이로 추가 권고 (ArkRule 인터페이스화) 가 *교체 가능성 측 추상화*.

### 2. null 회피 = 안드로이드 크래시 + 비즈니스 로직 분리

파이로의 *null 위치 정의* — *null = 예외상황 / null 핵심 사용 = 비즈니스 로직 위험*. *Color? 빈 자리* → *Color.NONE 제 3 sentinel* / *GameResult? winner* → *GameResult.IN_PROGRESS enum 추가*.

- **null = 예외상황 표현**: 진짜 예상치 못한 미초기화, 외부 API 실패
- **enum/sealed = 비즈니스 상태**: 게임 진행 중, 빈 자리, 미정 결과

말리빈 (kmkim2689/64) 의 *sealed 권고* + 파이로 (songpink/65) 의 *enum 권고* 가 *2 reviewer 일관 어휘*. 호두 (Junyoung-WON/68) 의 *StoneState enum 자가 도달* 과 *학생 자가 도달 ↔ reviewer 사전 권고* 의 *두 양면*.

블랙잭 INSIGHTS 1 + 3 (Tell-Don't-Ask + State sealed) 의 *반환 측 변주 정점*.

### 3. 변경 시나리오 = *학습 우선순위 + 미래 가치 호혜*

파이로의 *미션 요구사항 외 면제 + 실무 경험담* 어휘:
- *미션 요구사항* = *현재 학습 범위* — 강제 반영 X
- *실무 경험담* = *미래 학습 자원* — 미리 알아두면 유익

라코 (Junyoung-WON/68 + Hevton/57) 의 *학습 단계 외 주제 명시 회피* (*코루틴 = 레벨1 외*) 어휘와 *대비*. 라코 = *해당 학습 단계 외 = 피드백 자체 보류*, 파이로 = *현재 학습 외 = 권고 + 적용 자유 + 미래 가치 명시*.

### 4. 객체지향 생활체조 *표면 vs 본질 분리*

파이로의 *else 예약어 = else 키워드 X / 조건 3 연속 X 가 본질* 어휘 = *원칙 = 표면 텍스트 vs 본질 의도* 의 *어휘 단위 정의*.

→ *원칙 학습의 두 층*:
- **표면 적용**: 텍스트 그대로 — *else 키워드 안 쓰기*
- **본질 적용**: 의도 따라 — *조건 흐름 단순화 (다형성/sealed/맵)*

*표면 적용* 만으로 *if-else if-else if-else* 같은 *4 분기*는 회피되지 않는다 (*else 1 회만 있어도 조건 4 연속*). *본질 적용* 으로 *if 자체 3 연속 회피* — *다형성 (sealed), Map lookup, 함수 분리*.

블랙잭 INSIGHTS 메타 M1 (학생 자가 학습) 의 *원칙 정의 학습 변주*.

### 5. 알고리즘 추상화 어휘 — 8 방향 → 4 객체 = 대칭쌍 흡수

*Dfs sealed class + 4 구현체 (Ascending / Descending / Horizontal / Vertical)* = *대칭 방향 (↗↙ / ↘↖ / →← / ↑↓)* 의 *쌍 단위 흡수*. *한 방향 탐색 = 양쪽 끝까지 + 두 끝점의 합* — *2 끝점 1 방향* 이 *대칭 쌍 흡수의 단위*.

```
8 방향 → 4 대칭 쌍:
  ↗↙ (AscendingDfs)
  ↘↖ (DescendingDfs)
  →← (HorizontalDfs)
  ↑↓ (VerticalDfs)
```

→ *알고리즘 = 추상, 방향 = 구현* 의 *책임 분리*. sealed class 안 *search 추상 함수* + *각 구현체의 dx, dy 좌표 변환* = *알고리즘 본체 (방문 + 카운트 + 재귀)* 와 *방향 정보 (dx, dy)* 의 *분리*.

블랙잭 INSIGHTS 3 (State sealed) 의 *알고리즘 측 변주 — 상태 분기 X, 방향 분기 O*. *State 패턴이 아닌 Strategy 패턴* 의 *sealed 변주* — *4 객체 = 4 전략*.

### 6. *알고리즘 어휘 vs 도메인 어휘 명명 — 두 reviewer 상반된 시각*

파이로 (songpink/65): *Dfs 4 객체 = 알고리즘 추상화 우수 사례 칭찬*
말리빈 (kmkim2689/64): *Dfs = 옆 동료 인수인계 시 추측 비용 우려*

→ *같은 코드 구조* 에 *두 reviewer 어휘 상반*. 두 시각 모두 정당하지만 *명명 = 도메인 어휘 측 vs 알고리즘 어휘 측* 의 *trade-off*. *오목 도메인 어휘* 로 옮기면 *DiagonalUpChecker / DiagonalDownChecker / RowChecker / ColumnChecker* — *방향 정보 + 동작 (Checker)* 가 *도메인 어휘로 박힘*. *Dfs* 는 *내부 구현 어휘* 로 *private 또는 패키지 안 보조 클래스*.

블랙잭 INSIGHTS 10 (가상 객체 / 모호한 이름) 의 *알고리즘 어휘 측 변주 정점* — 두 reviewer 어휘 상반이 *학생 학습 자원의 다양성*.
