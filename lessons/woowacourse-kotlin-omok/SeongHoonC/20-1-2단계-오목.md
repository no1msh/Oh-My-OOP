### 1. 상태 패턴 도입 — `State` interface + `Turn` / `End` 구분

```kotlin
// State.kt
interface State {
    val stone: Stone
    val board: Board
    fun place(location: Location): State
}

// Turn.kt
abstract class Turn(override val board: Board) : State {
    override fun place(location: Location): State {
        if (isForbidden(location)) return this
        board.placeStone(location, stone)
        if (isOmok(location)) return End(board, stone)
        return nextTurn()
    }
    abstract fun isForbidden(location: Location): Boolean
}

// End.kt
class End(override val board: Board, override val stone: Stone) : State {
    override fun place(location: Location): State {
        throw IllegalStateException("")
    }
}
```

### 4. `OmokGame.playNextTurn` — 함수 매개로 좌표 입력 위임

```kotlin
// OmokGame.kt
class OmokGame {
    fun playNextTurn(state: State, getDot: (Stone) -> Dot): State {
        val location: Location = getLocation(state, getDot)
        if (state.board.canPlace(location)) return state.place(location)
        return state
    }

    private fun getLocation(state: State, getDot: (Stone) -> Dot): Location = runCatching {
        val dot = getDot(state.stone)
        Location(Coordination.from(dot.row), Coordination.from(dot.col))
    }.getOrNull() ?: getLocation(state, getDot)
}
```

→ **인사이트** (블랙잭 INSIGHTS 2 — 역할 vs 책임 분리의 *함수 전달 변주*): *도메인 (`OmokGame`) 이 좌표 입력 출처 (`View`) 를 직접 의존하지 않고* *함수 시그니처 `(Stone) -> Dot`* 로 *의존을 추상화*. *Tell-Don't-Ask 결* — *어디에서 가져왔는지 묻지 않고* *받은 함수에 메시지를 던진다*.

DYGames/39 의 *Observer 패턴 vs 함수 전달 동등 안* (vagabond95) 어휘 + Hevton/57 의 *고차함수 vs interface 두 안 자가 비교* 어휘와 *같은 결*. 베르는 1·2단계 (콘솔) 에서 이미 *고차함수 패턴*을 채택 — *MCP 룰 후보 `higher-order-fn-vs-interface-collaboration`* 인용 가능.

다만 *runCatching + getOrNull() 재귀 호출* 부분은 *예외 회피의 무한 재귀 변주* — *호두/68 의 예외 → 상태 반환* 어휘와 다른 결 (호두는 *상태 자체로 표현*, 베르는 *재귀로 무한 재시도*). 호두 결의 *더 가벼운 어휘*.

## 얻은 교훈 (OOP / 설계)

### 1. 상태 패턴 도입의 *적정선 검증 의무*

베르는 *상태 패턴을 도입* 했지만 *Omok/Turn/RetryTurn/BlackTurn 4겹 위계* 로 *세분화 과잉*에 도달. 호두/68 의 *상태 패턴 도전 → enum 절제* 결의 *대비쌍*. 두 학생이 같은 *상태 표현* 문제를 *각각 도입과 절제로* 다르게 풀었다.

→ *상태 패턴 채택 = 책임 끝* 이 아니라 *상태 세분화의 적정선 검증 의무 시작*. 레아의 *"4 값 = 4 의존"* 어휘가 *위계 폭증 신호*의 정점.

### 2. *값 보유 = 의존* — Wirfs-Brock 식 책임 분배 어휘

레아의 *"4개의 값을 들고 있다는 것은 결국 4개의 값 각각에 의존한다는 의미입니다"* 어휘가 *책임 위치 어휘* 의 핵심 정점. *객체가 어떤 값을 보유한다 = 그 값의 변경에 노출된다*. 호두/68 의 *Column 'A'..'O' 보유 → View 어휘에 도메인이 묶임* 결의 *레아 측 변주*.

블랙잭 INSIGHTS 6 (한 데이터 두 책임) 의 *값 보유 차원 변주* — *한 객체가 N 값 보유 = 그 객체가 N 변경 영향 영역*. 분리 신호.

### 3. Boolean 시그니처 의미 빈약 — 호두/68 결의 베르 측 누적 사례

### 4. Pair / MutableMap / Mutable 컬렉션 — *Kotlin 자료구조 의미 빈약 누적*

`Pair<Int, Int>` + `Map<Int, MutableList<Stone>>` + `MutableMap` 생성자 = *Kotlin 표준 자료구조를 도메인 어휘 없이 그대로 노출*. 베르의 1·2단계 = *Java 시절 자료구조 어휘를 Kotlin 어휘로 갈아엎는 학습 단계*.

## 도메인 특수 어휘 (1·2단계 베르 한정)

- **State / Turn / End**: 상태 패턴 — `Turn` (계속 진행) ↔ `End` (게임 종료) 분기. *4겹 위계 (RetryTurn/BlackTurn/WhiteTurn) → 단순화* 학습 토픽.
- **OmokForbiddenRuleAdapter**: 외부 `RenjuRule` 어댑터 + *OmokLongForbidden 싱글톤 별도 호출* (어댑터 + 싱글톤 혼재 → 클라이언트 가시화 부재).
- **OmokForbiddenRule** vs **OtherForbiddenRule** vs **OmokLongForbidden**: 룰 분리 3 종류 — *3-3, 4-4, 장목* 의 *각각 별도 클래스 표현*.
- **Coordination (value class, 0..14)**: `@JvmInline value class` + *NUMBERS 맵 플라이웨이트* + invariant. *0..14 (View 의 1..15 와 다른 도메인 좌표)*.
- **Dot vs Location**: `Dot` = *원시 (row, col)* + `Location(Coordination, Coordination)` = *invariant 보장 좌표*. *두 단계 변환* — 호두/68 의 *Column 도메인 어휘 1..15 / View A..O* 결의 *베르 측 변주*.
- **OmokGame.playNextTurn**: *상태 + 함수 매개* — 도메인이 View 함수에 직접 의존하지 않음. **MCP 룰 후보 `higher-order-fn-vs-interface-collaboration`** 사례.
- **`runCatching + getOrNull ?: getLocation(...)` 무한 재귀**: 예외 처리의 *재귀 변주* — 호두/68 의 *상태 반환* 결과 *대비*.
- **OmokController**: 절차지향 (`startGame / playOmokGame / stopGame`) — *상태 패턴의 의의 무시* 어휘.
- **BOARD_SIZE = 15**: Controller companion object 보유 — *Board 가 아닌 Controller 가 보유* 어색함.
- **Stone enum {BLACK, WHITE, EMPTY}**: *돌* 도메인 어휘에 *빈 자리* 가 섞인 케이스 — DYGames/7 의 *Color sealed* 결의 *베르 측 미해결 토픽*.
- **OmokRule (object)**: `OmokRule.isOmok(board, location, stone)` 싱글톤 함수 호출 — *어댑터와 다른 어휘로 룰 호출* (Adapter vs Singleton 일관성 어휘 — 레아의 *3 단계 질문*).
