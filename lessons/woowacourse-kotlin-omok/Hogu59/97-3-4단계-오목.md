private fun putStone(stone: Stone, view: ImageView, board: TableLayout) {
    view.setImageResource(imageResource(stone))

    if (placeable(stone)) {
        putStone(stone, view)
    } else {

private fun placeable(stone: Stone): Boolean =

private fun putStone(stone: Stone, view: ImageView) {

라코의 *"단순히 코드가 길어질 것 같으니 분리가 된 것 처럼"* 어휘는 *분리의 이유* 가 *길이 회피* 가 아니라 *책임 분리* 임을 짚어줌. *함수 분리 = 책임 어휘 표현* 이어야 함.

### 3. *15 매직넘버 → Point.index()* 도메인 이동

라코 (MainActivity.kt):

> *"`row + 15 + col` 에서 어떻게 15라는 값을 액티비티(컨트롤러)가 알고 있는 것일까요?"*

악어:

> *"해당 내용 `Point` 도메인으로 옮겨두었습니다!"*

```kotlin
data class Point(val row: Int, val col: Int) {
    fun index(): Int = row * 15 + col

    companion object {
        fun from(index: Int): Point {
            return Point(row = index / 15, col = index % 15)
        }
    }
}
```

→ **인사이트** (블랙잭 INSIGHTS 7 — 도메인 vs 표현 분리의 *Android 변주 정점*): *Activity = TableLayout 의 자식들을 한 줄 인덱스로 접근* 해야 함 (`getChildAt(index)`). *변환 책임 (Point ↔ index)* 이 *Activity 에 누설* 되면 *Activity 가 보드 크기 15 를 안다* — 변경 시 Activity 도 수정.

*Point.index() + Point.from(index)* = *변환 책임을 도메인 값 객체* 가 *자기 자신* 으로 가짐. *Activity = 결과 인덱스 사용만*. **다만 15 가 여전히 Point 안에 매직 넘버** — Board.size 를 *생성자 주입* 받아 *Point(row, col, size)* 또는 *PointFactory* 로 좁히는 *추가 정제* 여지.

PR #77 의 *"OutputView 가 보드 크기 15 하드코딩"* 의 *Android 측 동형 변주* — *콘솔 = OutputView 가 15 보유* / *Android = MainActivity 가 15 보유*. 같은 결합이 *플랫폼 두 곳* 모두에 나타남.

### 4. *게임 종료 후 흐름 — 3 안 흐름* 라코 정점 어휘

라코 (MainActivity.kt):

> *"오목이 완성된 이후에 바로 내용이 모두 삭제되면, 육안상으로는 오목이 맞았는지에 확인을 할 수 없는 상태입니다.*
>
> *게임이 끝나면 왜 바로 리셋을 하는 것인가요?*

> *3. 게임 다시시작 클릭 -> 게임 리셋"*


*Tell-Don't-Ask* 의 *상태 기반 분기* 어휘 — *게임이 자신의 상태 (진행/종료) 알고 그 상태별 행동 분기*. *외부 (사용자 클릭)* 가 *게임의 상태 모르고* *클릭 = place 시도* 만 하면, *게임이 자기 상태에 따라 처리*. INSIGHTS 1 의 *3 단계 분기 어휘*.

악어 자가 응답 (이전 PR 본문 → 못한 점에서 자가 인정):

> *"오목이 완성된 경우, 보드에 대한 입력을 아예 막고자 하는데, 구현이 조금 어려운 것 같습니다."*

→ *입력을 막는다* 어휘가 *no-op 처리* 와 *비활성화* 두 안을 혼동. 라코의 *no-op* 어휘가 *행동을 막는 것이 아니라 행동의 결과를 무효화* 의 정확한 어휘.

### 2. findViewById 비용 — 매 호출 순회

라코 (MainActivity.kt):

> *"안드로이드에서 가장 무거운 동작 중 하나는 findViewById 입니다.*
> *함수가 호출될 때 마다 반복해서 순회를 하고 있는데 어떻게 개선 할 수 있을까요?"*

라코 후속:

> *"TableLayout 같은 라이프사이클동안 변하지 않는 값은 클래스 레벨의 필드로 값을 가지는 방법이 있습니다."*

악어:

> *"가급적 모든 것을 넘겨 받는게 좋다고 생각했었는데, 변동 없는 객체(값)에 대해서는 그렇게 사용할수도 있겠군요!"*
