## 못한 점 (설계 관점)

### 1. Finished — placeStone 무용 구현 (Thread 3)

```kotlin
class Finished(...) : Turn() {
    override fun placeStone(point: Point): Turn {
        throw IllegalStateException("...")    // 무용 구현
    }
}
```

reviewer:

> *"Turn 의 역할을 어디까지 정의하느냐에 따라 다르겠지만, turn 의 핵심 함수는 placeStone 이라고 생각되는데요! 해당 함수가 무용한 구현체라면, 해당 구현체가 Turn 인터페이스를 구현하는것이 적합한 도메인인지 고민해볼 필요가 있을 것 같아요."*

학생 자가 답변:

> *"올바르지 않은 상태라는 예외를 던짐으로써 개발자에게 문제 상황을 알려줄 수 있다고 생각했습니다!"*

→ **인사이트**: *인터페이스 구현체가 핵심 메서드 무용화* = *LSP (Liskov 치환 원칙) 위반 신호*. *Finished 는 Turn 인가, 아니면 별개 상태인가* 재검토. *sealed class Turn { ... }* + `Finished` 별도 종료 상태로 분리하는 방식이 자연.

INSIGHTS.md 인사이트 3 도입 직후 함정 (*if state is Bust* 잔재) 결.

## 얻은 교훈 (OOP / 설계)

### 1. 예외의 두 청중 — 개발자 + 사용자

단일 예외 타입(IllegalArgumentException) = *개발자 디버깅 + 사용자 UX 메시지* 두 채널 손실. *명시적 예외 계층 (sealed)* + *사용자 메시지 분리*. chanho0908 #132 (sealed Exception 계층) 결.

### 2. LSP 위반 — 핵심 메서드 무용 구현 = 인터페이스 부적합

`Finished.placeStone()` 이 예외만 던지면 *Finished 가 Turn 인가* 재검토. sealed class 로 *별개 상태* 분리.

### 3. Tell-Don't-Ask — board 자기 종료 판단

외부 `Turn` 이 board 상태 꺼내 판단 = 위반. *board 가 자기 종료 판단*. 각 Turn 의 중복 코드 = 책임 잘못된 위치 신호.

### 4. 경계에서 즉시 도메인 객체로 변환

*view → model* 경계에서 `Pair → Point` 즉시 변환. 도메인 *내부*는 도메인 어휘만. aprilgom #102 결.

### 5. view → model 의존 회피

domain 객체 (Point) 를 view 가 의존하면 의존 방향 위반. 언어 표준 타입(Pair) 또는 DTO 로 변환. 단 *Pair* 는 *도메인 의미 손실* 위험 — 즉시 도메인 객체로 변환 동반.

### 6. 도메인 룰 인터페이스 추상화 — 공통 시그니처 다형성

Rule (Board → Boolean) = 4종 다형성. INSIGHTS.md 인사이트 3 결.
