## 얻은 교훈 (OOP / 설계)

### 1. 상속 의의 = 공통 분리 / 차이 내부화 — 어긋나면 상속 자체 무너짐

*BlackPlayer / WhitePlayer 상속* 후 *putStone 구현 다른 이유* = *상속의 의의 (차이 내부화) 위반*. *돌을 놓는다는 동작*이 *공통*이면 *상속 ≠ 합성 (has-a)*. **MCP 룰 `subclass-divergent-method-defeats-inheritance` 후보**:
- *부모 추상 메서드*가 *자식들에서 모두 다른 구현* + *해당 동작이 본질적으로 공통*이면 → *상속 의의 위반*.

라코의 *10명 변경 시나리오* 가 *상속의 확장 비용* 시각화.

### 2. 두 정의 문장 비교 — *is-a vs has-a* 학습

*#1 흰색 플레이어 = 흰색 돌이다 (is-a)* vs *#2 A 플레이어 = 흰색 돌을 가진다 (has-a)* — *플레이어 = 돌의 종류 (상속)* vs *플레이어 = 식별자 + 돌 보유 (합성)*. m6z1/139 의 *셀 = 분류식 vs 셀 = 합성식* 어휘의 *오목 측 다른 학생 결*.

라코의 *문장 단위 설계 어휘* 가 *모델링 의도 자체*를 *자연어 문장*으로 강제.

### 3. 라이브러리 격리 = Rule 인터페이스 도메인 어휘

*외부 라이브러리 (RenjuRule) 직접 의존* → *Rule 인터페이스 도메인 추상* + *Adapter = Rule 구현 + 라이브러리 호출* + *Board = Rule 의존*. 3단 구조가 *호출자가 라이브러리를 모름* 의의 완성.

donghyun81/122 *DIP 자가 narrate* + m6z1/139 *Board ↔ RuleAdapter 직접 의존* 의 *오목 측 미플 자가 도달*. **3 학생 누적 어댑터 의존 방향 학습**.

### 4. View 책임 확장 — parse / convert / toUI 도 View

*View ≠ 단순 출력*. *View = 입력 파싱 + 출력 포맷 + UiModel 매핑* 모두 가질 수 있음. *Controller 가 변환 책임 가짐* 가정은 *View 의 자기 일 외부 떠넘김* (Tell-Don't-Ask 위반).

donghyun81/122 *Factory 책임 폭증 회피* + 미플 *View 책임 자가 확장* — *오목 측 2 학생 누적*.

### 5. 인터페이스 리스너 vs 람다 = 동작 복잡도 어휘

*간단한 로직 = 람다 / 메인 게임 진행 = 인터페이스 리스너*. 동작 복잡도 + 추적 가능성으로 분기. Hevton/57·#88 라코 *고차함수 vs interface 조건부 적절성* 어휘의 *미플 자가 도달*.

MCP 룰 `higher-order-fn-vs-interface-collaboration` evidence 강화 — *학생 자가 도달 2번째 (Hevton + 미플)*.

### 6. canPlace 같은 can/is 명명 = Boolean 약속

*can~ / is~* 명명은 *Boolean 반환* 의 영어 직관. *반환이 Boolean 아님 = 약속 위반*. 호두 *playOmok → isPlaying* 어휘 결. MCP 룰 `signature-name-mismatch` evidence.

### 7. throw = 코드 약속 위반 / 자연스러운 게임 행동 ≠ throw

*돌 두기 실패* = *플레이어의 자연스러운 시도* (금수 / 점유 / 범위 밖) — *코드 약속 위반 X*. *throw = 앱 크래시* 가 *황당함* 어휘. 호두 #68 의 *예외 → 상태 반환* 학습 결.

### 8. private board + 동일 테스트 통과 = 캡슐화 보존

*테스트 = 캡슐화 보존* 어휘. *board[y][x] 직접 접근* → *getStoneState(position) 질의 메서드*. 구현 변경 시 테스트 안전. 남잭슨 *테스트 = 캡슐화 보존* 어휘의 *오목 측 라코 변주*.
