### 7. 라코의 *check() 의미 어울리지 않음* + *private 함수*

라코 (OmokGame.kt):

> *"check() 라는 의미는 무언가를 확인한다는 내용이라서, 내부의 상태를 변경하는 것과 어울리지 않습니다.*
>
> *또한 이 함수를 외부에서 사용하는 것이 아닌 돌을 내려놓는데 성공한다면 이어서 바로 호출되어야 하는 로직이 아닐까요? (private)*
>
> *> Test: 돌을 내려놓았을 때 게임이 종료되었다면 현재 상태는 종료상태이다."*

→ **인사이트** (MCP 룰 후보 4 *`command-query-separation-naming`* 의 *별 학생 변주*): *check* = *질의 어휘* (검사) + *내부 상태 변경* = *명령 어휘* → *함수 이름 ↔ 행동 불일치*. 뭉치 (m6z1/139) 의 *checkPutState 사이드 이펙트* 와 *같은 결*. **두 학생이 같은 명명 함정에 도달**.

라코의 *`(private)`* 어휘가 추가 — *외부에서 호출되지 않는 함수* 는 *private*. *돌 내려놓기 성공 후 자동 호출* 흐름이면 *외부가 호출할 일이 없음* — *공개 API 의 크기 감소*. *Test 시그니처 (자연어)* 로 *기대 동작* 까지 제시 — 라코의 *문장 단위 설계 어휘* 가 *테스트 명세까지* 확장.

라코의 *"함수 타입으로 넘기면 어떤 장점이 있는건가요?"* — *고차함수 도입 정당화 검증*. *입력값 (Position)* 을 *함수 타입* 으로 *포장* 하면 *간접화* 만 추가, *동작의 추상화* 가 없음 — *과잉*.

선택 기준 (Hevton/57·#88 라코 어휘 종합):
- **동작 한 개 + 보일러 플레이트 제거** = 고차함수 (Hevton/88 스낵바)
- **동작 여러 개 + 협력자 명시** = interface (Hevton/57 GameManager)
- **단순 값** = 일반 인자 — 스캇 #42 케이스

**MCP 룰 후보 2 의 별 학생 변주 사례**.

### 6. *check()* 사이드 이펙트 — MCP 룰 후보 4 (`command-query-separation-naming`)

라코의 *"check() 라는 의미는 무언가를 확인한다는 내용이라서, 내부의 상태를 변경하는 것과 어울리지 않습니다"* 어휘가 *MCP 룰 후보 4*. **m6z1/139 의 *checkPutState 사이드 이펙트* 와 *같은 결의 다른 학생 등장*. MCP 룰 확정 강화**.

CQS (Command-Query Separation):
- **질의** = 사이드 이펙트 X + 결과 반환 (check, get, find, is)
- **명령** = 상태 변경 + Unit 반환 (place, set, add, remove)

*check + 내부 상태 변경* = *어휘 ↔ 행동 불일치* — 이름이 *호출자를 속임*.

## 도메인 특수 어휘 (3·4단계 — Android + SQLite, 스캇 한정)

- **OmokGame (도메인 측, 고차함수 인자 제거)**: 콘솔 + Android 동시 만족 위해 *마스터 객체 설계 회피* + *상태 변경 인터페이스* 형태.
- **OmokGame.isRunning() / getWinnerColor()**: 라코 권장 — *진행 상태* + *결과* 명시적 분리. 스캇은 *Running/Finished 상태 보유* 로 부분 적용 (중복 계산 자가 자각).
- **OmokGame.placeTo(stone): Boolean**: nullable 반환 → Boolean 명시화. *명시적 sealed PlaceResult 단계까지는 미도달*.
- **Controller (콘솔 측, while 보유)**: 라코 명시 *"안드로이드의 MVC 에서는 액티비티가 Controller"*. *콘솔 Controller* + *Activity (Android Controller)* 별 보유.
- **Converter (UI ↔ DB 변환)**: UI 표시값 + DB 저장값 *분리 자가 narrate* — 변경 시나리오 기반 추상화 (MCP 룰 후보 1).
- **OmokDbHelper (SQLiteOpenHelper 상속)**: Context (non-null 권장, 자바 API nullable 흡수).
- **OmokDbManager**: DB 접근 책임 (Helper 직접) vs 도메인 매핑 책임 (Manager 간접) — kimhm0728/93 *omokDao ↔ omokDataStore* 와 같은 결.
- **MainActivity.setOnClickListener**: 람다 본문 = 익명 함수, 한 가지 역할 분리 강제.
- **lateinit vs lazy**: var → val (가변/불변 의도). *오목 게임 변경 없으면 lazy* (스캇 자가 narrate).
- **`var currentColor: Color private set`**: 외부 쓰기 차단 + 내부 쓰기 허용 (Kotlin 표준 어휘).
- **렌주룰 ↔ DbManager 결합 어색함**: *"렌주룰을 비롯한 보드게임 자체를 준비하는 것이 데이터베이스 매니저의 역할일까요?"* — DbManager 책임 폭증 신호.
- **show / print 명명 혼용**: 일관성 학습 — 호두 #103 *viewStone → showStone* 와 같은 결.
- **마지막 위치 기반 초기 턴**: *마지막 검정 → 흰* / *마지막 없음 → 검정* — 라코 자연어 테스트 명세.
