### 6. Pair 인자 *자가 정당화* — 좌표+색 함께 또는 없음

말리빈 (OmokGame.kt):

> *"여기 파라미터는 Pair로 받는 이유가 무엇인가요?"*

다이스:

> *"start()에서는 종료 전 마지막 착수의 좌표와 돌의 색상을 받습니다. 하지만 이전 기록이 없다면 해당 값은 null이어야 합니다.*
>
> *이때, 좌표와 돌의 색상은 반드시 함께 존재하거나 함께 없어야 하므로, 이를 Pair로 묶어 전달하도록 했습니다."*

말리빈 답 (압박):

> *"lastMove를 null로 주어야하는 때가 존재하나요? 존재한다면, 마지막을 null로 세팅하는 것은 객체가 자율적인 역할을 수행하고 있는걸까요?"*

→ **인사이트** (블랙잭 INSIGHTS 5 *값 객체 invariant* + INSIGHTS 1 *Tell-Don't-Ask* + INSIGHTS 6 *한 데이터 두 책임*): 다이스의 *Pair 정당화 (좌표+색 = 함께 존재/없음)* = *복합 invariant 표현* — *분리 변수 두 개면 한쪽만 null 가능성*. **다이스의 정당화가 정확**.

말리빈의 *반박이 더 깊음*: *null = 자율 깸 신호*. *마지막 수가 null* = *게임이 시작 안 했음* = *시작 안 한 게임에서 start() 호출* 자체가 *호출자가 외부에서 null 결정*. *자율 객체* 는 *자기 상태가 시작 안 했음을 스스로 알고* + *외부는 그냥 start() 호출*. 두 안:
- (a) `Pair<Point, Color>?` 인자 (다이스 안) — 호출자가 null 결정
- (b) `start(lastMove: Move?)` 별도 메서드 + null 인자 호출자에 위임
- (c) `start(): OmokGame` 팩토리 + `restore(lastMove: Move): OmokGame` 두 메서드 — 자율 측 정점


`nullable-boundary-conversion` MCP 룰 후보의 *자율 객체 측 변주 evidence*.

>
> *placeStone을 호출했을 때 리스너로 값을 콜백해준다는 사실을 내부를 보지 않고 한 번에 이해할 수 있을까요?"*
