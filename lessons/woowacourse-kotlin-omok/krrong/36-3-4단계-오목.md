## 도메인 특수 어휘 (3·4단계 크롱 한정 — Android + SQLite)

- **MainActivity (View)**: 화면을 표시하고 사용자 입력을 처리한다. Controller 역할 일부와 겹칠 수 있다.
- **OmokGameController**: Activity에서 도메인 로직을 분리하며 게임 흐름을 조정한다.
- **OmokGameListener**: 게임 결과를 전달하는 Listener. 화면 생명주기 및 이벤트 처리 책임에 따라 배치한다.
- **OmokGame (도메인)**: 턴 관리 책임을 가진다. `initBoard`는 이름과 동작을 일치시키고, 설정된 `OmokBoard`를 받을 수 있다. `successTurn`과 `doTurn`의 차이를 이름에 드러낸다.
- **OmokBoard (도메인)**: 게임판 상태를 표현한다.
- **MoveResult (sealed class)**: 이동 결과를 표현하는 대안으로 검토했다.
- **OmokDbHelper / SQLite**: SQL 문자열을 상수로 관리한다. `setPreBoardImage`는 DB 중복 조회 대신 메모리 도메인 상태를 활용할 수 있다.
- **BoardView**: 2차원 `ImageView`를 감싸 화면 표현 책임을 캡슐화한다.
- **ViewInterface (추상화된 View)**: Controller가 구체 View 구현에 직접 의존하지 않도록 한다.
- **MVC vs MVP/MVVM**: Activity와 Controller의 역할 분리 방법으로 비교할 수 있는 패턴이다.
- **변경 시나리오 (화면 변경)**: 화면 변경이 Controller에 미치는 영향을 고려해 추상화 경계를 정한다.
- **prevState() (State enum)**: PR #5 의 State enum 보강 — 이전 상태 가져오는 함수. successTurn 의 *currentTurn 변경* 후 *이전 turn 으로 검증* 위한 어휘.
- **Listener vs 반환값**: Listener 콜백과 `MoveResult` 반환은 호출자에 결과를 전달하는 두 방식이며, 동기성·결합도·테스트 용이성을 고려해 선택한다.
- **데이터 복원 = 메모리 상태 활용**: `omokGame`의 board 정보를 활용해 DB 중복 호출을 줄인다.
