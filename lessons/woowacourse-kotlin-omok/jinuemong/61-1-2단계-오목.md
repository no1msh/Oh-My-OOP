### 4. `is` vs `::class` 학생 자가 의문 → sealed 권장 (Wirfs-Brock 식 도구 비교)

누누 (Board.kt thread):

> *"is 키워드는 특정 타입의 인스턴스인지 확인하고, ::class는 객체의 클래스를 가져올 때 사용합니다. 각 객체의 클래스를 비교하기 위해서 ::class를 사용했지만, 뭔가 보기 좋아보이지 않다는 생각을 합니다.. 좋은 방법을 찾고있는데, 클래스에서 타입만 추론하는 방법이 있을까요? ㅠ 어렵네요"*

두루 답:

> *"현재 구현을 살펴보면, StoneState에 대해서 상속받은 객체들에 대해서 비슷한 기능을 하게 구현이 되어 있는 것들이 많은 것 같은데, 추상 클래스나 sealed class를 활용해보는 방법으로도 가독성을 향상시켜볼 수 있겠다는 생각이 듭니다!!"*

→ **인사이트** (블랙잭 INSIGHTS 3 — State sealed 결): `::class` 직접 비교는 *런타임 타입 객체* 를 *값*으로 다루는 *역방향 어휘*. *타입이 다르면 행동이 다르다* 의 정직한 표현은 *sealed when* — when 절이 *컴파일러 차원에서 모든 자식 분기 검증*. 누누의 *"보기 좋아보이지 않다"* 어휘가 *어색함 = 분리 신호 (메타 M4)* — DYGames/7 *PlaceStoneResult sealed class* / sh1mj1/96 *PlaceResult sealed interface* 의 *2024 누누 시드* 위치.

### 3. `bfs` 함수명 — 알고리즘 어휘 = 도메인 모호 (가상 객체)

두루 (Board.kt):
