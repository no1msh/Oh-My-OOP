### 2. value class private constructor + EMPTY companion — *잘못된 board 차단*

토리 (OmokBoard.kt) 의 *value class 권고*:

> *"`OmokBoard(emptyMap())`과 같이 잘못된 board를 만들 수도 있습니다.*
> *불변의 경우에는 아래와 같이 구현해주시면 별다른 유효성 검사 없이도 유효한 board를 가독성있게 외부 API로 제공해줄 수 있습니다.*
>
> ```kotlin
> @JvmInline
> value class OmokBoard private constructor(
>     private val value: Map<YCoordinate, OmokLine>
> ) {
>     companion object {
>         val EMPTY = OmokBoard(YCoordinate.all().associateWith { OmokLine() })
>     }
> }
> ```
>
> *-----*
>
> *만약 내부에 필드를 가져야하는 경우가 생긴다면 getter로 변경하거나 data class로 변경하시면 됩니다.*
>
> ```kotlin
> val keys get() = value.keys
> val values get() = value.values
> ```
>
> ```kotlin
> @Suppress("DataClassPrivateConstructor")
> data class OmokBoard private constructor(
>     private val value: Map<YCoordinate, OmokLine>
> ) {
> ```"


- **value class** = *원시값 wrapper + 런타임 오버헤드 없음* (Kotlin 인라인 어휘)
- **private constructor** = *외부 직접 생성 차단* — *EMPTY 처럼 명시 생성자만 노출*
- **EMPTY companion** = *기본 유효 인스턴스 = 항상 가능한 출발점*

tobae-time/124 의 *Position invariant init* 결의 *Kotlin 어휘 깊이 변주*. **MCP 룰 후보** `primitive-wrapper-without-invariant` (lotto/blackjack 결) 의 *시즌 초기 토리 어휘 변주* — 단순 wrapping 이 아니라 *invariant 가 박힌 wrapping*.

토리의 *대안 명시 어휘*: *"내부에 필드를 가져야하는 경우 ... getter 로 변경하거나 data class 로 변경하시면 됩니다"* — *value class 의 한계 (단일 필드)* 까지 *함께 명시*. *대안 + 그 대안의 한계* 까지 한 코멘트에 묶어 *학생이 이후 단계에 결정 가능* 하도록.

### 8. Kotlin으로 invariant 명시

토리의 *value class + private constructor + EMPTY companion* 어휘는 *Kotlin 만의 어휘 깊이*. 자바였다면 *@throws 문서화 + factory 메소드* 같은 *수동 어휘* 가 필요한데, Kotlin *value class + private constructor* 가 *컴파일러로* 강제.


## 도메인 특수 어휘 (1·2단계 오목 — 아크)

- **OmokBoard**: 불변 자료구조 보드. 토리 권고 *value class + private constructor + EMPTY companion* 3 단 어휘
- **OmokPoint(x, y)**: 좌표 한 객체 (X, Y 별도 차원 → 한 차원으로 일선화). 핑구 PR #2 *Column + Row 별도 객체* 와 다른 시작점

- **YCoordinate**: 토리 예시의 Y 축 좌표 추상 (값 객체)
- **StoneState**: 돌 상태 — 토리 *UI 로직? GUI 그림 표현 시?* 권고 (도메인-표현 결합)
- **gameState/BlackTurn**: 흑/백 차례 객체화 — *상태별 별도 객체 어휘*
- **WhiteTurn / BlackTurn**: 두 차례 객체 (디렉토리 패키지)
- **OmokRule**: 룰 객체 — 예외 메시지 누락 권고 (로그 수집 환경 대비)
- **WhiteWinRule / 33 룰 분리**: 각 룰을 별도 객체로 분리 (토리 *인상적* 칭찬)
- **OmokMap**: View 의 오목판 표현 — 동적 변경 (보드 크기 가변)
- **StoneStateModel**: 토리 권고 *복잡 시 별도 모델 클래스* (현재 간단 → 분리 불필요)
- **OmokController**: Controller. 토리 권고 *InputView/OutputView interface 로 느슨 결합 → Android 재사용 가능*

- **EMPTY companion**: 토리의 *기본 유효 인스턴스* 어휘 (factory 메소드 변주)
- **`@JvmInline value class`**: Kotlin 어휘 — *원시값 wrapper + 런타임 오버헤드 없음*
- **`@Suppress("DataClassPrivateConstructor")` data class**: Kotlin 의 *data class + private constructor* 어휘
- **`val keys get() = value.keys`**: Kotlin getter 어휘 (`@JvmInline` 의 단일 필드 한계 우회)
