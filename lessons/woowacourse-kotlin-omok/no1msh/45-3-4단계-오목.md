> *"안드로이드 프레임워크로 넘어오면서 그동안 배워왔던 MVC 패턴 적용에 굉장히 애를 먹고 있습니다. Activity가 View의 역할을 하는건 맞아보이는데 과연 Controller의 역할도 할지 헷갈렸습니다. 이에 관해 검색을 해본 결과 사람들도 의견이 혼재해있던걸 보았습니다. 어떻게 해야할까요?? 🧐"*

→ **MCP 출발점 어휘 4** (#23 의 *최대한 쉽게* 어휘 정점 다음 단계): *외부 검색 결과 = 의견 혼재* → *답이 단일하지 않음* 의 *외부 환경 자가 자각*. 반달이 *학생 시절에 인터넷 검색* 으로도 *단일 답을 얻지 못함*. MCP 서버의 *N 안 + 트레이드오프* 시그니처는 *현실 검색 결과의 모양*을 *도구 시그니처*로 끌어옴 — *학생 자가 학습이 마주치는 검색 결과의 형태* 와 *MCP 도구 응답의 형태* 가 일치.

→ **MCP 출발점 어휘 5**: 벅벅이 *Android 프레임워크 내부 코드 (setContentView 자바 구현체)* 까지 인용하여 *결론을 코드로 정당화*. *"~다고 볼 수도 있습니다 ... 하지만, ~에 더 가깝다고 볼 수 있습니다"* 어휘 = *N 안 비교 후 추천 안 명시* 의 *벅벅 변주*. 라코의 *Wirfs-Brock 식 두 안 비교 + 정답 회피* 와 다른 결: 벅벅 = *N 안 비교 + 코드 근거 기반 추천 명시*.

이 어휘가 *MCP 서버의 `oop_propose_alternatives` 도구 시그니처*에 정확히 매핑됨 — *대안 N 개 + 각 안의 트레이드오프 + 추천 근거*. 반달이 학생 시절 *받은 좋은 답변의 형태* 가 훗날 *MCP 도구의 응답 형태* 로 정착.

### 1. 학생 자가 의문의 *외부 검색 결과 narrate* — *의견 혼재* 어휘

PR body 의 *"검색을 해본 결과 사람들도 의견이 혼재해있던걸 보았습니다"* 어휘 — *외부 자원의 단일 답 부재* 를 *학생이 직접 체감*. 이는 *학생 학습 narrate 의 정점 어휘 중 하나* — *학생이 *답이 단일하지 않다는 것 자체*를 학습한 순간*.


**MCP 출발점 어휘로서의 의의**: 반달이 *"의견이 혼재"* 가 *문제* 가 아니라 *학습의 출발점* 임을 *벅벅의 답변에서 받아들임*. MCP 서버의 *"단일 답 X, N 안 + 트레이드오프"* 어휘는 *의견 혼재를 학습 자원으로 직접 끌어옴*.

## 도메인 특수 어휘 (3·4단계 — Android + SQLite 반달 한정)

- **Activity = Controller (벅벅 어휘 정점)**: 콘솔의 Controller 자리를 Android 에서 Activity 가 차지. 라코식 (호두 #103) 의 *Controller 폐기 + OmokGame 분리* 와 다른 길.
- **onCreate (체조 위반)**: *3 이상 인스턴스 변수* + *두 가지 이상의 일* + *else 예약어* 위반. Activity 의 본질적 제약과 충돌.
- **OmokContract (public 상수)**: DB 상수의 public 노출 — internal/private 권장.
- **OmokRepository / OmokDbHelper**: DB 어휘 격리 + Activity 가 도메인 어휘만. cursor 는 Repository 만.
- **SerializableBoard / Json 직렬화**: 우선순위 외 부가 기술 (PR #53 측 진단). 기본 요구사항 우선.
- **Activity 재생성 (재시작)**: 비싼 연산 + UX 어색. *돌 제거 + 보드 초기화*로 충분.
- **GoStoneColorNumber**: enum / value class 형태 — 테스트 가능 객체.
- **!omokRepo.isEmpty() (반달 자가 회수)**: cursor 직접 다루기 → Repository 위임 + 의도 명시. *읽는 입장* 어휘 정점.
- **MCP 출발점 어휘**: *최대한 쉽게* + *의견 혼재* + *제대로 적용* + *코드 보는 입장* — 학생 시절 결핍/자각이 MCP 도구 시그니처로 전환.
