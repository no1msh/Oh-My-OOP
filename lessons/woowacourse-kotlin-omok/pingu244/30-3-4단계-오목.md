라코의 *"DB에 접근하고 사용하는 기능은 액티비티가 아니고 DBHelper 스스로 하도록"* + *"의존 방향을 어디로 향할지 결정 기준"* 어휘가 **MCP 룰 후보** `responsibility-by-layer` (말리빈 *select/insert 외부 노출 회피* + 벅벅 *cursor = Repository만*) 의 *시즌 초기 라코 변주*.

*UI - 도메인 - 데이터베이스* 3 레이어 어휘 (dpcks0509/91 정점 정의) 의 *시즌 초기 핵심 사례* — *Activity ↔ DBHelper* 의존 방향이 *그저 한 방향* 이 아니라 *위치 변환의 위치 (인덱스 ↔ Position)* 까지 *함께* 결정.

### 9. enum exhaustiveness — *else 회피*

라코의 *"enum class라면 else를 사용하는 대신 명확하게 케이스를 나눠 주세요"* 어휘가 **boogi-woogi/16 enum → sealed 부정형 명제 ("색깔이 Black과 White라는 것이 없다")** 의 *시즌 초기 라코 변주*. *컴파일러 안전망* (sealed class 의 when exhaustiveness, enum 의 모든 case 명시) 을 *else 로 회피* 하지 않는 어휘.
