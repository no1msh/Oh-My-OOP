## 설계 요점

- `List<Stone>`은 임의 개수의 돌을 허용하므로 흑·백 두 값만 가능한 규칙은 sealed 타입으로 표현할 수 있다.
- 외부 규칙 라이브러리는 어댑터를 통해 도메인과 분리하고, 도메인 데이터와 presentation 모델은 mapper로 변환한다. 분리한 mapper는 실제 출력에서 활용되어야 한다.
- 실행 환경이 달라질 수 있으면 `println` 등 입출력 의존을 도메인에서 분리한다. 승리 규칙 교체도 인터페이스 경계를 검토할 수 있다.
- 예외와 nullable 결과의 선택은 실패의 의미와 알고리즘에 달려 있다. 범위 밖 좌표를 예외로 볼지 정상적인 탐색 결과로 볼지 경계를 명확히 한다.
- 템플릿 안에서 조건 계산을 하지 말고 값을 먼저 계산해 표현과 분리한다.
- 기본형 확장 함수는 적용 범위가 넓으므로 접근 제한자를 사용해 노출 범위를 제한한다.
- 함수명은 동작을 드러내고, 이름·반환값·부수 효과가 일치하는지 확인한다.

## 도메인 특수 어휘

- **Game (domain 패키지)**: 입출력과 게임 흐름이 섞이지 않도록 도메인 책임을 분리한다.
- **Referee (BlackReferee)**: 외부 렌주룰 라이브러리를 감싸는 어댑터.
- **Stone**: 흑·백 두 값만 표현할 때 sealed 타입을 사용할 수 있다.
- **List<Stone> (Turn)**: 임의 크기 목록은 흑·백 두 값이라는 규칙을 보장하지 않는다.
- **RowModel / ColumnModel**: presentation 계층용 모델과 도메인 값을 mapper로 변환한다.
- **Column 확장함수**: 기본형 확장 함수의 노출 범위를 접근 제한자로 제한한다.
- **runCatching nullable 반환**: 알고리즘이 범위 밖을 정상 결과로 취급하는지, 오류로 취급하는지 구분한다.
- **InputView / OutputView string template**: 표현 템플릿에서 도메인 계산을 분리한다.
- **승리조건 (winningCondition)**: 규칙 교체가 요구될 경우 인터페이스 경계를 검토한다.
