### 5. *apply 확장함수 학습* — use let apply with run 선택

크롱 (OmokAppControl.kt):

> *"`use let apply with run` 중 어떤 것을 사용하면 좋을까요?"*

메다:

> *"ContentValues()에서 put작업들을 마치고 객체 자기 자신을 반환하는 `apply`를 써보겠습니다"*

→ **인사이트** (Kotlin 어휘 깊이 + scope function 5 종 분류): Kotlin 의 *scope function 5 종*:
- `let`: *it* + 마지막 반환
- `apply`: *this* + 객체 자신 반환 (*객체 설정에 적절*)
- `with`: *this* + 마지막 반환 (객체 외부 변수)
- `run`: *this* + 마지막 반환
- `also`: *it* + 객체 자신 반환

메다의 *ContentValues 객체 설정 + 자기 반환 = apply* 선택은 *5 종 차이 자가 학습 정점*. 블랙잭 INSIGHTS 메타 M2 (그저 좋다 함정) 의 *Kotlin 표준 어휘 학습 단계*.

## 얻은 교훈 (OOP / 설계)

### 1. *도메인 변경 최소화 = 도메인 분리의 가장 강한 검증*

메다의 *콘솔 → Android 전환에서 도메인 코드 거의 그대로 유지* = *도메인 분리가 실제 작동*. 추상적 *3 레이어 분리* 어휘 (dpcks0509/91 라코) 의 *실제 작동 evidence*. **`change-scenario-based-abstraction` MCP 룰 후보의 *플랫폼 변경 격리 작동 evidence* 정점**.

### 2. *Fake 정당화 학생 측 어휘 정점*

메다의 OmokRule.Fake narrate 가 코퍼스에서 가장 명시적인 *Fake 정당화 학생 측 어휘*. *인터페이스 변경 → Fake 컴파일러 강제 → 테스트 코드 안정성* 세 가치 동시 narrate. 블랙잭 INSIGHTS 메타 M3 의 *Fake 정당화 학생 측 정점 추가*.

### 3. Controller와 Activity 책임 분리

`GameActivity`가 Controller 역할을 맡고 `MainActivity`가 화면 역할을 맡는 구조와, `MainActivity`가 둘 다 맡는 구조를 비교한다. 분리는 역할 구분을 명확히 하지만 파일·객체 수를 늘리므로 실제 책임이 분리되는지 확인한다.

### 4. 의미 있는 값 객체 재사용

좌표를 `Pair`로 전달하면 각 값이 행인지 열인지 호출부에서 추측해야 한다. 이미 있는 `Position`을 재사용하면 의미와 검증 규칙을 함께 표현할 수 있다.

### 5. Kotlin 기능 선택

`use`는 `Closeable` 자원을 안전하게 닫고, `apply`는 객체 설정 후 그 객체를 반환한다. 초기화가 최초 접근 시점에 일어나야 하면 `by lazy`, 호출자가 초기화 시점을 결정하면 `lateinit`을 고려할 수 있다.
