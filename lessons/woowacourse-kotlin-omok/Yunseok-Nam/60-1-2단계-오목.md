### 3. DeltaPosition unaryMinus — 4 인스턴스로 8 방향 표현 (Thread 8)

```kotlin
data class DeltaPosition(val row: Int, val column: Int) {
    operator fun unaryMinus(): DeltaPosition = DeltaPosition(-row, -column)
}
```

파이로:

> *"OmokChecker 의 로직을 읽기 전에는 DeltaPosition 과 일반 Position 이 어떻게 다른 건지 이해하기 어려웠습니다. 알고보니 상대적인 위치를 표시해주는 객체이군요.*
> *상대적인 위치를 나타내는 DeltaPosition 과 절대적인 위치를 나타내는 Position 을 별개의 data class 로 분리해주시고, unaryMinus operator 를 별도로 정의해주신 것은 정말 멋지다고 생각합니다. 👍 💯*
> *특히 unaryMinus 를 통해 4개의 인스턴스만으로 8개의 방향을 표현해주신 것은 이해를 하고나서 무릎을 탁 쳤네요."*

→ **인사이트** (블랙잭 INSIGHTS 5 — 값 객체 invariant의 *수학적 대칭 측 변주*): *오목의 방향* 은 *수평 / 수직 / 우상향 / 우하향 4 개* + *각각의 반대 = 4 개의 반대 (-우상향 = 좌하향)* = *4 개 인스턴스 + unaryMinus = 8 방향*. *수학적 대칭* 을 *operator overloading* 으로 *언어 어휘로 끌어올림*.


다만 파이로는 *Delta 라는 이름의 직관성* 의문도 동시에 제기:

> *"다만 Delta 라는 이름은 조금 더 직관적으로 바꾸어 주시면 좋을 것 같습니다. 상대좌표의 "상대적인" 이라는 의미가 더 강화되면 좋지 않을까 싶습니다. Position 도 "절대" 좌표의 절대적인 이라는 의미가 있는 네이밍이면 좋을 것 같고요."*

이어 *Direction* 으로 명명 권유 (Thread 9):

> *"네이밍과 관련해서는, DeltaPosition 은 Position 의 특성보다는 direction 의 성격이 더 강하지 않나? 라는 생각을 했습니다. 그렇기에 DeltaPosition 리스트를 directionType 이라고 네이밍을 하신거고요. 만약 DeltaPosition 을 Direction 과 관련된 네이밍으로 객체 이름을 지으면, Position 의 이름에 "절대적인" 과 관련된 추가 수식어가 필요없겠다는 생각도 들었습니다."*

→ *명명이 객체의 본질*을 가리키는지 점검. *DeltaPosition* 은 *Position 의 변종* 처럼 들리지만 *실제는 Direction*. `signature-name-mismatch` + `vague-class-name` 결의 *오목 측 변주*.

## 얻은 교훈 (OOP / 설계)

### 1. 어댑터 패턴 자가 도달 — *외부 라이브러리 격리* 의 학생 측 직관

서기의 어댑터 자가 도달은 *키워드 미리 받지 않고 본질에서 풀어낸* 변주. *외부 라이브러리 → 도메인 의존 단방향* + *도메인 → 라이브러리 의존 = 어댑터 한 자리* 라는 어휘를 학생이 자가 풀이.

호두 #68 의 *다른 PR 참고 후 자가 정의* + 서기 #60 의 *키워드 미리 안 받고 자가 도달* = *어댑터 어휘의 두 도달 경로*. `adapter-vs-wrapper-naming` 룰의 *학생 자가 도달 정점*.

### 2. 라이브러리 격리 2 항목 체크리스트 — *의존 단방향 + 최소 영역*

파이로의 *(1) 라이브러리 → 도메인 의존 X (2) 도메인 → 라이브러리 의존 최소 영역* 어휘 = *라이브러리 격리 점검의 정형 체크리스트*. 두 조건 동시 충족이어야 정당.

`responsibility-by-layer` 룰의 *라이브러리 측 변주* — 외부 라이브러리 어휘는 *어댑터 한 자리에서만 호출*. 도메인 코드 본체는 *라이브러리 어휘 자유*.

### 3. sealed class 의 정당화 = *exhaustive when + 상속 제한 (보안)* 두 결

서기가 자가 풀이한 *exhaustive when* 어휘 + 파이로의 *상속 제한 = 협업 안전성/해킹 방어* 어휘 = sealed class 의 *두 정당화 결*. 두 번째 결 = *코퍼스 안 최초 보안 측 어휘 첫 등장* (PR #60, 2024-03).


### 4. 명명 외부자 시뮬레이션 — *코드 처음 본 사람의 직관*

파이로의 *"Stone 이라는 클래스명 만 보고, 처음에 Stone 이 ... 최상위 인터페이스라고 생각했습니다"* + 서기 자가 *"코드를 처음 본 사람이라면 ... 생각할 수 밖에 없겠네요"* = **명명의 외부자 시뮬레이션** 어휘.

말리빈의 *"다른 회사 개발자도 이름 이해할까"* 어휘 (블랙잭 INSIGHTS) 의 *오목 코퍼스 파이로 변주*. `signature-name-mismatch` + `vague-class-name` 룰의 *외부자 시선 측 변주*.

### 5. Tell-Don't-Ask 자가 도달 — *외부에서 쓴다 = 그 기능이 그 클래스의 책임*


*외부 호출자가 객체.x.y 풀어 조작* = *객체 책임 = 그 조작 자체*. *질의 + 외부 처리 → 메시지 한 자리로 응집*. 블랙잭 INSIGHTS 1 의 *오목 측 자가 도달 변주*.




### 7. else 회피의 *엄밀한 의미* — 같은 함수 안 연속 조건문 회피

파이로의 *"else 예약어를 쓰지 않는다 = 같은 함수내에서 연속된 조건문을 쓰지 말라는 뜻"* 어휘 = *체조 규칙의 엄밀 풀이*. *if/else 한 쌍은 허용 + 여러 분기 연속은 다형성으로 흡수*.

블랙잭 코퍼스의 *벅벅 #41 체조 4 규칙 직접 인용* 의 *오목 코퍼스 첫 등장 자리* (파이로 #60). `function-decomposition-excess` 의 *반대편 변주* — 분해 부족 + 조건 응집 폭증.

### 8. Expression vs Statement — *취향 명시 + 정답 회피* 어휘

파이로의 *"이건 정말 취향 차이인데 ... 이건 제 편견일 수도 있는 취향의 영역입니다"* 어휘 = *정답 강요 회피*. namjackson, vagabond95 의 *"개인적인 의견"* 결의 *파이로 변주*.

서기의 *"좋다 나쁘다를 떠나서 ... 어떤 차이가 있는지 경험해보는 것도 좋다고 생각이 드네요"* 어휘 = *경험적 학습 어휘*. 블랙잭 코퍼스의 *불완전 코드 = 학습 자원* (제이든 결) 의 *학생 측 변주*.

### 9. 라이브러리 경계와 코드 표현 선택

외부 라이브러리 의존을 어댑터에 모으면 교체 지점을 제한할 수 있다. 단일 표현식은 expression body로 간결하게 쓸 수 있지만, 여러 단계의 흐름은 블록 본문이 읽기 쉬울 수 있다. `tailrec`은 꼬리 호출 위치가 제한되므로 실제 재귀 구조와 컴파일러 최적화 조건을 확인한다.

## 도메인 특수 어휘 (1·2단계 오목)

- **GoStone (sealed class)**: 흑돌·백돌 공통 추상 부모. *상속 제한 = exhaustive when + 협업/해킹 방어* 두 정당화. 호두 #59 의 *추상 클래스 GoStone* 과 *Kotlin 어휘 단계 차이* (sealed = 상속 제한 강).
- **BlackStone / WhiteStone (object 싱글톤)**: GoStone 의 자식. *돌의 주체 = 한 명 → 싱글톤 정당*. *놓아지는 돌 (값) vs 놓는 주체 (object)* 분리.
- **Stone → StoneType (enum class)**: 외부자 명명 직관 회피 어휘. *enum 의 역할 명시*.
- **Position (절대 좌표) ↔ DeltaPosition (상대 좌표) → Direction (명명 진화)**: 좌표 분리. *unaryMinus operator = 4 인스턴스로 8 방향 표현*. 명명 진화 결.
- **RenjuRuleAdapter (도메인 ↔ 외부 라이브러리)**: 어댑터 패턴 *학생 자가 도달*. *renjurule 라이브러리 교체 시 어댑터 한 자리만 변경*.
- **lib/renjurule (외부 라이브러리 패키지)**: *애플리케이션 코드 의존 X* 단방향 격리. *2 항목 체크리스트 충족* 자리.
- **OmokGame.retryUntilSuccess (재귀함수)**: 반복문 대신 재귀. *tail recursion* 학습 자원.
- **OmokChecker.checkWinningPosition (Expression 위주 표현)**: *if/expression* 으로 *불변값 + 함수 합성 친화* 어휘.
- **BOARD_SIZE / board / lastPosition (public 누설)**: 캡슐화 약함 신호. *Board 책임 흡수 → private + 메시지로 위임*.
- **Position.col → Position.column (축약어 금지)**: 체조 규칙 *줄여 쓰지 않는다* 적용.
- **객체지향 생활 체조**: *else 회피 (연속 조건문 회피)* + *한 단계 들여쓰기*. 파이로의 *엄밀 풀이* 어휘 (코퍼스 첫 등장).
- **horizontalDirection / verticalDirection / upwardDirection / downwardDirection (4 인스턴스)**: companion object 정적 인스턴스 후보 어휘 — enum class Direction 으로 끌어올림 가능.
