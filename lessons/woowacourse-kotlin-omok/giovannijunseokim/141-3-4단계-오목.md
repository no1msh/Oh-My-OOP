### 1. lateinit vs lazy vs nullable — 학생 자가 4안 학습 (Thread 0, 1, 9, 14)

reviewer 질문 → 학생 자가 답변:

> *"지연 초기화 하는 방식들은 어떤 것들이 있고, 어떤 장단점이 있을까요?"* (두루)

학생 자가 정리:

> *"다른 방법으로는 다음과 같은 방식이 있을 것 같아요!*
>
> *- **`null`로 초기화**: 하지만 이 방식은 사용 시마다 `null` 체크를 해야 하는 점이 번거롭게 느껴졌습니다. 😅*
>
> *- **`lazy`로 초기화**: 이 방식은 처음 사용될 때 초기화되는 것으로 알고 있는데, 사실 `by` 키워드를 이용한 프로퍼티 초기화에 대해 잘 몰라서 사용하지 않았습니다.*
>
> *이렇게 비교해보니 `lazy`로 초기화하는 것이 제일 좋아 보이네요. 또한 공식 문서에서 스레드 안정성을 제공한다고 보았습니다."*

후속 (Thread 14):

> *"- **`null`로 초기화**: 만약 추후 `null`로 참조를 해제해야 한다면 필요한 방법임을 알았습니다!*
>
> *- **`by` 키워드를 통한 프로퍼티 초기화**: `by` 이후에 `getValue`, `setValue`를 지원하는 객체를 전달해 게터 세터를 위임하는 방식임을 알았습니다. 추가적으로 `val`, `var`을 `get`과 `get`, `set`을 구현해야 한다는 인터페이스같다는 관점도 생겼습니다!"*

→ **인사이트**: *초기화 시점 invariant* 의 4안:
- (a) `lateinit var` — 초기화 강제 X (호출 순서 invariant 부재)
- (b) `nullable + null check` — 매 사용 시 체크 부담
- (c) `by lazy` — 처음 사용 시 초기화 + 스레드 안전
- (d) 생성자 주입 (가장 안전, 학생 자가 언급 X)

INSIGHTS.md `lateinit-var-call-order-invariant` 결 — 블랙잭 7+ PR 반복 패턴. 코틀린 환경에서 `by lazy` 가 가장 안전한 후보 학습.

### 2. DB 테스트 추상화 — interface OmokHistoryStorage 도입 (Thread 13, 학생 자가 정리)

```kotlin
interface OmokHistoryStorage {
    fun save(...)
    fun fetch(): List<...>
}

class SQLiteOmokHistoryStorage(...) : OmokHistoryStorage { ... }

class OmokHistory(private val storage: OmokHistoryStorage) { ... }
```

학생 자가 정리:

> *"테스트란 **개발 과정에서 코드 수정 후에 제대로 동작하지 않을 수 있다는 불안감을 떨쳐내는 도구**라 생각했습니다. (...) 따라서 저는 DB 자체가 아닌, DB(혹은 그 후에 추가될 수 있는 어떠한 저장소)로부터 **데이터를 가져오는 것을 테스트**해야 겠다고 생각했습니다."*

> *"때문에 SQLite에 의존하는 것을 `SQLiteOmokHistoryStorage`까지 제한했고, 이의 추상화인 `OmokHistoryStorage`에 의존하는 `OmokHistory`라는 객체를 만들어주었습니다. 그리고 이 `OmokHistory`를 테스트하며, 미지의 저장소로부터 데이터를 가져오는 로직을 테스트하였습니다. 만약 새로운 저장소가 추가된다면 `OmokHistoryStorage`의 구현체를 추가하여 쉽게 갈아낄 수 있겠다고 생각했습니다!"*

→ **인사이트 (정점)**: DIP 적용. *도메인 객체 (OmokHistory)* 가 *추상 (OmokHistoryStorage)* 에 의존, *구체 (SQLiteOmokHistoryStorage)* 가 추상을 구현. INSIGHTS.md 메타 M3 (테스터빌리티) + chanho0908 #132 (도메인 외부 의존성 자가 자각) 결.

학생 자가 *테스트 = 불안감 떨쳐내는 도구* 어휘 정의 — *명세 도구* 어휘와 별개 시점이지만 둘 다 정당. 테스트의 *목적*에 대한 학생 자가 정의.

PR #114 (1·2단계) 의 *모든 도메인 모델 interface* 는 *오버엔지니어링* 으로 지적받았지만, *3·4단계의 OmokHistoryStorage* 는 *진짜 다형성 활용 (SQLite vs Fake) 이 필요한 자리* — interface 도입 정당화의 *현재 활용 가치* 기준 충족.

### 3. runOnUiThread — Android 스레드 분리 학생 자가 정당화 (Thread 2, 10)

학생 자가 답변:

> *"가장 근본적인 원인은, 메인 스레드가 아닌 Worker 스레드에서 UI에 관여하면 안 되기 때문입니다. 그 이유는 UI를 그리는 행위를 하나의 스레드가 독점하지 않으면 충돌이 발생할 수 있기 때문인 것으로 알고 있습니다."*

> *"위 함수는 Worker 스레드에서 수행된 결과(`omokHistory.fetch()`)를 사용해야 하기 때문에 해당 함수가 수행 완료되면 바로 뷰에 반영하도록 `runOnUiThread`를 사용했습니다. 😁 `join`의 경우, 메인 스레드를 블로킹하여 사용자와의 상호 작용이 중단될 가능성이 있다고 판단해 사용하지 않았습니다!"*

→ **인사이트**: Android 특수 영역이지만 *근본 원인 인지 → 도구 선택 정당화*는 일반. *왜 이 도구인가*를 *근본 원인 (UI 스레드 충돌)* 으로 설명. chanho0908 #132 (*근본 원인 미파악 시 transaction 도입*) 의 정반대 결.

## 얻은 교훈 (OOP / 설계)

### 1. 초기화 시점 invariant — 4안 트레이드오프

- `lateinit var` — 초기화 강제 X, 호출 순서 invariant 부재
- `nullable + null check` — 매 사용 시 체크
- `by lazy` — 처음 사용 시 초기화 + 스레드 안전
- 생성자 주입 — 가장 안전

코틀린 환경에서 `by lazy` 가 *지연 + 스레드 안전*. INSIGHTS.md `lateinit-var-call-order-invariant` 결.

### 2. DIP 적용 — 도메인 → 추상, 구체 → 추상

도메인 객체가 *추상 인터페이스*에 의존, 구체 (SQLite/Network/...) 가 *추상을 구현*. 새 저장소 추가 시 *구현체만* 추가. INSIGHTS.md 인사이트 7 (의존 방향) 의 영속화 변형 + chanho0908 #132 *도메인 외부 의존성 자가 자각* 결.

### 3. interface 도입 정당화 = *현재 다형성 활용 가치*

PR #114 의 *모든 도메인 모델 interface* 는 *오버엔지니어링*. 그러나 `OmokHistoryStorage` 는 *실제 다형성 활용 (SQLite vs Fake)* 이 있어 정당화. *추후 시나리오* 가 아니라 *현재 활용* 이 기준.

### 4. 진짜 중복 vs 우발적 중복

*하드코딩 리터럴 가독성* 학생 자가 *진짜 중복인지* 자가 자각. 모든 리터럴이 *상수화 대상*은 아니다. 블랙잭 #150 (로버트 마틴) 결.

### 5. 테스트의 목적은 다층 — 명세 + 안전망 + 학습 도구

- *명세*: 룰 표현 (블랙잭 INSIGHTS.md 인사이트 9)
- *안전망*: 학생 자가 *불안감 떨쳐내는 도구* 정의
- *학습 도구*: Fake DB 구현 자체의 학습 가치 (두루 권유)

### 6. 표현 layer 외부화 — strings.xml/리소스

INSIGHTS.md 인사이트 7 (도메인 vs 표현 분리) 의 Android 변형. *지역화 + 재사용 + 한 자리 수정* 가치 vs *리터럴 가독성* 트레이드오프.

### 7. 근본 원인 인지 → 도구 선택 정당화

`runOnUiThread` 사용 이유를 *UI 스레드 충돌* 근본 원인으로 설명. chanho0908 #132 (*근본 원인 미파악 transaction*) 의 정반대 결 — *왜 이 도구인가*를 *근본*으로 답변.

### 8. 학생 자가 트레이드오프 정리 + 의견 요청 — 학습 메타 어휘 정점

학생이 *4안 트레이드오프 직접 정리* + *"두루는 어떻게 생각하나요?"* 의견 요청. 블랙jack #134 (학생 자가 트레이드오프 도표화) 결 정착.
