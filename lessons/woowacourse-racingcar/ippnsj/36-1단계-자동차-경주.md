## 얻은 교훈

- **DTO의 정체성 = 데이터 운반.** 검증/가공/계산은 DTO의 일이 아님. DTO에 로직이 생기면 그것은 사실 다른 객체.
- **알고리즘 단순함 vs 효율.** O(n) 1회 vs O(n) 2회는 사실상 같은 클래스. 가독성이 우선. 진짜 성능 문제가 생긴 후 최적화.
- **테스트 하드코딩의 가치.** "DRY 원칙"이 테스트에 그대로 적용되지 않음. 테스트는 시나리오 명세이므로 데이터가 명시될수록 가독성.
- **시그니처 거짓말 = 호출자 혼란.** `inputCarNames: Boolean`은 메서드 이름과 반환 타입이 어긋남. 호출자가 함수 본문을 봐야.
- **`in range` 표현 활용** — 코틀린의 `number in 4..9`가 `number >= 4 && number <= 9`보다 가독성 + 의도.
- **메타 학습 가이드의 가치** — "왜 그렇게 생각했는지 직접 비교해보고 의견을 들어라"는 가이드는 학생이 자기 추론을 검증하는 훈련.
