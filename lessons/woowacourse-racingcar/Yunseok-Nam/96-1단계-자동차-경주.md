## 얻은 교훈

- **도메인 객체의 초기 상태는 생성자가 아니라 init/default가 담아야 한다.** `Car(name)`로 받고 forwardCount는 0으로 시작. 외부가 초기 위치를 정할 권리가 없다.
- **함수 이름은 동사형 + 무엇에 대한 동사**. `carName()`은 명사라 부르는 쪽에서 "이 함수는 뭘 하는 거지?"가 됨. `checkName()`, `validateName()`처럼 동사로.
- **검증의 위치 = 입력 재시도 확장성으로 정해질 수 있다.** "도메인 init에서 던지면 catch해서 재입력 어렵다 → InputView/Validator 선에서 잡고 정상 흐름으로"라는 논리가 성립.
- **getter 메서드 제거 = property 활용.** Kotlin에서 `getForwardCount()` 자바식 메서드는 자동 생성된 property getter가 이미 있는데 또 만든 셈. 호출 측에서 `car.forwardCount`로 단순화.
- **"Manager", "Util", "Helper" 같은 일반어 접미사는 책임 회피의 흔적.** 무엇을 관리하는지 / 무엇을 돕는지가 이름에 드러나야 함.
