## 리뷰어 의견 요지

리뷰어 @BeokBeok의 메시지:

1. **간접 호출의 함정** — `executeInputTryNumber` = "execute" + "input". 동사 두 개. 함수는 한 동사.

2. **backing property 컨벤션** — 생성자에 `_xxx` 두지 말고, 클래스 body에서 별도 선언.

3. **빈 리스트 = `emptyList()` (가독성)**.

4. **랜덤 의존성 분리** — `Cars.move` 안에 랜덤이 있으면 테스트 불가. 외부에서 주입.

5. **Validator의 View 의존 제거** — Validator는 도메인 검증만, View는 Controller가 다룸.

- **대표 인용:**
  > executeInputTryNumber함수보다는 inputTryNumber라는 함수가 더 잘 이해가 돼요. executeInputTryNumber함수를 사용하는 것을 "간접 호출"이라고 합니다. "간접 호출"은 유용한 경우도 많지만, 자칫 잘못하게 되면 과하게 함수를 호출하게 되는 상황을 만들기도 해요.

## 얻은 교훈

- **함수명에 동사는 *하나만***. `executeInput` = 두 동사. `executeXxx` 같은 간접 호출은 단순 `xxx`로 충분.
- **backing property는 *body 선언***. 생성자에 `_xxx`는 컨벤션 위반.
- **`emptyList()` vs `listOf()`** — 의미 명시.
- **랜덤은 함수 안이 아닌 *주입*으로**. 함수 안에 두면 테스트 시 결정적 결과 불가.
- **Validator의 View 의존 = 의존 방향 거꾸로**. Validator는 가장 안쪽 (도메인 가까이), View는 가장 바깥 (UI). 안쪽이 바깥을 알면 의존 역전.
