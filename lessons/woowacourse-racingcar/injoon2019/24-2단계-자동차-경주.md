## 얻은 교훈

- **인터페이스를 만들었다면 *반드시 사용*하기**. 전략 패턴 인터페이스 만들고 Car에 안 쓰면 "선언만 한 죽은 추상". 리뷰어가 즉시 잡음.
- **`require` + `check`의 의미 차이**. `require` = 인자 검증 (IllegalArgumentException), `check` = 상태 검증 (IllegalStateException). 사용자 입력 = require, 객체 내부 invariant = check.
- **companion object ≠ Java static**. Companion은 *그 클래스의 컴패니언 인스턴스*. 메서드/속성도 일반 클래스처럼 가질 수 있음. 진정한 static은 Kotlin에서 top-level이나 `@JvmStatic`.
- **kotest의 DSL** = "사람이 읽는 영어 문장". `position1 shouldBe position2`는 assertion이 아니라 *주장*처럼 읽힘. 테스트 가독성에 큰 이점.
- **여러 리뷰어가 한 PR에 모이면 협력적 학습** — 각자 다른 관점 (코틀린 idiom, OOP, 테스트). 학생이 한 라운드에 여러 깊이의 토론을 동시에 받음.
- **`maxByOrNull` = 안전 default 미반환**. 빈 컬렉션 시 null 반환 → null 처리 강제. 빈 컬렉션에서 max 부르는 잠재적 NPE 차단.
