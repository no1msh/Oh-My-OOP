## 리뷰어 의견 요지

리뷰어 @BeokBeok는 **방어적 복사** 라는 객체지향 핵심 패턴을 정확히 안내. MutableList를 받으면 외부 수정에 무방비 → 무결성 깨짐. Immutable 타입 + 방어적 복사로 안전성.

또한 **backing property** 패턴을 명시적으로 가르침 — `_movingState`(private) + `get() = _movingState`(public)로 코틀린 프로퍼티의 게터를 활용.

상수 위치에 대해서는 **"특정 클래스에서만 쓰면 companion으로"** 라는 명확한 가이드. 학생이 "각 사용처 vs 별도 파일" 중 어느 것이 맞는지 직접 물어봐 정답을 받음.

`indent depth 2 제한`으로 try-catch를 쓸 수밖에 없었다는 학생 답변에 대해 **"함수로 분리"** 라는 깔끔한 응답 — 제약을 우회의 핑계로 두지 말고 설계로 풀어내라는 가이드.

## 얻은 교훈

- **방어적 복사의 원리.** 외부에서 받은 컬렉션을 내부 상태로 사용한다면, 외부가 그 컬렉션을 바꿔도 내부가 안전해야. `MutableList`를 받아 내부에 그대로 저장하면 외부 변경이 즉시 내부에 전파.
- **상수의 자리는 사용 응집도가 결정.** 특정 클래스에서만 쓰면 그 클래스의 companion으로. 두세 도메인이 공유하면 각자에게 복제하거나 공유 도메인 객체로. 절대 `Constants.kt` 한 곳으로 모으지 말 것.
- **Backing property로 코틀린 프로퍼티 활용.** `private _x` + `val x get() = _x` 패턴으로 자바 게터를 만들지 않고도 read-only 외부 노출.
- **제약은 우회가 아니라 설계로 풀어낸다.** "indent depth 2 제한"이 있으면 함수 분리로. 제약을 핑계로 표준 도구(runCatching)를 못 쓴다고 결론짓지 말 것.
- **테스트 이름의 명세화.** "정상적으로 작동한다" → "4 이상이면 전진한다", "이름은 5자 이하만 허용" 같은 명세 단위로.
- **자기 의문 응답 패턴이 학습 가속.** 학생이 "drop이 List 반환인데 Int 반환이 맞나요?" 물어보면 리뷰어가 자기 잘못 인정("코드를 잘못 봤네요")하고 학생의 방향을 칭찬. 진솔한 토론이 학습 사이클을 만든다.
