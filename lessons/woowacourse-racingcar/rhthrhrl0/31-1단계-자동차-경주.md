## 리뷰어 의견 요지

리뷰어 @vagabond95의 핵심 가르침:

1. **data class에 비즈니스 로직?** — "데이터 클래스의 의도는 무엇? data class에 변경이 발생해야 한다면 그 이유는?" 데이터 운반 + 동치성이 본업이지 로직 호스팅이 아님.

2. **`Const` 단일 파일 → 의미별 분리 또는 사용처 내부 선언**. "common"이라는 패키지가 곧 god-folder.

3. **OutputView의 그리기 로직 = 별도 함수 분리** — 자동차 그리는 요구사항이 복잡해지면 println의 결과 예측 어려움.

4. **전략 패턴 활용 칭찬** — 의도에 맞게 잘 사용.

- **대표 인용:**

## 얻은 교훈

- **data class의 의도 = 데이터 + 동치성**. 비즈니스 로직 (이동, 검증, 변환)이 들어오면 *왜 data class인가* 의문. 일반 class로 충분할 수 있음.
- **`common`/`Const`/`Util` 같은 일반 패키지명은 god-folder**. 시간 흐르면 모든 게 그곳에 모임. 의미별 분리 또는 사용처 옆에 둘 것.
- **OutputView의 그리기 = 별도 함수**. `"-".repeat(...)` 같은 표현이 인라인되어 있으면 출력 요구사항 변경 시 println 예측 어려움.
