## 얻은 교훈

- **"어디까지 분리할까"의 고민 자체가 SRP 위반 신호일 수 있다**. 자연스러운 책임 분리는 자명함. 고민이 길어지면 클래스가 잘못 나뉜 상태일 가능성.
- **확장 함수의 자리 = top-level**. 클래스 내부 확장 함수는 *그 클래스의 멤버처럼* 동작하지만, 진짜 *유틸*이면 top-level이 깔끔.
- **빈 클래스 (확장 함수만 호스팅)는 객체 아님**. 멤버 없이 함수만 있으면 그건 함수 모음 = top-level 또는 object.
- **backing property** = `private var _xxx` + `val xxx: Type get() = _xxx`. Kotlin에서 외부 read-only + 내부 mutable의 표준 패턴.
