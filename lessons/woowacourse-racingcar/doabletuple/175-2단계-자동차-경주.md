## 얻은 교훈

- **data class 사용의 정당화 = 데이터 보유.** 행위가 있으면 일반 class. 코틀린 공식문서의 기준을 직접 확인하는 것이 가장 안전.
- **추측 대신 확인.** 학생이 "이렇게 동작할 것 같다"는 추측을 디컴파일 결과로 확인 → 자기 모델 보정. 리뷰어가 답을 주지 않고 도구를 안내한 가치.
- **방어적 복사의 자리.** 컬렉션을 반환할 때마다 외부 변경 가능성을 차단. `cars.toList()` 또는 `cars.toImmutableList()` 같은 보호.
- **object 선택의 정당화는 도메인 의미 + 라이프사이클** — "인스턴스 하나로 충분"은 충분하지 않은 정당화. "프로그램 전체에서 단 하나만 존재해야 한다"는 도메인적 의미가 있어야 object.
- **자기 학습 사이클이 가장 깊은 학습.** 학생이 공식문서 → 디컴파일 → 자기 모델 수정의 과정을 거치면 그 지식이 진짜 본인 것이 된다. 리뷰어는 가이드만 제공.
- **View → View 의존은 금지.** InputView가 OutputView를 알면 입출력의 책임 경계가 무너진다. 조립은 Controller의 일.
