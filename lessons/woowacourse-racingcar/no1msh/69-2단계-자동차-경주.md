## 얻은 교훈

- **object + 가변 상태는 안티패턴.** Object는 싱글톤이며 프로세스 동안 영속. 가변 상태가 있으면 멀티스레드/재실행 불가. object를 쓰려면 stateless 또는 thread-safe 보장.
- **테스트 데이터는 production 로직을 거치지 않는다.** `getCars()`로 데이터를 만들면 그 함수의 변경이 무관 테스트를 깨뜨림. 직접 하드코딩이 테스트 안정성.
- **View의 책임 경계 = 이름까지.** InputView가 도메인 객체(Car)를 만들면 도메인 생성 책임이 흩어진다. View는 raw 입력을 도메인이 받기 쉬운 형태(이름 리스트)로 전달.
- **`fun interface` + 람다 = SAM 패턴.** inner class로 inteface 구현하는 대신 fun interface 선언 후 `{ 1 }`처럼 람다로 넘김. 가독성 + 간결성.
- **함수 체이닝 한 줄 하나.** `cars.maxBy { ... }.position`보다 줄을 나누면 (1) 디버깅 쉬움, (2) 의도 단계가 보임, (3) 변경 시 영향 좁음.
- **에러 메시지에 입력값** = 디버깅 효율 + UX 동시 개선. 작은 변경의 큰 효과.
