## 못한 점 (설계 관점)

- **`Exception`이라는 클래스명** — 실제 Exception 타입과 혼동.
- **`","` 같은 매직 문자열**.
- **`Validator` 모호한 이름** → `InputValidator` 권고.
- **`올바르지 않은 레이싱 게임` 테스트명이 너무 포괄적**.
- **테스트가 랜덤 의존 (값을 임의로 넣어 회피)**.
- **Car가 랜덤 생성 책임 보유** — 도메인이 외부 비결정성에 의존.

## 리뷰어 의견 요지

리뷰어 @vagabond95의 메시지:

1. **클래스명 = 책임. `Exception` 접미사 ≠ 실제 Exception**. 실제 자바 Exception과 혼동 위험.

2. **모호한 이름 = 모호한 책임의 신호** — `Validator` → `InputValidator`. "정의할 수 있는 범위가 넓을 수 있도록 짓는 것을 지양."

3. **테스트 이름 = 한 시나리오 한 의미**. "올바르지 않은 레이싱 게임"은 너무 포괄적.

4. **Car ↔ 랜덤 연관 없음**. "클래스에는 꼭 해당 클래스에서만 수행하는 것이 적절한 함수만 남겨라."

## 얻은 교훈

- **클래스명에 *타입 시그널*을 잘못 넣지 말 것**. `Exception` 접미사는 *Exception 타입* 의미. 검증 객체엔 `Validator`/`Validation`.
- **클래스의 함수 = "그 클래스의 책임에 속하는가" 검증**. Car에 랜덤 생성 함수가 있다면 Car의 책임이 *움직임*+*랜덤*으로 흐림. 분리.
- **테스트 이름의 *정밀도***. "올바르지 않은 게임"은 5가지 실패 케이스 모두 포섭 → 어떤 실패인지 모름. 케이스별 분리.
