## 얻은 교훈

- **예외는 진짜 예외에만.** 사용자 입력 형식 오류 같은 "예상 가능"한 케이스는 null/Result/sealed로 표현. try-catch가 흐름 제어로 쓰이면 안티패턴.
- **무작위성을 매개변수로 격리.** `canMove: Boolean` 같은 추상 입력으로 결정 위임. 도메인은 무작위 표현 모름.
- **Expression body의 타입 생략 위험.** 추론 변경이 컴파일 에러 없이 다른 동작. 명시적 반환 타입이 안전.
- **테스트 클래스명 = production 클래스명 + Test.** `DomainTest`처럼 추상 명명은 무엇의 테스트인지 모호.
- **Service/Controller 테스트가 String 검증은 UI 결합.** 도메인 객체 비교로 의도 명확화.
- **자기 의문이 리뷰어의 명확한 답을 끌어냄.** 학생이 자기 모델을 적극 표명하면 리뷰어가 그것을 보강할 수 있는 토론이 만들어진다.
