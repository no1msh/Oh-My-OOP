- **`WinnerService` 같은 "Service" 접미사** — 객체보다 함수 모음에 가까움.

## 얻은 교훈

- **상태 없음 + 함수만 = object**. InputView, ValidationUtil처럼 인스턴스마다 다른 동작을 안 가지면 object가 정답.
- **EOL 문제는 *근본 이해*가 진짜 학습**. CR vs LF + POSIX + gcc까지 파고들면 "왜 안 되는가"가 명확. 표면 해결 (체크박스만 켜기)은 다음에 또 만남.
- **try-catch → runCatching 이행**. Kotlin idiom의 흐름. 다음 라운드의 피드백 예고편.
- **커밋 메시지 중복 = 책임 단위 모호의 신호**. 두 번 같은 메시지가 보이면 "이 두 변경이 *실제로 다른 작업*이었는가" 자문.
- **`Service` 접미사의 의문**. 백엔드 관습이지만, 상태 없는 함수 모음이면 object 또는 top-level fun으로 충분. 굳이 Service 인스턴스가 필요한가?
