## 리뷰어 의견 요지

리뷰어 @RightHennessy는 **"질문 + 자료 링크"**로 학생의 추가 학습 유도.

1. **data class vs record** — "왜 data class를 썼는가? 자바 record와 차이는?" → 페어가 5가지 차이점 정리 (copy, var/val, 비구조화, 상속, 인스턴스 프로퍼티). 그리고 역질문 "Sample1 vs Sample2 차이는?" → 리뷰어가 답: `equals/hashCode`는 주 생성자만 고려 → 주 생성자 밖 프로퍼티는 동치성 비교에서 빠진다.

2. **`maxOf` vs `maxBy`** — "최댓값" vs "최댓값을 가진 객체". 도메인 표현(우승자는 객체)에 맞는 함수.

3. **`map`의 반환 = `List<T>`** — `filter().map()`이 List를 만드는데, 호출자가 또 List로 감싸 이중 작업.

4. **Car.position 캡슐화** — 외부 접근 가능. `private set` 권장.

5. **smart cast** — `val input = readLine() ?: throw IllegalArgumentException()` 이후 컴파일러가 input을 non-null로 추론 → 반환 타입을 nullable로 유지할 필요 없음.

학생과 리뷰어가 **양방향 질문**으로 진행 — 학생이 역으로 퀴즈를 내고 리뷰어가 답하는 흥미로운 상호작용.

## 얻은 교훈

- **data class의 `equals/hashCode`는 주 생성자만 본다.** "본문에 선언한 프로퍼티"는 동치성 비교에서 빠짐. VO를 만들 때 모든 식별 속성은 주 생성자에 넣어야 함.
- **`maxOf` vs `maxBy`의 의미 차이.** 도메인이 "우승자(객체)"를 표현해야 하면 `maxBy`. "거리(스칼라)"라면 `maxOf`. 함수 이름이 도메인 의도를 반영.
- **일급 컬렉션의 변환 = 한 번만 감싼다.** `cars.filter().map()`의 반환이 `List<Car>`인데 다시 `Cars(it)`로 감싸야 하면 중간에 List를 두는 게 의미 없음.
- **smart cast로 nullable의 흐름 종결.** null 검사 후 컴파일러가 non-null로 좁히면, 반환 타입까지 non-null로 끌어올림. throw 한 줄로 도메인이 깨끗.
- **페어 프로그래밍의 가치 = PR에 토론이 보임.** "왜 이렇게 했는가"가 두 사람의 합의로 들어오면 리뷰가 그 합의를 검증하는 단계로 격상.
- **양방향 질문 = 깊이의 신호.** 학생이 "이 두 코드의 차이가 뭘까요?"로 역질문하면 리뷰어가 자료를 인용해 답하면서 토론의 격이 올라감.
