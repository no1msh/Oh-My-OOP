## 얻은 교훈

- **일급 컬렉션 표준 패턴**: 단일 `List<T>` 필드 + 생성자에서 받기 + `get()`/`size` override + companion object 팩토리.
- **getter 선언 ≈ 캡슐화 안 함**. 같은 효과. 진짜 캡슐화는 "외부 로직을 객체 안으로 가져오기" — Tell Don't Ask.
- **방어적 복사 = 컬렉션 노출의 의무**. 내부 List를 노출하면 외부에서 `add()`로 도메인 invariant 깨질 수 있음. `toList()` / `unmodifiableList`로.
- **테스트 코드의 *의도*는 본문에서 보여야**. 테스트 함수명도 중요하지만, 본문만 봐도 "왜 이 결과가 나오는가"가 명확해야.
- **`Cars.move()`의 *반환값* 설계**. 차량을 다 움직인 후 결과를 어떻게 외부에 보여줄까 — 새 Cars 반환? 결과 List<Position>? "외부와의 결과 공유" 방식이 일급 컬렉션 design의 일부.
