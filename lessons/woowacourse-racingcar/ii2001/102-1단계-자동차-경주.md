## 리뷰어 의견 요지

리뷰어 @vagabond95의 메시지:

1. **함수 이름 = 동사형 (코드 컨벤션)**.

2. **도메인 타입 = 도메인 의미를 반영** — position이 *증가/감소 가능한 성질*이면 Int. String으로 두면 표현 형식이 도메인을 침범.

3. **함수 모음 파일 → 클래스로 묶기**. 함수만 노출하면 Controller가 비즈니스 로직을 *직접 호출*. MVC의 model 의미가 없어짐.

4. **테스트 커버리지 = 입력 검증 + 자동차 움직임 필수**.

- **대표 인용:**
  > position 을 String 타입으로 선언해주신 것은 실제로 postiion 을 표현 할 때 String 타입으로 이용되기 때문이라고 생각되는데요. model 의 경우 보통 도메인을 표현하는 영역이므로 실제 동작의 속성을 지켜주면 좋다고 생각합니다. position 은 증가(혹은 감소) 할 수 있는 성질이 있으므로, 숫자 타입으로 선언되면 좀 더 활용할 수 있는 범위가 넓지 않을까요~?

## 얻은 교훈

- **도메인 타입 ≠ 표현 형식**. position이 표시에 String으로 쓰이더라도, 도메인은 *Int* (증가/감소 가능한 성질). 표현은 OutputView가 변환.
- **함수만 노출하는 model = 책임 누수**. Controller가 함수들을 직접 부르면 비즈니스 흐름이 Controller에 모임. model이 클래스로 묶여야 책임이 분배.
- **테스트 부재 = 검증 의지 부재**. "이 검증이 가치 있다"고 판단해서 model로 옮겼다면 *반드시* 테스트.
