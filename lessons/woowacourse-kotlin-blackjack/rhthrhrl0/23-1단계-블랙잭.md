### 1. `점수 계산 Dealer 책임` + `Player vs Player 비교 어려움` — 말리빈 매우 긴 답변 + 그림 첨부

> *"점수를 계산하는 부분은 Dealer만 가지고 있으면 좋겠어요. 플레이어와 플레이어는 사실 경쟁 상대가 아니기 때문이에요. 플레이어끼리 결과를 비교하면, 어떤 플레이어가 이겼는 지 알기도 어려울 것으로 예상돼요. (Player.getGameResult()) 또, 승패를 결정하는 룰은 딜러와 플레이어 간 연관이 있기도 해서요. 그러면 자연스럽게 Players 에게 메시지를 던지는 형태도 사라질 수도 있겠어요 :) 멘델의 생각은 어떠신가요?"*

학생 자가 답변 (자가 정당화):

> *"저는 플레이어의 승패가 딜러보다 먼저 결정나고('플레이어가 버스트 된다면 플레이어는 딜러가 버스트 되더라도 진다'라는 규칙) 또한, 딜러의 승패 종합 결과는 플레이어들에 의해 정해진다고 생각했습니다. 그래서 플레이어 기준의 승패 결과가 중요하다고 생각을 해서 플레이어쪽에 게임 결과 반환 메소드가 있는것이 적절할것 같다고 생각했습니다. 그래서 이번에 수정하면서 딜러쪽에서 게임의 승패를 반환하는 메소드는 제거 시켰습니다. 혹시 수정 이후에도 아직 부자연스러워 보이시면 해당 로직을 딜러쪽으로 이동시켜보겠습니다!"*

말리빈 매우 긴 답변 (3 메타 시점 + 그림 첨부):

> *"저는 딜러쪽이 좀 더 특수하다고 생각해요 :) 일반적이라면 카드 점수와 개수 만으로 결과가 나오지만, 블랙잭의 경우는 딜러가 블랙잭일 때 특수 룰이 적용된다 생각해요. 그리고 현실 세계에서는 딜러가 결과를 알려주기 때문이에요.*

> *위 같은 의견도 있지만, 아래는 제 개인적인 의견입니다 ㅎ_ㅎ 저는 딜러도, 플레이어도 아닌, 그 부모 객체인 Participant에 위치해도 좋다는 생각이에요. 사실 결과 자체는 누가 가지고 있는 지 보다, 카드더미만 있으면 알 수 있으니까요.*

> *좀 더 의존 관계에 대해 짚어보면, 현재는 플레이어는 Dealer를 알고 있습니다. (의존 관계 그림 첨부)"*

학생 후속 답변: *"열정적으로 피드백과 의견을 달아주셔서 감사합니다! 말리빈님의 글을 읽어보니 왜 그렇게 하기를 원하셨는지 알겠습니다. 더 수정해보겠습니다!"*

→ **4 가지 메타 학습**:

#### 1.1. *점수 계산 책임 위치 = 3 후보*

- (A) **`Dealer.compareResult(player)`** — 말리빈 *공식 의견*. *블랙잭 특수 룰 (딜러 블랙잭) + 현실 메타포 (딜러가 결과 알려줌)*.
- (B) **`Player.getGameResult(dealer)`** — 학생 자가 선택. *플레이어 승패가 딜러보다 먼저 결정 + 플레이어 기준 결과 중요*.
- (C) **`Participant.compareWith(other)`** — 말리빈 *개인 의견*. *카드더미만으로 결과 알 수 있음 + 의존 관계 단순*.

#### 1.2. *플레이어 vs 플레이어 비교 어려움*

말리빈의 핵심 진단 = *"플레이어와 플레이어는 사실 경쟁 상대가 아니기 때문이에요. 플레이어끼리 결과를 비교하면, 어떤 플레이어가 이겼는 지 알기도 어려울 것으로 예상돼요."*

→ **블랙잭 도메인 룰 = *플레이어 vs 플레이어 비교 X***. *각 플레이어 vs 딜러 1:1 비교*. *학생의 `Player.getGameResult()` = "이 플레이어가 이겼는가" 의 *상대* 가 불명확*.

대안:
- **`Player.getGameResultAgainst(dealer)`** — 명시적 상대.
- **`Dealer.compareResult(player)`** — 딜러 기준 (위 A).

#### 1.3. *현실 메타포 + 도메인 룰 = 같은 결*

*"현실 세계에서는 딜러가 결과를 알려주기 때문이에요"* — *현실 메타포 = 딜러가 결과 발표* + *도메인 룰 = 딜러 vs 각 플레이어 비교* = **같은 결**. PR #70 (chaehyuns 1단계) 의 *현실 메타포 (Dealer 판단) vs 확장성 (Participant vs Participant)* 트레이드오프 결.

#### 1.4. *공식 의견 + 개인 의견 분리 메타 어휘*

말리빈의 *"제 개인적인 의견입니다 ㅎ_ㅎ"* — *공식 권고 (Dealer 책임)* + *개인 의견 (Participant 부모 책임)* 명시 분리. **MCP `oh-my-oop` 의 *단일 답 X + N개 대안 + 트레이드오프* 어휘와 일치**. PR #95 (말리빈 *"옳고 그름 없고 장단점만"*) 결.

PR #74 (송핑크 *Referee*) / PR #148·#151 (krrong *역할 vs 상태*) / PR #49·#132 (참가자 vs 참가자 일반화) 결.

### 5. `Cards(Set<Card>)` — 여러 벌 카드 요구사항 시 한계

말리빈: *"Cards를 생성할 때 Set을 받으셨네요! 중복된 카드를 받지 않을 수 있는 장점이 생길 수 있지만, 블랙잭 게임에서 여러 벌의 카드를 사용하는 요구사항이 추가되면 어떤 일이 생길 수 있을까요?"*

→ **자료구조 선택 트레이드오프**:
- **`Set<Card>`** = *중복 차단 + 카드 1벌 한정*. *여러 벌 사용 시 동일 카드 중복 = Set이 차단 → 동작 깨짐*.
- **`List<Card>`** = *순서 + 중복 허용 + 여러 벌 가능*.
- **`MutableList<Card>` + draw 시 remove** = *덱 자료구조 + 카드 소진 모델링*.
- **`ArrayDeque<Card>`** = *FIFO 덱 + draw 효율*.

**MCP 룰 후보 — `set-vs-list-multiset`** = *중복 허용 시나리오 검토*. PR #58 (otter66 *카지노 6덱 메타포*) 결.

> *그렇다면, 이 모든 변경 가능할 요소들을 domain이 가지고 있는 게 맞을 지에 대한 질문이었어요!"*

→ **3 가지 메타 학습**:

#### 6.1. *학생 자가 의문 = 학습 모범*

*"이모지를 써야하는 이유를 잘 모르겠습니다!!"* = *reviewer 의 *의도* 가 학생에게 닿지 않음 + 자가 명시*. **학습 갭 명시 모범**. PR #95 (송핑크 *"이해를 못했습니다"*) 결.

#### 6.2. *reviewer 부연 = 의도 명시*
