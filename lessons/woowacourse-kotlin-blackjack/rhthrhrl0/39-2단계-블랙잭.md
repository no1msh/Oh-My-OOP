### 1. `NameAndBet` 명명 + `PlayersNameAndBet` 일급 컬렉션 과적용

말리빈 진단 1: *"플레이어의 정보를 나타내고 싶은 class 같은데, 이름에 큰 의미를 부여하긴 어려워 보이네요. 더 나은 이름을 고민해볼까요? 🤔"*

말리빈 진단 2: *"이 객체는 값을 갖고만 있고, 특별한 역할을 하지 않아 쓸모를 느끼기 어려워요. 모든 컬렉션을 반드시 일급 컬렉션으로 래핑할 필요는 없다고 생각해요 🙂"*

→ **2 가지 학습**:

#### 1.1. *`NameAndBet` = and 접속어 명명 안티패턴*

- *`NameAndBet`* = *Name + Bet 두 속성 이어붙임* = *도메인 어휘 X + 책임 모호*.
- 대안:
  - **`PlayerInfo`** — 추상 명사, 여전히 모호.
  - **`PlayerProfile`** — *기본 정보 + 베팅 = "프로필"* 어휘.
  - **`Bettor` / `PlayerRegistration`** — *책임 (베팅하는 자 / 게임 참가 등록 정보) 중심*.
- **MCP 룰 후보 — `and-conjunction-name`** = *Name + Bet, Hand + Wallet 같은 *접속어 명명* 검사*. PR #133·#88·#132·#136·#93 의 *3 변수 제약 부산물 인공 객체* 결.

#### 1.2. *모든 컬렉션 일급 X — 일급 컬렉션 과적용 안티패턴*

- *`PlayersNameAndBet`* = `List<NameAndBet>` 일급 화 + *행동 없음*.
- *일급 컬렉션 = *컬렉션 + 도메인 행동* 의 조합*. *행동 없는 일급 화 = 의미 없는 래퍼*.

**MCP 룰 후보 — `first-class-collection-without-behavior`** = *lotto 의 `collection-wrapper-without-behavior` 변형*. PR #133·#74·#108·#99 의 *일급 컬렉션 자가 학습* 결의 *역효과*.

### 3. `Cards.deepCopy` — *정말 deepCopy 인가?*

말리빈: *"deepCopy가 정말 필요할까요? 정말로 'deepCopy'가 이루어지고 있을까요?"*

→ **2 가지 메타 의문**:

#### 3.1. *deepCopy 필요성*

- *Cards 가 불변이라면 deepCopy 불필요* — *동일 인스턴스 공유 무해*.
- *Cards 가 가변이라면* deepCopy 정공.
- *학생 코드 = *불변 의도* 인데 deepCopy 잔재* = **불필요한 방어**. 

#### 3.2. *정말 deepCopy 인가?* — 명명 vs 실제

- *`deepCopy()`* 명명 = *재귀적 깊은 복사 의미*.
- *학생 코드*가 *얕은 복사 (shallow copy, e.g., `cards.toList()`)* 라면 *명명 거짓*.
- **MCP 기존 룰 `defensive-copy-on-immutable`** (batch 10·11) + *명명 정확성*.

PR #137·#148 의 *방어적 복사 강박 자가 학습* 결.

### 4. `Cards 불변 의도 + 가변 내부` + 매번 계산

말리빈: *"Cards를 불변 객체로 만들어주신 것 같아요. 불변 객체를 의도하셨지만 내부는 가변 객체를 가지고 있네요 :) 반드시 가져야할 가변 객체일까요? 컬렉션에도 + operator가 오버로딩 되어있답니다 😊 또, 불변 객체이면, 위 프로퍼티들을 호출할 때마다 계산하는 함수들을 매번 호출해주어야할까요?"*

→ **3 가지 학습**:

#### 4.1. *불변 의도 + 가변 내부 = 의도 누수*

- *`Cards(val cards: List<Card>)`* — *List 자체는 불변 인터페이스* 이지만 *백킹 객체가 `MutableList`* 라면 *외부 캐스팅으로 변경 가능*. PR #74 (송핑크 *불변 객체 자가 학습*) 결.

#### 4.2. *컬렉션 `+ operator` 오버로딩*

- *`cards + newCard`* = *불변 List + 새 Card → 새 List 생성*. Kotlin 표준 라이브러리.
- *학생 코드의 `add(card: Card): Cards = Cards(this.cards + card)` 같은 형태* 가 정공.

#### 4.3. *불변 + 매번 계산 함수 호출 = 비효율*

- *`fun sum() = cards.sumOf { it.value }`* — *매 호출마다 N 회 합산*.
- *불변 객체 + 생성 시점 계산* = *`val score: Int = cards.sumOf { it.value }`* 한 번 + 캐시.

**MCP 룰 후보 — `immutable-recompute-on-call`** = *불변 객체의 비싼 계산이 매 호출마다 반복 = 캐싱 정공*.

## 얻은 교훈

1. ***모든 컬렉션 일급 X — 일급 컬렉션 과적용 안티패턴*** — *행동 없는 일급화 = 의미 없는 래퍼*. **MCP 룰 후보 `first-class-collection-without-behavior`** (lotto `collection-wrapper-without-behavior` 변형). PR #133·#74·#108·#99 의 *일급 컬렉션 자가 학습* 결의 *역효과*.

2. **`and 접속어 명명`** = *`NameAndBet`, `HandAndWallet` 같은 *두 속성 이어붙임* = *도메인 어휘 X + 책임 모호***. **MCP 룰 후보 `and-conjunction-name`**. PR #133·#88·#132·#136·#93 의 *3 변수 제약 부산물 인공 객체* 결.

3. **불변 의도 + 가변 내부 = 의도 누수** — *`Cards(val cards: List<Card>)` + 백킹 `MutableList` 가능*. *kotlin 의 List 인터페이스 자체는 불변 보장 X*. PR #74 (송핑크 *불변 객체 자가 학습*) 결.

4. **불변 객체 + 매번 계산 함수 호출 = 비효율** — *`val score: Int = ...`* 1회 계산 vs *`fun score() = ...`* N회 계산. **MCP 룰 후보 `immutable-recompute-on-call`**.

5. ***deepCopy 명명 vs 실제* 의문** — *명명 = 깊은 복사 의미 + 실제 = 얕은 복사 가능성*. **명명 정확성 + 방어적 복사 강박** — PR #137·#148 의 *defensive-copy-on-immutable* 결.

6. **State 객체 외부 주입 = 테스터빌리티** — *Participant(state: State = InitialState)* = *임의 상태 시작 시뮬레이션 가능*. PR #98 (chaehyuns *State 객체 데이터 최소화*) 결.

7. **랜덤 = 가장 바깥 계층으로 끌어올림 (Functional Core, Imperative Shell)** — *내부 = 결정적 + 외부 = 랜덤 주입*. PR #74·#23·#95·#99·#26 의 *Random 테스트* 결.

8. **객체 생성 방식 = 명확한 의도 (factory vs constructor)** — *기본 = primary, 변형 = secondary, 복잡 = factory*. *동일 코드베이스 내 일관성*. **MCP 룰 후보 `factory-vs-constructor-inconsistency`**.

9. **`Phase` 추상화 = 학생의 창의적 발상** — *진행 단계 객체화 → View 분리 + 흐름 명시*. PR #98 (chaehyuns State 패턴) / PR #99 (s6m1n 람다 콜백) 와 다른 *제3의 추상화*. **`phase-pattern`** = *블랙잭 진행 단계를 객체 시퀀스로 표현* — 도메인 특수 패턴.

10. **학생 *상태 패턴 처음* 자가 사과 + reviewer 인정 = 학습 진화 모범** — *PR 본문 자가 사과 + 머지 시점 reviewer 인정 + 학생 자가 회고 (다음 미션 적용)* 3 단계. PR #98 (chaehyuns *추후 시간 될 때 다시*) / PR #95 (송핑크 *처음부터 다시 만들어보기*) 결.

11. **PR 본문 + 1단계 PR URL 자가 참조** — *2단계 학생이 *1단계 코멘트 답변 + PR URL 첨부*. *양 단계 본 reviewer 만 가능한 학생 자가 학습 가시화*. PR #99·#95 결.

12. **suggestion 블록 활용 (Kotlin 표현식 함수)** — `if return true else return false` → `return ...`. PR #26 (잭슨 `isPossibleDrawCard`) 결.
