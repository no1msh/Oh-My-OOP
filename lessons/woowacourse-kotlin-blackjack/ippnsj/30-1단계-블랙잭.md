## 못한 점 (설계 관점)

### 1. 에러 메시지 inline String template vs 상수 (Thread 0) — 핵심

reviewer:

> *"개인적인 컨벤션으로는 항상 inline으로 작성합니다. 그 이유는 예외가 발생했을 때의 변수들을 에러 메시지에 담아놓아야 다음에 에러가 발생했을 때, 디버깅이 쉬워지기 때문입니다. **inline으로 작성하면 String template을 통해 가독성있게 작성할 수 있는데 이를 상수로 분리하면 `%s`와 같이 작성하고 `String.format()`을 써야하기 때문이에요.***
>
> *현재 코드를 예시로 들자면, 추후 여기서 예외가 던져져서 로그 툴에 쌓이더라도 예외 메시지가 `number`를 담지 않았으므로 `number` 값이 무엇인지는 알 수가 없습니다."*

학생 자가 답변: *"format 함수를 사용하는게 오히려 가독성을 해칠 수 있겠네요! 감사합니다!ㅎㅎ😆"*

→ **MCP 룰 `error-message-as-inline-string-with-template`** ⭐⭐⭐ **신규 정점** — *상수화 = `%s` + `String.format()` 필요 = 가독성 X + 변수 누락 / inline String template = 디버깅 변수 포함 가능*. **단일 답 아님** (개인 컨벤션) + reviewer 어휘 *"개인적인 컨벤션"* — MCP `oh-my-oop` 핵심 가치 어휘.
