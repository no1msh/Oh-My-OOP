### 6. `sealed interface vs abstract class vs open class` — Kotlin 어휘

reviewer (Thread 8):

> *"- sealed interface*
> *- abstract class*
> *- open class*
> *이 세가지의 차이점과 용도는 어떻게 될까요? 고민해보시고 블랙잭 미션에서는 어떤 키워드가 어울릴지 고민해보시고 저에게도 공유해주세요!"*

학생 자가 답변:

> *"abstract class와 sealed interface 모두 추상화를 제공하지만, abstract class는 공통된 로직을 미리 구현하여 하위 클래스에서 재사용할 수 있도록 강제하는 반면, interface는 구현해야 할 틀만 제공하고, 모든 로직을 하위 클래스에서 직접 작성해야 한다는 차이가 있습니다. open class는 일반 클래스를 어디서든 상속 가능하도록 하지만 그렇기 때문에 의도를 잘못 이해했다면 잘못된 방식으로 기능이 변경될 위험이 있다고 알고 있습니다."*

→ **Kotlin 어휘 3 가지 트레이드오프**:

| 키워드 | 의도 | 적합 시점 |
|---|---|---|
| `sealed interface` | *알려진 자식 한정 + 다형성 분기 (when exhaustive)* | *자식이 한정 + 상태/이벤트 표현* (Bust/Normal/Blackjack 같은 State) |
| `abstract class` | *공통 로직 + 추상 메서드* | *자식 공통 로직 + 차이는 추상 메서드 (Participant)* |
| `open class` | *상속 허용 (의도 약함)* | *드물게 사용 + Java 호환* |

학생 최종 선택: **`abstract class Participant`** — *공통 로직 (finalScore, isBust, receiveCard) + 추상 메서드 (showInitialCards, isDrawable, getResult)*. **정확한 의도 매핑**.

**MCP 룰 `sealed-vs-abstract-vs-open-locator` 후보** — *Kotlin 키워드 선택 트레이드오프*. PR #98·#36·#147·#93·#136 결의 *sealed vs enum vs abstract* 변형.
