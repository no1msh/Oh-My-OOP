### 4. `init` 함수 재사용 vs 최초 초기화 (Thread 2)

reviewer: *"init 함수는 매번 재사용 하는 것을 고려하신걸까요~? 재사용이 아니라 최초 초기화가 목적이라면, 매번 함수를 호출할 수 없도록 구조를 변경해봐도 좋을 것 같아요."*

학생 자가 답변:

> *"해당 함수를 구현한 이유는 재사용의 목적도 일부 있었습니다. 하지만 최초 초기화를 진행하지 않았던 가장 큰 이유는, **프로그램의 전체적인 흐름에서 보았을 때 플레이어가 얼마를 베팅하겠다는 것은 블랙잭 게임의 과정 중 일부라고 생각**했기 때문입니다. 그래서 `BlackJackGame`의 내부 로직에서 베팅금을 입력받고 설정(초기화)하는 것이 자연스럽다고 판단했기 때문에, 일부러 초기화를 진행하는 init 함수를 따로 구현하였습니다."*

→ **MCP 룰 `init-fn-reusable-vs-init-only`** ⭐⭐ 신규 — *init 함수 = 재사용 vs 최초만 + 흐름 정합 학생 자가 정당화*. PR #12 (`init-name-implies-no-return`) 결 합류.

### 8. companion object function — 인스턴스화 불필요 (Thread 8)

```kotlin
// 변경 전 - 매번 객체 생성
class GameResult(val win: Int = 0, val push: Int = 0, val defeat: Int = 0) {
    fun win(): GameResult = GameResult(win = 1)
}

// 권장 - companion object function
companion object {
    fun win(): GameResult = GameResult(win = 1)
}
```

reviewer: *"이 부분은 companion object funtion 으로 제공해도 되지 않을까요? 굳이 객체를 만들고 함수를 호출할 이유가 없어보여요."*

학생 자가 답변:

> *"말씀대로 승리, 무승부, 패배를 1씩 증가시키기 위해 매번 객체를 새로 생성할 필요가 없어보입니다. companion object 내부에서 승리, 패배, 무승부 시의 `result`를 정의하였고 companion object function으로 해당 `result`들을 반환하도록 바꾸어보았습니다."*

→ **MCP 룰 `companion-object-fn-for-reuse-instead-of-instantiation`** ⭐⭐⭐ 신규 — *companion object function = 인스턴스화 없는 재사용 어휘*. PR #154 (`reviewer-kotlin-tip-vocabulary`)·PR #18 (`enum-companion-init-order`) 결 합류 누적 3 PR.
