### 2. 3개 인스턴스 변수 원칙 = 가이드 / 절대 X (Thread 6) — 정점

학생 자가 의문 정점:

> *"또 미션 요구 사항 중 `3개 이상의 인스턴스 변수를 가진 클래스를 쓰지 않는다.`라는 사항이 있는데, `Player`클래스에서 `name`,`bet`,`cards` 이렇게 3개의 인스턴스 변수를 가지고 있는데 `bet`과 `cards`를 `BetInfo`새로운 클래스로 분리한다고 하면 `Player` 클래스는 단순히 `name`과 `BetInfo`라는 **두개의 상태를 가지고 있고 역할은 없는 클래스로 변한다고 생각**됩니다.*
>
> *혹시 해당 요구 사항을 지키기 위해 제가 다른 관점에서 생각해볼 점이 있는지 궁금합니다!"*

reviewer:

> *"지금 상황에서는 오히려 나누지 않는게 더 나아보입니다.*
>
> *해당 요구사항은 클래스를 잘게 나누도록 가이드하는 하나의 원칙일 뿐입니다. **원칙을 따르는 것은 좋지만 절대적으로 항상 올바른 원칙은 없기에 모든 경우에 적용시켜서는 안됩니다.**"*

→ **MCP 룰 `principle-as-guide-not-absolute`** ⭐⭐⭐ **신규 정점** — *3 인스턴스 변수 원칙 = 가이드 / 절대 적용 X*. PR #38 (`primitive-fn-conversion-as-temporary-fix` 임시 방편 vs 본질)·PR #62 (`mutable-team-policy-no-single-answer`)·PR #43 (`responsibility-of-judging-no-single-answer`) 결 합류 누적 **4 PR 원칙 vs 본질 단일 답 거부 정점**.

→ **MCP 룰 `forced-class-division-without-role`** ⭐⭐⭐ 신규 — *역할 없는 클래스 분리 = 분리 X 권유*. PR #42 (`info-suffix-as-misplaced-data` PlayerInfo) 결 합류 누적 2 PR.

→ **MCP `oh-my-oop` 핵심 가치 학생 측 메타 어휘** — *원칙 준수 vs 역할 명시 학생 자가 의문* = 도구 핵심 가치 (책임-역할-협력) 학생 측 자각.
