## 못한 점 (설계 관점)

### 1. `Hand(cards: List<Card>)` 외부 가변 참조 — *방어적 복사 자가 인식*

```kotlin
val cards = mutableListOf(card1, card2, card3)
val hand = Hand(cards)
cards.clear()
```

크롱 진단 (Hand.kt — 미해결): *"어떤 일이 발생할 수 있을까요?"*

학생 자가 답변: *"cards의 리스트가 비워지게 됩니다. `Hand`가 `cards`를 직접 참조하고 있기 때문에, 외부에서 `cards`에 변경이 일어나면 `hand`가 들고 있는 카드에도 변경이 일어나게 됩니다. 그래서 Hand 내부에서도 `fun getCards(): List<Card> = cards.toList()` `toList()` 연산자를 사용해서 얕은 복사가 가능하도록 구현했었습니다. 혹시 해당 방법이 틀렸던 것일까요? 😰"*

→ **`toList()` getter = *읽기 방어*** + **생성자 인자 직접 참조 = *쓰기 방어 0***. *비대칭 방어*. *생성자에서 `cards.toMutableList()` 사본*이 *읽기 + 쓰기 양쪽 방어*. PR #108·#132·#133·#85·#58 와 같은 결의 *MutableList 인자 함정*.

→ **enum + when exhaustive = else 불필요 = 컴파일러 보장**. *새 enum 멤버 추가 시 when 안 채우면 컴파일 오류*. *Kotlin 패턴 매칭 정공*. PR #137·#136·#93·#90 와 같은 결.

### 3. `DealerResult` 가 *GameResult 와 중복*

크롱 진단 (DealerResult.kt — 미해결): *"`DealerResult`가 하는 일은 아래와 같은 이유로 `GameResult`로 대체할 수 있는 것처럼 보입니다. 1. 플레이어의 경기 결과를 기반으로 딜러의 경기 결과를 계산할 수 있다. 2. 플레이어의 수익을 기반으로 딜러의 수익을 계산할 수 있다."*

### 4. `Hand` 의 *블랙잭 = 21 무조건* 룰 부정확 — 자가 학습

학생 자가 후속 반영 (인용 PR #151 jerry 케이스 유사): *"그 전에는 합계가 21이면 블랙잭 상태로 바꾸는 것이였습니다. 따라서, Blackjack 객체에서 카드를 처음 나누어주는 메소드에서만 판단하기만 하면 되었기 때문에 합계가 21이면 무조건 블랙잭으로 되도록 하였습니다.😅 하지만, Hand객체의 status변수가 없어진 지금은 카드의 size가 두장임을 판단하여 블랙잭이 되도록 수정하였습니다!💪"*

### 11. `setPlayerStatus → getPlayerStatus` 함수명 자가 학습

학생 자가 인용: *"또한, `setPlayerStatus`라는 함수명이 실제로는 승패 결과를 반환하는 함수였기 때문에, 그 함수명이 직관적이지 않다는 점도 깨달았습니다. 따라서 `getPlayerStatus`와 같이 승패를 반환하는 의미가 명확한 함수명으로 변경했습니다"*

## 리뷰어 의견 요지

- **역할 vs 상태 명확 구별** — *역할 = 행위 주체*, *상태 = 변하는 값*. *Player = 역할*, *GameResult = 상태*.

- **베팅금 vs 수익 분리** — *베팅금 = 불변*, *수익 = 결과 + 베팅금*.
- **enum + when exhaustive = else 불필요 = 컴파일러 보장**.
- **MutableList 인자 직접 참조 = 외부 변경 함정** — *cards.toMutableList() 사본*.

- **`addCard` 재활용 = vararg/list 인자**.
- **`Listener` vs 고차함수 콜백 트레이드오프** — *학생 자가 결정 = Listener*.
- **`setXX` vs `getXX` 어휘** — *반환 = get, 설정 = set*.
- **함수 호출 순서 = 정의 순서** — 가독성.
- **린트 = PR 위생** — *시간 부족 ≠ 무시*.

## 얻은 교훈

1. ***역할 vs 상태 명확 구별 = OOP 핵심 개념***. *Player = 승패 판단 역할 (행위 주체)*, *GameResult = 승패 결과 상태 (변하는 값)*. *학생 자가 인식 + 메타 학습 모범*. **MCP 룰 후보 — `role-state-conflation`**.
