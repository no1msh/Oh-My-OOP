### 1. `BettingMoney * Int` 메서드 폭증 → `operator times` 오버로딩

말리빈 진단: *"1~10000개의 곱셈이 생긴다면 1만 개의 메서드가 생겨야할까요? BettingMoney를 불변 객체로 만들어주셨으니, BettingMoney자체를 곱셈할 수 있게, multiply operator를 오버로딩 해보는 것을 도전해보세요 :)"*

학생: *"`operator fun times(d: Double)` 을 사용해서 multiply operator를 오버로딩 해보았습니다!"*

→ **3 가지 학습**:

#### 1.1. *극단 사례 메타 어휘 — "1만 개"*

말리빈의 *"1~10000개의 곱셈이 생긴다면 1만 개의 메서드가 생겨야할까요?"* — **극단 사례 (reductio ad absurdum) 메타 어휘** = *현재 코드의 *한 사례 (× 2, × 3)* 가 *변경 요청 시 N 회 반복* 됨을 학생에게 자가 명시*. **MCP `oh-my-oop` 의 *변경 시 비용* 어휘**.

#### 1.2. *Kotlin operator overloading 어휘*

- *`operator fun times(d: Double): BettingMoney`* → *`BettingMoney(1000) * 4`* 표기.
- *Java/일반 OO 어휘*: `multiply(int)` 메서드.
- *Kotlin 의 *연산자 오버로딩* 어휘 = 도메인 객체에 *수학 연산* 명시*.

#### 1.3. *불변 객체 + 새 객체 반환 정공*

- *`times` 가 *새 BettingMoney 반환* = 불변성 유지.
- *호출 측: `val newMoney = oldMoney * 2`*.

### 2. `data class private primary constructor` 함정

말리빈 진단: *"data class의 private primary constructor는 컴파일러가 경고하듯, 의미가 없습니다. class로 변경해보는 것은 어떨까요?"*

### 4. `BettingMoney 곱셈 → BettingMoney 반환 vs Int` 자가 토론

- **수익률 ≠ 베팅 머니** — *별도 타입 (예: `Profit`) 또는 *원시 Int 사용*.

#### 4.2. *학생 자가 의문 + reviewer 답변 후 *trade-off 인정***
