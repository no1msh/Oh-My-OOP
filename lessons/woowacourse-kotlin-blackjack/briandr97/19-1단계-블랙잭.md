### 2. Kotlin 어휘 자가 학습 정점 (sealed interface + enum vs sealed)

학생 자가 학습 (Thread 12):

> *"sealed interface가 존재하는지 몰랐습니다! 뭔가 코틀린 인 액션에서 sealed interface는 안된다는 식으로 봤었던 것 같아 존재하는지 몰랐었는데 이번 기회를 통해 알 수 있게 되었습니다! 감사합니다!*
>
> *찾아본 결과 sealed class와 sealed interface의 차이점은 추상 클래스냐 인터페이스냐로 다중 상속을 가능하게 하는가?로 이해하였습니다."*

학생 자가 학습 (Thread 14):

> *"enum과 sealed의 큰 차이점은*
> *- enum에서는 하나의 인스턴스만을 갖고 sealed에선 여러 인스턴스를 생성할 수 있다.*
> *- enum에선 모두 같은 생성자를 가져야하지만 sealed에서는 다른 형태의 생성자를 가질 수 있다.*
>
> *그런데 현재 제 코드에선 sealed class의 서브 클래스들이 object로 선언되어있습니다. 이 경우 여러 인스턴스를 생성할 수 있고 여러 형태의 생성자를 가질 수 있다는 sealed의 이점이 사라져 enum과 거의 동등한 상태가 되는 것 같습니다."*

reviewer 자가 답변 (Thread 14):

> *"공식 docs 에서, enum 의 정의를 보면 다음과 같이 나오고 있습니다. `Each enum constant is an object`. 즉, enum 은 의미 그대로 상수의 집합이라고 보시면 될 것 같아요.*
>
> *반면, sealed class 는 말그대로 자식의 확장을 정확하게 제한하는 역할을 할 수 있습니다. enum 처럼 쓸 수도 있지만, 그보다 좀 더 확장시켜 클래스의 집합이라고 보셔도 좋을 것 같아요.*
>
> *당장은 이정도만 생각을 해두고, 구현해나가면서 장/단점과 사용처를 경험으로 익혀보시는 것도 좋겠습니다."*

→ **학생 자가 깊은 학습 + reviewer 공식 문서 인용 + 학생 부담 최소화** = *MCP `oh-my-oop` 핵심 가치 합류*. PR #129·#143 (Kotlin 어휘 자가 분류) 결 강화.

**MCP 룰 `enum-vs-sealed-class-criteria` 후보** — *enum (상수 집합) vs sealed class (클래스 집합) 구분 기준*.

reviewer 자가 답변 (긴 메타 어휘):

> *"제 이야기 또한 정답이 아닌 하나의 의견으로 받아들여주셨으면 합니다. :)*

> *어쨌든 이 논리를 확장시켜보면, controller 를 모르므로 결국 model 도 view 를 알지 못하고, view 도 model 을 알지 못하는 구조가 되는 것이죠.*

> *그런데, BlackJackGame 의 경우*
> *1) 컨트롤러의 명세(BlackJackGameBluePrint) 를 구현하고 있고, (= 컨트롤러의 존재를 알고 있고)"*
