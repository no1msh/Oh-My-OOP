#### 2.2. *Context↔State (양방향) vs Context→State (단방향)*

- **Context→State** (학생 선택):
  - State 는 Context 무관 = 재사용 친화 + 결합도 한정.

- **Context↔State** (책 표준):
  - State 가 Context 의 setState 호출 = 상태 전환 책임이 State 에.
  - 단점: 양방향 의존 = 재사용 어려움 + 복잡성 증가.
  - 장점: Context 는 단순 + State 자기 도메인 로직 응집.

학생 자가 반박: *"저는 참가자의 state가 finishState 가 아닌데, judge() 함수를 호출하는 것이 논리적 오류라 판단했습니다. 그 이유는, Participant 가 아직 블랙잭 게임을 Play하지도 않았는데, judge를 호출하는 것이 의도대로 동작하지 않는 논리 에러 라 생각했기 때문입니다. 따라서, 다른 개발자가 Play하지도 않았는데, judge를 호출한다면 예외를 발생시켜 개발자에게 알리고자 했습니다!"*

#### 4.1. *논리적 오류 vs 입력 오류*

#### 4.2. *학생 자가 *분류 기준* 명시 + reviewer 권고 반박*

학생이 *자기 코드의 *오류 종류* 를 *논리적 오류* 로 분류 + 권고 거부 + 이유 명시*. **자가 분류 + 권고 반박 모범**. PR #46·#43·#95 결의 *학생 자가 결정 + 이유 명시*.
