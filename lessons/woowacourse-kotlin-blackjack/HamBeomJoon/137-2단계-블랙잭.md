### 1. `BlackjackGame.dealerDrawPhase` — *while 안에 print 콜백 + condition 이중 검사*

```kotlin
private fun dealerDrawPhase(printDealerHandStatus: (Boolean) -> Unit) {
    val condition = dealer.isMoreCard()
    if (!condition) {
        printDealerHandStatus(false)
    }

    while (dealer.isMoreCard()) {
        printDealerHandStatus(true)
        gameManager.drawCard(dealer)
    }
}
```

→ **`isMoreCard()` 호출 + condition 변수 + while 다시 호출**. *condition 사용 한 번 + while 재호출*. *Kotlin 어휘 = `if (dealer.isMoreCard()) { while (...) } else { printDealerHandStatus(false) }` 또는 `while + 첫 iteration 출력 분리`*. *변수 1회 사용 + while 동일 메서드 호출* 가 *함수 호출 중복*.

또한 `dealer.score < DEALER_MORE_CARD_MINIMUM (17)` 조건이 *17 미만이면 hit* — 정확. 다만 *Bust 도달 시 dealer.score = > 21* 도 *17 미만 아니므로 while 종료* — 정합.

### 2. `Player.getInitialCard(): List<Card> = cards` — *Player 전체 카드 노출*

```kotlin
class Player(...) : Participant(name) {
    override fun getInitialCard(): List<Card> = cards  // ⚠ 전체 카드
}

class Dealer(...) : Participant(name) {
    override fun getInitialCard(): List<Card> = listOf(cards.first())  // 딜러 1장
}
```

→ **`Player.getInitialCard` = *전체 cards 반환*** — *블랙잭 공개 룰 = 플레이어 2장 공개, 딜러 1장 공개*. *Player 가 *모든 카드* 반환* = *플레이어 손패 수 무관 모두 공개*. *초기 2장 공개* 의도면 `cards.take(2)`. *현재 cards = 초기 + 추가 hit 모두 포함* → *Player 의 모든 카드 공개*.

학생 의도 = *Player 는 모든 카드 공개* + *Dealer 만 첫 1장*. *블랙잭 룰 정합* (플레이어 손패 전부 공개). 다만 *naming `getInitialCard` = 초기 카드* 어휘 — *Player 의 경우 전체 카드 반환*은 *naming 부정확*. PR #132 (환노) 의 *Player.getInitCard = cards.take(2)* 와 *다른 트레이드오프*.

### 11. `ResultCalculator.calculate` 의 *`while (countAce-- > 0)` Ace 처리* — *Kotlin 어휘*

```kotlin
fun calculate(cards: List<Card>): Int {
    var sumScore = calculateTotalScore(cards)
    var countAce = countAce(cards)
    while (countAce-- > 0) {
        if (sumScore + ADJUST_ACE_NUMBER > BLACKJACK_NUMBER) {
            break
        }
        sumScore += ADJUST_ACE_NUMBER
    }
    return sumScore
}
```

→ **`countAce-- > 0`** = *Java/C 어휘*. *Kotlin = `repeat(countAce)` 또는 `for (i in 1..countAce)`* 가 *어휘 정공*. 다만 *break 활용 시 repeat 어색* — *while + countdown* 트레이드오프. PR #58·#93·#108 와 같은 결.

또한 *`+= ADJUST_ACE_NUMBER` 안에 break* — *Ace 처리 패턴 정확*. *Ace 1 기본 + 가능한 만큼 +10*. PR #128·#114·#125·#108·#131·#136 와 같은 결의 *Ace 처리*.

## 리뷰어 의견 요지

- **원시값 최대한 포장** — *Double 의미 모름*. *WinningMoney / BetAmount / Profit value class 분리*.
- **`ResultType enum + profit: Double` = 게임 결과가 이익률 알 수 있음** — *상수 응집*.
- **`Map<X, X>` 회피 — Profit class 응집** — PR #132 와 같은 결.
- **`it.copy()` 방어적 복사 = 불변 객체엔 복사 비용만 추가** — 학생 자가 학습 모범.
- **`println` 도메인 X = View 책임** — *간접 lambda 도 View 결합*.
- **콜백 = `onXX` 행위 명시** — *Inversion of Control + 의도 명료*.
- **`when` 절 = if 다중 분기 가독성 ↑** — *Kotlin 패턴 매칭*.
- **테스트 명세 = 도메인 룰 정확** — *플레이어 24 / 딜러 19 → WIN?* 함정.
- **BlackjackGame 통합 테스트 = 흐름 검증** — *각 객체 단위 테스트 + 통합 흐름*.
- **이익 vs 수익 어휘 혼란 → 학생/리뷰어 양방향 학습** — *지훈도 자가 인정*.
- **확장함수 vs Double 직접 = YAGNI** — *불필요한 확장함수 제거*.
- **`value class.value` 명명 = 어색하지 않은 표현** — *value 표준 어휘*.
- **`Builder` 필수값 = 진입 함수 인자** — *Builder의 본질 = 선택적 속성*. *필수 = 인자 우선*.
