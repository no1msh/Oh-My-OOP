### 6. `ScoreCalculator.adjustAceScore` 수학적 풀이 — while 제거

```kotlin
private fun adjustAceScore(totalCardScore: Int, aceCount: Int) = 
    totalCardScore - ACE_MINUS_VALUE * aceCount.coerceAtMost((totalCardScore - BLACKJACK_SCORE) / ACE_MINUS_VALUE + 1)
```

→ **`while` 반복 → 수학적 단일 식 변환** (reviewer Thread 23 권유 → 학생 자가 적용). 

#### 6.1. *수학 공식 도출*

- Ace 11→1 = -10 점.
- 초과 점수 = `totalCardScore - BLACKJACK_SCORE` (양수).
- 필요한 -10 회수 = `초과 / 10 + 1` (1 부터 시작 = +1).
- 다만 최대 -10 회수 = `aceCount` (Ace 개수 한정) → `coerceAtMost(aceCount)`.

→ **MCP 룰 `iterative-loop-vs-math-formula` 강화** — *반복문 의존 vs 수학적 단일 식*. 외부글 동반.

PR #87 (mutableMap → fold) 결의 *명령형 vs 함수형/수학적* 어휘 합류.

### 4. `distinct()` vs `toSet()` — 함수 의도 양가

reviewer (Thread 4):

> *"distinct() 함수가 어떻게 구현되어 있는지 한번 보시고 distinct()대신 다른 함수를 쓰도록 변경해보면 좋을 것 같습니다. 아니면 제이는 여기서 distinct()를 사용하신 이유가 중복제거 외에 다른 의미도 있었을까요?"*

학생: *"중복제거 말고는 다른 의미는 없었어요..😅"*

→ **`distinct()` vs `toSet()` 의미 비교**:

| 함수 | 의도 | 비용 |
|---|---|---|
| `distinct()` | *순서 보존 + 중복 제거 (List 유지)* | *O(n) + HashSet 보조 자료구조 내부* |
| `toSet()` | *순서 X + 중복 자가 X* | *O(n) + HashSet* |

학생의 *카드 중복 invariant 검증* 용도 = *순서 보존 불필요* → `toSet()` 적합.

```kotlin
// AS-IS
require(allCards.distinct().size == getCardsCount())
// TO-BE
require(allCards.toSet().size == totalCount)
```

**MCP 룰 `distinct-vs-toSet-intent` 후보** — *함수 의도 = 순서 보존 여부*.
