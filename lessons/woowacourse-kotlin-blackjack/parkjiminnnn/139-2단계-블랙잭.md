### 1. `betAmount` Player 생성 시점 — 한 판 vs 여러 판 가정

reviewer (Thread 2):

> *"betAmount는 Player가 생성될 때 만드는게 맞을까요? 지금은 게임을 한판만 하지만 여러판을 한다고 가정하면 Player는 어떻게 변경되어야할까요?"*

학생 코드 (수정 후):
```kotlin

    var betAmount: Float = ZERO
        private set(value) {
            require(value > ZERO) { PLAYER_AMOUNT_ERROR_MESSAGE }
            field = value
        }

    fun betting(betAmount: Float) {
        this.betAmount = betAmount
    }
}
```

→ **여러 판 가정 = betAmount 가 *판마다 변경***. *Player 인스턴스 = 여러 판 공유 + betAmount = 매 판 변경*. **`var betAmount` + `betting()` 메서드** 자가 적용.

#### 1.1. *3 가지 대안*

| 안 | 장점 | 단점 |
|---|---|---|
| `Player(name, cards, betAmount)` (학생 초안) | *생성 시 invariant 강제* | *Player = 매 판 신규 인스턴스 X 가정* |

| `Player.startRound(betAmount): Round` | *Round 객체 = 판 별 인스턴스* | *Round 객체 추가 + 복잡도 ↑* |

reviewer 의 *"여러 판 가정"* = *학생이 *미래 확장* 의식 권유*. **MCP 룰 `feature-evolution-driven-design` 후보** — *현재 요구사항 vs 미래 확장 의식*.

다만 *현재 미션은 1 판만 * → *여러 판은 가정만*. *YAGNI 위반? vs 변경 비용 인식?* 트레이드오프.
