### 1. `abstract Participant + Player/Dealer 동일 구현 override` — *학생 자가 의문 + 말리빈 매우 긴 메타 답변*

#### 1.2. 상속 구조 자체 의문 권유

*"꼭 Player와 Dealer가 같은 부모를 상속 받아야만 한다는 규칙은 없으니까요"* — *블랙잭에서 Player와 Dealer 가 *같은 추상 부모를 가져야 한다* 는 가정 자체 의문 권유*.

- (B) **`abstract Participant`** = *공통 추상 + 각각 구현*. *학생 현재 코드*.
- (C) **`interface Participant`** + *각각 별도 구현* = *상속 회피 + 다중 인터페이스 가능*.
- (D) **`Dealer`/`Player` 무관계 + 공통 코드는 협력자에게 위임** = *상속 회피 + 컴포지션*.

### 2. `Controller → BlackjackGame.start() 결과 반환` — 학생 *이해 못함* + 두번 부연

말리빈 진단:

```kotlin
val game = BlackJackGame()
val result = game.start()
print(result)
```

학생 자가 의문: *"이해를 못했습니다.. 출력해야 할 사항이 여러개인데, 어떤 결과를 반환하도록 하라는 말씀이실까요..?"*

말리빈 부연: *"마지막 게임이 종료되고 나서 출력해야할 게임의 결과물을 말씀드렸어요! 출력해야할 것들은 객체를 생성하거나, 메서드 파라미터 등으로 적절히 전달해주면 충분히 구성 가능하실거예요 :)"*

→ **학생 자가 의문 = 이해 갭 명시 (자가 학습 모범)**. 

이해 갭 진단:
- *학생 코드*: Controller 가 *진행 중 단계별로 출력* (initial hand → hit 입력 → 결과 출력 → 수익 출력 4-5 단계).
- *말리빈 의도*: *게임의 진행과 출력 시점을 결과 객체에 응축* → *Controller 는 출력 명령만*.
- 그러나 *진행 중 출력*은 *블랙잭 도메인의 자연 흐름* — *초기 카드 후 → 각 플레이어 hit 입력* 단계 자체가 *결과 객체 반환 후 출력* 모델과 충돌.

해결 대안:
- (A) **`game.start()` 가 *상태 전이 기록*을 담은 `GameLog` 반환** = *Controller 가 로그 재생 (replay)*. 그러나 *hit 입력 같은 양방향 IO 가 어려움*.
- (B) **`game.start(inputCallback, outputCallback)` 패턴** = *Inversion of Control + 콜백*. *학생 미적용*. PR #137 의 *onXX 콜백* 결.
- (C) **현재 학생 구조 유지 + Controller 가 진행 중 출력 명령** = *현실 절차에 가까운 모델 + 양방향 IO 자연*.

학생 미반영 + 머지. *말리빈 권고가 *학생 도메인 모델과 충돌* → 학생이 *명확히 이해 못한 채 머지* 케이스*. **두 번 부연했음에도 학생 미반영** — 권고의 한계.

→ **PR #98 의 *상태 패턴 효과 자가 의문*** 와 같은 결 *(권고 ≠ 학생 도메인 정합 시 미반영)*.

### 3. `Dealer.hit(condition)` vs `Dealer.hit()` 시그니처 불일치 → 디폴트 파라미터 우회

말리빈 진단: *"이 둘은 어떻게 다른가요? 딜러는 둘 둥 어떤 메서드를 써야할지 다른 개발자는 바로 알아차릴 수 있을까요?"*

학생: *"추상클래스의 메서드를 딜러와 플레이어가 공통으로 상속하도록 하고 싶었는데, 딜러는 hit조건을 객체 내부에서 불러올 수 있기 때문에 condition파라미터가 필요가 없더라구요.. 그런데 상속을 할 때 메서드의 시그니처를 바꾸는 방법이 없어서, 별 수 없이 오버로드를 했습니다. 다른 방법을 일단 찾아보겠습니다.."* + 후속: *"디폴트 파라미터를 사용해 수정했습니다!"*

말리빈 후속: *"음~ 사실 condition을 외부에서 받도록 구성하지 않았으면 했어요. BlackjackGame을 관제하는 하나의 객체가 있어서, 해당 객체와 적절히 협력하는 형태로 구성해도 좋겠다는 생각이 들었어요 :) 말씀해주신대로 딜러와 플레이어가 동일한 메서드를 호출해서 플레이하지 않을 수도 있으니까요!"*

→ **3 단계 자가 학습 + reviewer 후속 권고**:

1. **상속 시그니처 불일치 자가 진단** = *Player.hit(condition)* vs *Dealer.hit()* → *추상 메서드 시그니처 강제*.
2. **디폴트 파라미터 우회** = *`hit(condition: () -> Boolean = { true })`* 같은 형태. 학생 자가 시도.
3. **reviewer 후속 = 우회 X, *근본 원인* (외부에서 condition 받는 구조) 자체가 잘못** = *Player.hit 자체가 외부 의존 = 단순 명령 X*.

대안:
- (A) **`Dealer` / `Player` 가 *같은 부모 X* + 각자 자기 책임의 hit()** (위 §1.2 (A)).
- (B) **상속 유지 + Player/Dealer 동일 시그니처 + 내부에서 자기 조건 판단** = *condition 인자 제거 + 자기 메서드에서 자기 조건*.

## 얻은 교훈

1. **reviewer 의 메타 답변 = *"옳고 그름 X, 장단점만"*** — *조영호 「객체지향의 사실과 오해」 와 MCP `oh-my-oop` 의 핵심 어휘*. *말리빈의 답변이 이 어휘를 직접 사용* = *학생이 *reviewer 의견을 절대 답으로 오해하지 않도록 메타 학습 어휘 명시***. **MCP 의 핵심 가치가 실제 리뷰 현장에서 동일하게 작동**.

2. **다른 크루의 말 *그대로 따라하지 말기*** — *권위 인용 ≠ 논리적 설득*. 학생이 *논리를 묻고 자기가 납득해야* 자기 결정. *말리빈의 *"왜 안되는지 그 크루는 논리적으로 알송을 설득한 것일까요?"*. PR #147·#151·#137 의 *학생/reviewer 메타 토론* 결.

3. **상속 구조 자체 의문 권유** — *Player extends Dealer? Dealer extends Player? 둘 다 같은 부모? 무관계?* — *기본 가정 자체 다시 보기*. PR #49·#108·#133·#132·#136 의 *추상 클래스 + Participant 통합* 결의 *반대 시점*.

4. **`abstract class` vs `open class` vs `interface` 자가 학습**:
   - *`abstract class`* = *인스턴스 생성 차단 + 추상 메서드 가능 + 단일 상속*.
   - *`open class`* = *인스턴스 생성 가능 + 상속 가능*.
   - *`interface`* = *다중 구현 + 구현 메서드 (default impl) 가능 + 백킹 필드 X*.
   - *블랙잭 Participant 처럼 *인스턴스 X + 공통 코드 100%* = *abstract 이지만 abstract 메서드 X* → *어색함* → *open class (인스턴스 X 강제 X) 또는 interface (다중 구현) 정공*. **MCP 룰 후보 `abstract-without-abstract-method`** = PR #74·#108·#133·#137·#147 결.

5. **PR 본문 자가 의문 + 자가 정당화 + 본문 코멘트로 자가 의문 명시** — *학생이 *불필요해 보이는 프로퍼티 / 어려운 구조 변경 / 학습 갭* 을 *PR 본문 + 본문 코멘트에 명시 = 학습 가시화 모범*. PR #128·#135·#108·#133·#136·#137·#148·#151·#98 와 같은 결.

6. ***이해 못함* 자가 명시 = 학습 모범** — *"이해를 못했습니다.. 어떤 결과를 반환하도록 하라는 말씀이실까요?"* — *reviewer 권고를 *그대로 반영 X* + *자가 이해 갭 명시 후 부연 요청*. *학생이 *모르는 채로 머지하지 않으려는 자가 의식*.

7. **권고가 학생 도메인 모델과 충돌 시 미반영** — *Controller → BlackjackGame.start() 결과 반환* 처럼 *학생의 진행 중 출력 흐름 (양방향 IO)* 과 *결과 객체 응축* 이 충돌 → *학생 미반영 + 머지*. **권고 ≠ 절대 답** 의 실증.

8. **1단계 PR 자가 참조 + URL 인용** — *2단계에서 1단계 동일 안티패턴 재발 시 reviewer 가 1단계 코멘트 URL 첨부* → *학생이 즉시 1단계 학습 위치 확인 + 자가 인정*. **양 단계 본 reviewer 만 가능한 권유 형식**.

9. **`Player.profit` 책임 위치 = *Player vs PlayerResult* (역할 vs 상태)** — *역할 (Player) 은 베팅 머니까지 / 상태 (수익 계산 결과) 는 PlayerResult*. **MCP 룰 후보 `role-state-conflation`** — PR #148 의 krrong (역할 vs 상태 자가 학습) 결.

10. **재구현 권유 = 학생 자가 진화 모범** — *"나중에 시간이 나게 된다면 미션을 처음부터 다시 만들어보는 시간을 가져보셔도 좋겠어요! 처음 만든 것과 완전히 다른 코드를 마주하게 될거예요"*. *학습 = 한 번에 X + 시간 두고 반복*. PR #98 chaehyuns *"추후 시간이 될 때 다시한번 구현해보고 싶네요"* 결.
