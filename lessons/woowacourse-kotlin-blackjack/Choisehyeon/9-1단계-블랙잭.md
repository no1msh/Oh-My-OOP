### 1. `setBlackJack()` 함수명 — set 계열 함수 컨벤션 위반

벅벅: *"함수명만 봤을 때에는 '블랙잭을 설정한다' 라는 의미로 이해가 되는데요. 하지만 흔히 set 계열의 함수는 무언가를 리턴하는 것으로 예상되기 보다는, 단순히 값을 설정할 것으로 예상이 됩니다. 함수명이 구현체가 하는 일을 잘 표현하도록 함수명을 개선해보면 어떨까요?"*

→ **JavaBean 컨벤션 + Kotlin**:
- *`setX(value)`* = *값 설정 + Unit 반환* (관용).
- *`set 동사 + 명사`* + *리턴값 보유* = *컨벤션 위반*.
- 대안: *`createBlackJack()`*, *`buildBlackJack()`*, *`initializeBlackJack()`*.

**MCP 기존 룰 `vagueName` 변형** + *set 접두사 컨벤션 위반 검사*. PR #99·#26·#39·#46 결.

### 2. `winTo` 함수 = 프로퍼티 X (상태 vs 행동)

벅벅: *"프로퍼티는 상태를 나타내며, 함수는 행동을 나타냅니다. winTo 함수는 상태라기보다는 행동을 의미합니다. 프로퍼티는 상태만을 갖도록 코드를 개선해보면 어떨까요?"*

→ **Kotlin 어휘 (프로퍼티 vs 함수)**:
- *프로퍼티* = *상태 (값) 표현*. 정적 의미.
- *함수* = *행동 (계산/변환) 표현*. 동적 의미.
- *`val winTo: ...` (프로퍼티)* < *`fun winTo(): ...` (함수)* — *행동은 함수 정공*.

PR #91 (murjune *프로퍼티 vs 함수 자가 인정*) 결.

### 3. `BlackJack 확장 함수` 위치 — 외부 발견 가능성

벅벅: *"BlackJack 클래스와 관련된 확장 함수를 작성해주셨네요. 👍 BlackJack 클래스 내의 멤버 함수로 구현하는 것과, 다른 클래스에서 BlackJack의 확장함수를 만드는 것은 각각 어떤 장점이 있을까요? 만약 다른 개발자가 guestsTurn 함수와 dealerTurn 함수가 BlackJackGame에 정의가 되어있을 것이라 예상할 수 있을까요?"*

→ **확장 함수 vs 멤버 함수 발견 가능성**:
- *멤버 함수* = *클래스 내 즉시 가시 + 자동 완성*.
- *확장 함수* = *외부 클래스에 정의 + import 필요 + 발견 어려움*.
- *블랙잭 도메인 핵심 메서드 (guestsTurn, dealerTurn)* = *멤버 함수 정공*.

PR #11 (위 학생 자가 4 분면) 의 *확장 함수 단점 (네임스페이스 오염)* 와 동일 결.

### 5. `Cards.toList()` 외부 호출 — 학생 자가 정당화

벅벅: *"toList라는 함수를 외부에서 호출해줘야할까요? 외부에서 cards 변수에 접근해서 값을 조회하도록 개선해보면 어떨까요?"*

학생 자가 정당화: *"캡슐화를 위해 toList 함수를 사용해서 호출해줬는데 직접 접근하게 된다면 Card.card.toList()과 같이 될 것 같아서 캡슐화를 하기 위해 위 방식으로 진행했습니다!"*

벅벅 별도 (suggestion):

```kotlin
class Cards(val cards: Set<Card> = setOf()) {
```

*"대체로 Immutable한 컬렉션 타입이라면, 외부에 오픈이 되더라도 변경할 수 없습니다. private 접근자를 제거한다면, 불필요한 toList 함수를 만들지 않아도 됩니다."*

→ **2 가지 학습**:

#### 5.1. *Immutable 컬렉션 vs Mutable 컬렉션 외부 노출*

- *`MutableList<Card>` 외부 노출* = *외부 변경 위험* → *방어적 복사 / `toList()` 필요*.
- *`List<Card>` (Immutable interface)* = *외부에서 변경 불가* → *`toList()` 불필요*.
- **단, `MutableList` 가 백킹 객체인 경우 `List` 인터페이스로 캐스팅해도 외부에서 `as MutableList` 가능** — PR #16 (SeongHoonC *LSP 자가 학습*) 결.

#### 5.2. *학생 자가 정당화 (캡슐화 의도)*

학생이 *`toList()` 가 캡슐화를 위한 것* 자가 명시. *그러나 Set<Card> immutable 이라면 노출해도 무해* — *학생 자가 학습 갭*.

PR #74 (송핑크 *불변 객체 자가 학습*) / PR #46 (krrong *backing property*) 결.

### 8. `Builder 패턴 호출 순서 + 지연 초기화`

벅벅: *"Builder 패턴은 호출 순서와 상관 없이, build 함수를 호출하는 순간 객체가 정상적으로 만들어져야 합니다. 하지만, 아래와 같은 코드를 작성하게 되면 어떻게 될까요?"*


- *`lateinit var`* = *향후 초기화 강제 + 접근 전 초기화 필수*.
