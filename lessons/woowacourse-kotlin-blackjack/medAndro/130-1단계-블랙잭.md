### 4. ArrayDeque vs MutableList vs Stack vs Queue 자가 분석 (페어 학습)

reviewer (Thread 6): *"여러 자료구조 중에 `ArrayDeque`를 사용하신 이유가 무엇인지 궁금합니다!"*

학생 자가 답변:

> *"카드를 한장씩 Pop해야 하는 상황에서 어떤 자료구조를 쓰면 좋을까 페어와 논의하다가 (페어의 제안 인용) 라는 페어의 제안으로 사용해보게 되었습니다.*
>
> *- ArrayDeque: 양쪽 끝에서 O(1) 시간 복잡도로 효율적인 추가/제거 작업 가능하며 메모리 효율적이지만, 제거 작업을 해도 내부 배열의 크기가 줄어들지 않음*
> *- MutableList: 끝에서 요소 추가/제거시 효율적이지만, 중간이나 처음에서 제거하는 작업은 O(n) 시간 복잡도로 비효율적*
> *- Stack: LIFO(Last-In-First-Out) 원칙을 따르며 한쪽 끝에서만 O(1) 시간 복잡도로 요소 추가/제거가 가능하지만 Java의 레거시 클래스로 성능 이슈 존재*
> *- Queue: FIFO(First-In-First-Out) 원칙을 따르며 한쪽 끝에서 추가하고 반대쪽 끝에서 제거하는 구조로, 자바의 Queue자체는 인터페이스이며 LinkedList나 ArrayDeque로 구현 가능*
>
> *라는걸 공부하게 되었고 현재로서는 ArrayDeque를 유지할 생각입니다."*

→ **자료구조 4 안 자가 분석 + 페어 학습 + 다른 PR 인용**:

#### 4.1. *Kotlin 어휘 깊은 자가 학습*

PR #21·#23·#26·#58 결의 *카드덱 자료구조 (LinkedList vs ArrayDeque vs MutableList 뒤에서 pop)* 어휘 합류. 

#### 4.2. *페어 학습 + 외부 인용*

페어와의 토론 인용 + 다른 PR (`pull/128#discussion_r1986069929`) 인용 = **다른 학생의 학습 자가 참조**.
