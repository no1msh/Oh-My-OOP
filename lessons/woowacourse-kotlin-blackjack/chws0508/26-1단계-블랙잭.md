### 1. `Answer.YES` 입력값 → BlackJackGame 모름 권고

잭슨: *"BlackJackGame에서 Answer.YES라는 입력값을 알아야 할까요? BlackJackGame에서는 카드를 추가로 받는지에 대한 부분만 관심사이지, 어떤 input을 받을지에 대한 부분 몰라도 좋을거같아요! input이란 네이밍도 함께 변경해보아요!"*

학생: *"Boolean을 받도록 수정하였습니다"*

→ **3 가지 학습**:

#### 1.1. *View 어휘 (`y`/`n` → `Answer.YES/NO`) 누수 방지*

*BlackJackGame 도메인* 이 *`Answer.YES`* 같은 *입력 표현* 을 알면 = *입력 표현 변경 (예: "예"/"아니오") 시 도메인 변경*.

#### 1.2. *Boolean vs sealed Action*

- *Boolean* = 단순. *학생 자가 반영*.
- *sealed class Action { Hit, Stay }* = *블랙잭 도메인 어휘 명시 + Bust 등 확장 가능*. PR #88·#90·#147 의 *Action enum* 결.

#### 1.3. *`input` 변수명 — 모호*

PR #23 (멘델) 의 *`input/output/choice` 모호 명명* 결. **MCP 기존 룰 `vagueName`**.

### 3. `RandomCardPicker` 테스트 전용 코드 + cards 생성시점 주입

잭슨 1차: *"테스트 코드에서만 사용되고 있네요! 테스트를 위한 코드는 지양해주는것이 좋아요! 다른 방법의 테스트를 고민해보면 어떨까요?"*

잭슨 2차 (메타 질문): *"cards를 생성시점에 주입하면 장점이 있을까요?"*

학생 자가 답변: *"cards를 생성시점에 주입하면 cards가 한번만 생성될 것 같아서 데이터 관리에 효율적일 것 같습니다"*

잭슨 3차 (도메인 룰 확장):

> *"보통 CardDeck에서 카드를 뽑으면 해당 카드가 CardDeck에서 제외되곤합니다. 이 처럼 구현해보면 어떨까요? CardPicker 생성시점에, CardDeck를 주입받아서, 해당 CardDeck 또한 관리해보면 어떨까요? CardDeck에 카드가 모두 떨어졌을때에도 예외처리할 수 있을거 같아요!"*

학생 자가 의문 (도메인 룰 인용):

> *"제가 알기로는 블랙젝 게임에서는 여러카드덱을 사용하는것으로 알고있는데 카드를 뽑고나서 카드덱에서 지우게되면 중복된 카드를 뽑을 수 없게 되지 않나요? 그리고 카드가 다 떨어지게 되는 경우는 카드덱을 여러개 사용하지 않는다는 뜻 아닐까요?"*

→ **3 가지 학습**:

#### 3.1. *카드 뽑기 + 제외 vs 캐싱*

- *뽑은 카드 = 덱에서 제외* (잭슨 권고) = *카드 1벌 한정 모델*.
- *카드 캐싱 + 매번 random pick* (학생) = *여러 벌 가능 + 중복 카드 가능*.

#### 3.2. *학생 자가 도메인 룰 인용*

*"블랙젝 게임에서는 여러카드덱을 사용하는것으로 알고있는데"* — *카지노 6덱 메타포* (PR #58 otter66) 결. *카드 1벌 한정 = 6덱 룰과 충돌*.

#### 3.3. *카드 부족 시 예외 vs 자연 종료*

잭슨 권고 *"카드가 모두 떨어졌을때에도 예외처리"* = *1벌 한정 + 예외*. 학생 *"카드가 다 떨어지게 되는 경우는 카드덱을 여러개 사용하지 않는다는 뜻"* = *6덱 사용 시 비예외*. **둘 다 유효 — 도메인 룰 결정에 따라 다름**. PR #74·#108·#133·#136·#41 의 *카드 부족 시 게임 종료 UX* 결.

### 4. `Participant Result 책임 위치 + 블랙잭 룰 정확성`

잭슨: *"Participant에는 플레이어와 딜러가 있습니다, Result는 누구의 기준으로 승/패가 정해지는 걸까요? 해당 책임이 누구에게 있어야하는지 한번 고민해보셔도 좋을거같아요!"*

블랙잭 룰 추가 명시:

> *"블랙잭의 룰 상 플레이어와 딜러가 모두 Burst이더라도, 1. 플레이어 Burst -> 딜러의 점수와는 상관없이 플레이어 패배 2. 딜러 Burst -> Burst가 아닌 플레이어의 승리 가 정해집니다."*

→ **2 가지 학습**:

#### 4.1. *책임 위치 = Participant 부모 X*

*Participant 부모에 Result 메서드* = *Player/Dealer 둘 다 동일 시그니처* → *그러나 Player 기준 vs Dealer 기준* 의 명확화 X. PR #23 (멘델 1단계) / #70 (chaehyuns 1단계) / #74 (송핑크 1단계) 의 *점수 책임 위치 토론* 결.

#### 4.2. *블랙잭 룰 = 양측 Bust 분기*

- *Player Bust → 자동 패배* (Dealer 의 Bust 무관).
- *Dealer Bust → Bust 아닌 Player 승리*.

**MCP 룰 후보 — `blackjack-rule-fidelity`** = *Player Bust 자동 패배* + *Dealer Bust 시 Bust 아닌 Player 승리*. PR #20·#64·#110·#120·#29·#63·#23 결.

### 8. `Cards 초기 2장 검증` — 책임 위치 자가 학습

잭슨: *"개인적인 의견이니 참고만해주셔도 좋아요. 카드 초기값이 2장인 부분의 검증이 필요할까요? 카드 2장을 초기값을 받는건 BlackJack게임의 관심사라고 생각이 들어요. Cards 생성에 이러한 조건이 있는 것은 외부에서 알기 힘들지 않을까 하는 생각이드네요!"*

학생 자가 답변: *"블랙잭 게임에서 혹시 실수로 카드를 하나만 주입했을때를 방지하기 위해 제약을 걸어둔건데 생각해보니 Cards가 이것까지 알아야 하나 라고 생각되고 초기 카드 2장을 갖는건 Cards의 책임이 아니라 blackjackgame의 책임이라고 볼수도 있겠군요.. 객체의 역할과 책임에 대해 좀 더 고민해보겠습니다"*

→ **3 가지 학습**:

#### 8.1. *학생 자가 정당화 + 자가 후회*

*"실수 방지를 위해 제약"* → *"Cards 가 이것까지 알아야 하나"* — *학생이 *자가 정당화 + 자가 후회* 두 단계 거침*. **자가 학습 풍부 모범**. PR #128·#135 의 *학생 자가 답변 모범* 결.

#### 8.2. *책임 = Cards (일반 카드 묶음) vs BlackJackGame (블랙잭 도메인 규칙)*

- *Cards* = *카드 묶음 일반 = 1장도 N장도 가능*.
- *BlackJack 룰* = *초기 2장 분배*.
- *Cards 에 *최소 2장* 제약* = *Cards 가 블랙잭 도메인 룰까지 알게 됨* → *Cards 재사용 불가 (다른 카드 게임에서 1장만 가질 수 없음)*.

#### 8.3. *"외부에서 알기 힘들지 않을까"* — *암묵 제약 어휘*

잭슨의 *"Cards 생성에 이러한 조건이 있는 것은 외부에서 알기 힘들지 않을까"* = **암묵 제약 (implicit invariant)** 어휘. *Cards(emptyList()) 가 통과될 것 같으나 init 에서 Exception* = *호출자 놀람*. PR #20·#64·#110 의 *implicit-invariant-on-known-rule* 결.
