## 못한 점 (설계 관점)

### 1. `compareScoreValue` 점수 차이 계산 → 직접 비교 권고

잭슨 suggestion:

```kotlin
fun compareScoreValue(dealerScoreValue: Int, playerScoreValue: Int): GameResultType {
    return when {
        playerScoreValue > dealerScoreValue -> WIN
        dealerScoreValue < playerScoreValue -> LOSE
        else -> DRAW
    }
}
```

잭슨 진단: *"점수차이를 계산하신 이유가 있나욤? 그냥 크기를 비교해주는게 좀더 직관력이 있지않을까욤?"*

학생: *"when 을 쓸때 무조건 소괄호안에 값이 있어야 한다고 착각했네요 ㅠㅠ 수정하였습니다!"*

→ **3 가지 학습**:

#### 1.1. *`when (값)` vs `when { 조건 }` 두 형태*

- *`when (x) { 1 -> ..., 2 -> ... }`* — *값 매칭*. 학생 *잘못된 가정 (소괄호 필수)*.
- *`when { x > y -> ..., x < y -> ... }`* — *조건 매칭 (if-else-if chain 대체)*. **Kotlin 의 강력한 어휘**.

#### 1.2. *점수 차이 vs 직접 비교*

- *점수 차이 (`dealer - player`) → 부호 검사* = *우회 + 직관성 ↓*.
- *직접 비교 (`>`, `<`, `==`) → enum 결과* = *직관 + 단순*.

#### 1.3. *학생 자가 잘못된 가정 자가 인정 모범*

**Kotlin 어휘 학습 갭 자가 노출 = 학습 가시화 모범**. PR #23 (멘델 *else 지양 극단*) / PR #146 (yrsel *YAGNI 자가 인정*) 결.

### 2. `GameResultType` 책임 위치 — 학생 자가 매우 깊은 의문

잭슨 메타 진단:

> *"GameResultType에게 승패를 결정하는 책임을 주었는데, GameResultType에는 결국 playerScoreState와 dealerScoreState를 모두 알아야한다는 단점또한 생기는것 같아요. 승패를 정하는 책임이 어디에 있어야할지 한번 더 생각해보아도 좋을거같아요! 정답은 없는거니, 고민만해주셔도 좋아요!"*

학생 자가 매우 깊은 의문:

> *"이 부분이 상당히 어려운 것 같습니다 ㅠㅠ 게임의 승패를 결정하는 것이 플레이어의 역할인지, 블랙잭 게임의 역할인지, 아니면 승패를 가지고 있는 GameResultType의 역할인지... 아니면 따로 또 객체를 만들어줘야 하는지... 이번에는 상태패턴을 써서 상태가 승패를 결정하도록 하였지만, 이런식으로 책임을 정하기 애매하거나 어려울 때, 리뷰어님은 어떤 기준으로 부여하시는지 궁금합니다."*

→ **5 가지 학습**:

#### 2.1. *책임 위치 = 4 후보*

학생 자가 명시:
- (A) **Player** — 플레이어가 자기 승패 판단.
- (B) **BlackJackGame** — 게임이 승패 판단 (god-object 위험).
- (C) **GameResultType (enum)** — *enum 이 행동 가짐 = OOP 함정 (enum 만능)*.
- (D) **별도 객체 (예: Judge / Referee)** — *심판 객체 분리*.
- (E, 학생 선택) **State** — *상태가 자기 승패 결정 (다형성)*.

PR #74 (송핑크 *Referee 자가 토론*) / PR #23 1단계 (멘델 *3 후보 + 그림*) / PR #70·#98 (chaehyuns *Judge 분리*) 결.

#### 2.2. *enum에 행동 부여 = 양가성*

- *enum + 행동* = *Kotlin 어휘 풍부 + 멤버별 분기 캡슐화*. PR #137·#148·#90·#146 의 *enum + when exhaustive* 결.
- *그러나 enum 이 *다른 객체 (Player, Dealer) 의 내부 상태* 까지 알아야 한다면* = *책임 누수*.

#### 2.3. *State 패턴 = 다형성 디스패치*

- *각 State (BlackJack, Bust, Hit, Stay) 가 자기 승패 결정 메서드*.
- *외부는 `state.compareTo(other)` 만 호출* → *enum 분기 제거*.

PR #93·#136·#152 의 *State.compareTo: GameResult 다형성* 결.

#### 2.4. *책임 기준 자가 의문 모범*

#### 2.5. *"정답은 없는거니, 고민만해주셔도 좋아요"* — reviewer 메타 어휘

### 5. `Controller god-object` — `BlackJack.runGame()` 결과 반환

잭슨: *"게임시작시 , 플레이어 턴 -> 딜러턴 의 게임을 통해서 결과를 리턴하는 부분은 BlackJack 클래스내에서 관리하는 책임이 아닐까요? 컨트롤러에서는 blackJackGame 게임을 실행시키고, 결과만 받아오면 어떨까요? `val gameResult = blackJackGame.runGame(`"*

### 7. `interface 프로퍼티` 자가 학습

잭슨: *"코틀린에서 인터페이스에서는 프로퍼티도 선언할수 있어요 😄 필요에 따라서, 함수대신 프로퍼티도 사용할수 있습니당!"*

PR #98 (chaehyuns *fun interface vs interface*) 결.
