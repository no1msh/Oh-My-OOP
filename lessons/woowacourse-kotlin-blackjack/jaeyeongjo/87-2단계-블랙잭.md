### 1. `sealed class ParticipantState` + 3개 자식 (Blackjack/Bust/Normal) — 진정한 State 패턴

```kotlin
sealed class ParticipantState(private val hand: Hand, private val info: ParticipantInfo) {
    abstract val isBlackjack: Boolean
    abstract val isBust: Boolean
    abstract val isFinished: Boolean
    
    abstract fun calculateGameOutcome(opponent: ParticipantState): GameOutcome
    abstract fun drawCard(card: Card): ParticipantState
    ...
}

class Blackjack(hand: Hand, info: ParticipantInfo) : ParticipantState(hand, info) {
    override val isBlackjack = true
    override val isFinished = true
    override fun calculateGameOutcome(opponent: ParticipantState): GameOutcome {
        if (opponent.isBlackjack) return GameOutcome.Tie
        return GameOutcome.WinWhenBlackjack
    }
    override fun drawCard(card: Card): ParticipantState = this
}
```

→ **State 자식들이 *abstract 함수 2개* 구현** (`calculateGameOutcome` + `drawCard`) — *Tell-Don't-Ask + 다형성*. PR #93·#136·#152·#98 결의 *State 자식 책임 부여* 정공.

→ *Dealer 의 수익 = -(상대 베팅 × 결과 배수)* = *상대 베팅을 가져옴*. **Dealer 가 *자기 베팅 0* 을 호출하지 않음** = *코드는 OK*.

다만 *getBetAmount() 메서드 가 Participant 에 있음* = *Dealer 호출 시 0 반환 = 의미 누수* (위 §10).

### 18. `Participant.getState()` getter — 디미터 위반 직접 노출

### 20. `Participant.calculateProfitAgainst` 추상 + Player/Dealer 구현 차이

```kotlin
abstract fun calculateProfitAgainst(opponent: Participant): Double

class Dealer(...) : Participant(...) {
    override fun calculateProfitAgainst(opponent: Participant) =
        -(opponent.getBetAmount() * (opponent.calculateGameOutcomeAgainst(this).payoutMultiplier))
}

class Player(...) : Participant(...) {
    override fun calculateProfitAgainst(opponent: Participant) = 
        getBetAmount() * (calculateGameOutcomeAgainst(opponent).payoutMultiplier)
}
```

→ **Dealer.calculateProfitAgainst = -(상대 베팅 × 상대 결과)** vs **Player.calculateProfitAgainst = 자기 베팅 × 자기 결과**.

#### 20.1. *대칭 깨짐*:

- Player: *self.betAmount × self.outcome*.
- Dealer: *-(opponent.betAmount × opponent.outcome)*.

→ *Dealer 의 수익 = 모든 Player 의 수익 합의 부호 반전* (PR #36 *operator fun not() 부호 반전* 결).

#### 20.2. *Tell-Don't-Ask 위반*

`Dealer.calculateProfitAgainst` 가 *opponent.getBetAmount() × opponent.calculateGameOutcomeAgainst(this).payoutMultiplier* 호출 = *opponent 의 데이터 가져와서 계산*.

대안: **`Player.calculateProfitAgainst` 의 부호 반전 활용** — `Participants.calculateFinalProfits` 에서 *Player 합 부호 반전*:

```kotlin
profits[dealer] = -players.sumOf { player -> player.calculateProfitAgainst(dealer) }
```

→ *Dealer.calculateProfitAgainst 불필요 → abstract 제거*.

**MCP 룰 `tell-dont-ask-asymmetric-method` 후보** — *대칭 깨진 메서드 = 한쪽이 다른쪽 데이터 가져옴*.

→ *현재 안은 sealed class + protected = 적절*. Kotlin 어휘 활용.
