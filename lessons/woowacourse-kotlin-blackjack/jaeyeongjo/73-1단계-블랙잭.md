### 6. `State 디자인 패턴 = 조건문 제거 핵심`

ghojeong: *"디자인 패턴을 사용했다면, 그 디자인 패턴이 해결하려고 한 문제가 해결되었어야 합니다. State 디자인 패턴이 해결하려고 한 핵심은 유한 상태 기계를 객체로 흉내냄으로써, 절차지형적인 조건문 분기를 없애는데 그 목적이 있습니다. 만약 State 디자인 패턴을 도입해서 조건문 분기가 늘어난다면, 저는 상태 디자인 패턴을 도입할 이유가 없다고 생각합니다."*

→ **3 가지 학습**:

#### 6.1. *디자인 패턴 도입 = 해결 문제 해결되어야 함*

- *학생: State 패턴 도입 후 조건문 분기 잔존* = *패턴 효과 X*.
- *MCP 룰 후보 `design-pattern-without-effect`* = *패턴 도입 후 의도 효과 X 시그널*. PR #98 (chaehyuns *상태 패턴 효과 자가 의문*) 결.

#### 6.2. *State 패턴 핵심 = 절차지향 조건문 제거*

- *유한 상태 기계 객체화 = 분기를 객체 다형성으로 위임*.
- PR #93·#136·#152·#43 결.

#### 6.3. *반복된 reviewer 의도 명시*

ghojeong 의 *"제가 State 에 집착하는 것은"* (아래 §8 안드로이드 비유) — *동일 메타 어휘 반복 강조*.
