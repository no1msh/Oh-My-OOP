## 못한 점 (설계 관점)

### 1. index loop = 절차지향 + LISP / Lazy Evaluation 어휘 (Thread 1) — 정점

```kotlin
for (i in 0 until players.size) { players[i]... }
```

reviewer:

> *"size 크기를 통한 index 가 사용된 반복문이 있다면, **굉장히 절차지향적인 코드를 짜고 있지는 않나 의심해 볼 필요가 있습니다.***
>
> *절차지향이 나쁘다는 의미는 아닙니다. 하지만 **index 를 통한 Element 의 접근은 가상메모리와 1대1 대응이 되는 \"Array\" 를 위한 문법이지, \"List\" 를 위한 문법은 아닙니다.***
>
> ***[List 는 LISP](https://www.tutorialspoint.com/lisp/lisp_lists.htm) 라는 프로그래밍 언어에서 중요하게 도입되었던 개념인데, 전통적으로 List 는 single linked list 를 뜻합니다. 즉 index 가 5라면 List 에서 5개의 node 를 루프를 돌아서 건너뛰어야 한다는 것을 의미합니다.***
>
> *요즘은 메모리가 부족한일이 없어서 HashMap 형태로 최적화가 되어있지만, 만약 함수형 프로그래밍을 연습하고자 한다면, **index 를 사용하지 않도록 연습하시는게 좋습니다. 왜냐하면 이러한 연습이 Lazy Evaluation 이라는 함수형 프로그래밍의 특성을 익히는데 큰 도움이 되기 때문**입니다."*

학생 자가 답변:

> *"HashMap으로 최적화되어 있는지 처음 알았습니다. 감사합니다. Lazy Evalutation을 사용하기 위해 Sequence를 활용하겠습니다."*

reviewer 정정:

> *"엄밀히 이야기 하면 JVM 은 ArrayList 로 최적화가 됩니다. 하지만 코틀린은 자바스크립트로 컴파일도 가능하므로, 넓은 의미에서 해시맵이라고 표현하였습니다."*

학생: *"List로 초기화하면 MutableList가 불리고 MutableList에서 ArrayList에 값을 넣는 방식이라는 것을 배우게 됐습니다. 감사합니다!"*

→ **MCP 룰 `index-loop-as-procedural-signal`** ⭐⭐⭐ **신규 정점** — *index loop = 절차지향 시그널 + LISP single linked list + JVM ArrayList vs HashMap 어휘 + Lazy Evaluation 함수형 특성*.

→ **MCP 룰 `kotlin-sequence-as-lazy-evaluation`** ⭐⭐ — *Sequence = Lazy Evaluation 어휘*.
