### 2. `Card.from(cardProvider)` vs `cardProvider.provide()` 양가성

말리빈: *"아래코드에서 카드를 한 장 가져오는데, cardProvider만 있어도 충분해보이는데 이렇게 구성하게 된 이유가 궁금해요 :)"*

```kotlin
val cardProvider: CardProvider = ~~
val card1 = cardProvider.provide()
val card2 = Card.from(cardProvider)
```

학생 자가 정당화: *"만약 Card가 현재 프로덕션에서 사용하고 있는 RandomCardProvider가 아니라 다른 종류의 CardProvider를 사용하고 싶을 경우 `val cardProvider: CardProvider = RandomCardProvider`코드를 수정하기 보다 `from()`메서드의 파라미터를 통해 전략을 수정해주고 싶어서 위와 같이 작성하였습니다!"*

말리빈 반박:

```kotlin
var cardProvider: CardProvider = RandcomCardProvider()
val card1 = cardProvider.provide()

cardProvider = OtherCardProvider()
val card2 = cardProvider.provide()
```

*"아래 코드 처럼 cardProvider만을 가지고도 충분히, 원하는 'RandomCardProvider가 아니라 다른 종류의 CardProvider를 사용하고 싶을 경우' 를 지킬 수 있어보이네요!"*

→ **3 가지 학습**:

#### 2.1. *Card.from(provider) = 책임 누수*

- *Card 가 *provider 알기* = *Card 가 *생성 전략* 인지*.
- *학생 의도 = 전략 선택 가능성*. *현실 = `var cardProvider` 변경* 으로 충분.

#### 2.2. *Card 가 provider 의존 = 양방향 의존 위험*

- *학생: Card → CardProvider 의존*.
- *추가 의존성 = 결합도 증가*.

#### 2.3. *학생 자가 의도 명시 + reviewer 단순 대안 제시*

**MCP 룰 후보 `redundant-factory-with-strategy-parameter`** = *전략 객체 + 정적 팩토리 + 전략 인자 = 중복*.

### 7. `HandCards` 생성자 초기값 양가성 — 학생 자가 의문

말리빈: *"HandCards 의 생성자로 초기 값을 넣을 수 있게 재구성해보는 건 어떨까요?"*

학생 자가 정당화:

```kotlin
class HandCards {
    private val _cards = mutableListOf<Card>()
    val cards: List<Card>
        get() = _cards.toList()
    fun addCard(card: Card) {
        _cards.add(card)
    }
}
```

*"현재 HandCards에서 생성자로 초기 값을 넣어주려면 주생성자에 cards가 들어가야 하고 그러기 위해서는 카드를 한장씩 add하는 것이 아니라 한번에 넘겨주야 하는데 게임 로직 상 한장씩 넘겨줄 수 밖에 없는 상황이 있는 것 같습니다,,ㅜ"*

말리빈 메타 질문: *"주생성자에 cards가 들어갈때, 이 cards는 반드시 멤버 변수로 동시에 선언되어야할까요?"*

→ **3 가지 학습**:

#### 7.1. *생성자 인자 ≠ 멤버 변수*

- *`class HandCards(cards: List<Card>)` (멤버 X)* — *생성 시 받지만 내부 mutable list 로 변환*.
- *`class HandCards(val cards: List<Card>)` (멤버 O)* — *외부 노출*.

#### 7.2. *학생 자가 잘못된 가정*

*"주생성자에 cards가 들어가면 자동으로 멤버"* 가정 = *Kotlin 어휘 미숙*.

#### 7.3. *PR #145 와 같은 결*

PR #145 (junseo511 *Hand initialCards 7 단계 토론*) / PR #76 (Yunseok-Nam 1단계 *HandCards 테스트*) 결.
