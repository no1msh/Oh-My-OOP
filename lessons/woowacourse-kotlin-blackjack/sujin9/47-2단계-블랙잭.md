reviewer:

> *"메서드 참조를 잘 활용해주셨네요. 👍 일반 함수에 비해 메서드 참조가 갖는 장점은 무엇인지 학습해보시면 어떨까요?"*

학생 자가 답변 정점:

> *- 만약 `game.startGame(participant) { ResultView.printSetUp() }` 과 같은 형태로 쓰게 된다고 했을 때, 만약 함수에 매개변수가 있는 경우라면 매개변수를 함께 담아서 함수를 전달해야 합니다. 하지만 메소드 참조를 사용하면 이를 나중에 지정해줄 수 있다는 장점이 있는 것 같아요!*
>
> ***제가 말한 부분이 맞는지, 혹은 놓친 부분이 있을지 궁금해요!*** 😄"*

> *"잘 정리해주셨습니다. 👍 첨언드리자면, **메서드 참조는 input을 가공없이 그대로 함수 파라미터로 전달하기 때문에, 데이터가 전달되는 과정에서 훼손되지 않았음을 확신할 수 있습니다.** 즉, 동일한 input이면 동일한 output이 나올 것이라 기대할 수 있습니다.*

### 2. 테스트 커버리지 100 강박 vs 의미 (Thread 8) — 정점

```kotlin
// BlackjackGameTest
@Test
fun `게임을 오류없이 실행한다`() {
    BlackjackGame().apply {
        startGame(participant, ::output)
        runPlayer(participant.players, ::isHit, ::output)
        runDealer(participant.dealer, ::output)
    }
}
```

reviewer: *"게임을 오류없이 실행한다는 것은 어떤 의미일까요? 여기서 말하는 \"오류가 없다\" 라는 것은 어떤 오류를 말하는 걸까요?"*

학생 자가 답변:

> *"게임이 전체적으로 중간에 종료되거나 다른 오류 없이 잘 끝나는, 전체적인 로직의 `흐름`에 대한 테스트를 하고 싶어서 이렇게 작성하였었습니다. 다른 구체적인, 디테일한 오류들에 대해서는 다른 단위 테스트들이 있기 때문에 모든 경우의 수를 테스트하는 것은 굳이 필요하진 않다고 생각했어요!*
>
> ***혹시 이런 상황에서는 테스트가 굳이 필요한지, 필요하다면 어떻게 테스트를 하면 좋을까요?*** 다른 더 나은 테스트 방법이 있는지, 혹은 커트라면 어떻게 테스트를 작성하실지 궁금해요 😊"*

reviewer 정점:

> *"적어도 테스트는 명확한 요구사항이 기재되어야 합니다. 그렇지 않은 테스트는 의미가 없으며, **반드시 성공하는 테스트 코드를 작성하기 쉽게 됩니다.** 또한, 테스트 코드에는 가급적이면 로직을 넣지 않는 것이 좋습니다.*
>
> *모든 로직에 단위 테스트를 작성하는 것은 좋으나, **그렇다고 반드시 성공하는 테스트를 작성하는 것은 의미가 없습니다. 저라면, 이런 경우라면 차라리 테스트 코드를 작성하지 않습니다.** 그럼에도 불구하고 테스트 코드를 작성해야한다면, \"BlackJackGame 객체를 생성합니다.\" 와 같은 테스트 코드를 작성할 수 있을 것 같아요."*

학생 자가 답변:

> *"모든 로직에 테스트를 작성해야 한다는 생각과, 굳이 이게 작성할 필요가 있는 테스트인가에 대한 고민이 계속 있었는데 의견 감사해요! :)*
>
> ***앞으로 다음 미션에서는 테스트 커버리지를 100 만드는 것만 생각하기 보다는, 테스트의 의미에 더 집중해야겠어요*** 😄"*

→ **MCP 룰 `coverage-100-vs-test-meaning`** ⭐⭐⭐ **신규 정점** — *테스트 커버리지 100 강박 vs 테스트 의미 — 학생 자가 자각*.

→ **MCP 룰 `always-passing-test-anti-pattern`** ⭐⭐⭐ **신규** — *"반드시 성공하는 테스트 = 의미 없음 + 차라리 안 쓰는 게 낫다"* reviewer 명시 어휘.

→ **MCP 룰 `test-with-logic-anti-pattern`** ⭐⭐ — *테스트 코드에 로직 포함 X*. PR #14·#48·#86 (테스트 어휘) 결 합류.

→ **MCP `oh-my-oop` 핵심 가치 학생 측 메타 어휘** — *커버리지 100 강박 자가 자각*. PR #18 (`student-honest-no-deep-thought`) 결의 학생 솔직 인정 다른 축.
