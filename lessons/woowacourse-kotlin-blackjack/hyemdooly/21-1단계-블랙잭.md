### 2. `Cards` 중복 카드 invariant — init + add 양쪽 검증

```kotlin
class Cards(cards: List<Card>) {
    private val _cards = cards.toMutableList()
    val cards: List<Card>
        get() = _cards.toList()
    ...
    init {
        require(cards.distinct().size == cards.size) { CARD_DUPLICATE_ERROR }
    }

    fun add(card: Card) {
        require(!_cards.contains(card)) { CARD_DUPLICATE_ERROR }
        _cards.add(card)
    }
    ...
}
```

→ **카드 중복 invariant 강제** — *init 시점 distinct 체크 + add 시점 contains 체크* 양쪽 모두. **backing property + 방어적 복사 패턴** (PR #18 결 + PR #46·#36 결).

다만 **doubly-enforced invariant 중복 비용**:
- init 시점 distinct = O(n)
- 매 add 시점 contains = O(n)

→ *MutableSet 자료구조 대안* (PR #23·#26 결).

### 3. `abstract class Participant` + Dealer/Player 상속 — 다형성 hit 판정

```kotlin
abstract class Participant(val cards: Cards, val name: Name) {
    abstract fun isHit(): Boolean
    fun isBust(): Boolean { if (cards.sum() > BUST_POINT) return true; return false }
    fun pick(cardPack: Cards) { cards.add(cardPack.pop()) }
}

class Dealer(...) : Participant(cards, name) {
    override fun isHit(): Boolean = cards.sum() < HIT_STANDARD_POINT
}

class Player(...) : Participant(cards, name) {
    override fun isHit(): Boolean = !isBust()
}
```

→ **`isHit()` 다형성 자가 적용** — *Dealer = 16 이하 hit, Player = bust 아니면 hit*. **Tell-Don't-Ask 적용**. PR #16·#98·#91·#43·#73·#80·#87 결.

**MCP 룰 `nested-builder-readability` 후보** — *buildList/forEach/map 중첩 4단계 = 읽기 어려움*.

### 9. `LinkedList` 자료구조 활용

reviewer (Thread 15):

> *"LinkedList와 같이 이미 잘 만들어져있는 자료구조를 활용해봐도 좋겠네요."*

**MCP 룰 `data-structure-choice-deck` 후보** — *카드덱 자료구조 = LinkedList vs ArrayDeque vs MutableList rear-pop*. PR #58·#23·#26 결.

### 13. `Cards.sum()` 함수 — 합산 로직 일부 외부에 (Rank.getScore)

### 16. `Participants.of(dealer, players)` `listOf(dealer as Participant) + players.toList() as List<Participant>` — 캐스팅 누수
