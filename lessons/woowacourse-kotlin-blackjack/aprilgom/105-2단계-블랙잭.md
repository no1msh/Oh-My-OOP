PR 본문:

> *"이전 단계에서 StrengthPolicy에 대한 설명이 필요하다는 피드백 남겨주셨는데요,*
>
> *(스크린샷 첨부)*
>
> ***strength는 족보의 순위라 생각하시면 될 것 같습니다.** (위 쪽으로 갈 수록 강한 패이고, 아래쪽으로 갈수록 약한 패입니다.)*
>
> *그러면 출력할 때 블랙잭은 22, bust일때는 -1이나 0이 나오지 않는가? 라는 피드백을 주셨는데요, **참가자끼리 승패를 비교할 때는 이 strength를 이용해 비교를 하고, 점수 출력을 할 때에는 손에 있는 카드 점수의 총합을 이용해 출력합니다.***
>
> *예를 들어, 손에 10,10,7 카드가 있다고 할 때 bust가 되었으니 strength가 0 or -1이나 출력할때는 손 패의 카드 점수 총 합인 27을 출력합니다. (...) **이 두 패의 승부를 낼 때는 손 패의 카드 점수 총 합인 27, 21로 비교하는 것이 아니라 strength인 0, 22로 비교하여 승부를 냅니다.***
>
> *딜러의 bust가 플레이어의 bust를 이기기에 StrengthPolicy 인터페이스를 만들고 딜러와 플레이어가 각기 다른 구현체를 받게 해 차이를 두고자 했습니다. (굳이 인터페이스를 쓴 이유는, Participant 안에 when문을 길게 넣고싶지 않아 인터페이스로 따로 뺀 것입니다.)"*

→ **MCP 룰 `pr-body-domain-vocabulary-with-screenshot`** ⭐⭐⭐ **신규** — *학생 자가 도메인 어휘 상세 설명 + 이미지 첨부 + 분리 의도 명시*. PR #150 (`student-bug-discovery-with-screenshot`)·PR #144 (m6z1 셀프 코드 리뷰) 결 합류 누적 3 PR — *학생 자가 스크린샷 어휘 정점*.

→ **MCP 룰 `score-display-vs-score-compare-separation`** ⭐⭐⭐ **신규** — *점수 출력 = cards.scoreSum / 점수 비교 = strength* 분리 어휘. PR #134 (`score-vs-blackjack-score-locus`)·PR #50 (`bjackjack-vs-normal-win-different-responsibility`) 결 합류 누적 3 PR → ***도메인 책임 분리 어휘 정점*** ⭐⭐⭐.
