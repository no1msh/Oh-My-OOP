### 1. `enum class` 내 매직 넘버 — 학생 자가 의문 + woowahan-leah 답변

학생 자가 의문 (PR #1, 본문): *"companion object로 선언할 수 없는 enum class 내부에서 쓰이는 매직 넘버들은 어떠한 형식으로 처리해야하는지 궁금합니다!"*

woowahan-leah 답변 (위 §잘한점):

```kotlin
enum class GameResultCondition(
    val gameResult: GameResult,
    val condition: (playerScore: Int, dealerScore: Int) -> Boolean
) {
    ...

    companion object {
        private const val ...
    }
}
```

학생 후속 자가 의문: *"처음에 companion object의 상수를 enum class안에서 이용하려고 했었습니다. 그런데 enum class의 인스턴스들이 생성되는 시점에 companion object가 생성되지 않아서 사용할 수 없다는 것을 알게되었습니다! 이런 경우에 해당 파일의 상위에 private const val로 정의를 해도 괜찮을까요?"*

→ **3 가지 학습**:

#### 1.1. *enum class + companion object 생성 시점 양가성*

- *enum 인스턴스 생성 시점 (정적 초기화)* vs *companion object 생성 시점 (정적 초기화 이후)*.
- *enum 인스턴스 *생성자 인자에서 companion 상수 참조* 시 = ClassNotInitialized*.
- *enum 인스턴스 *메서드에서* companion 상수 참조 = OK*.

**MCP 룰 후보 `enum-companion-init-order`**.

#### 1.2. *enum 외부 top-level private const val 양가성*

- *enum 외부 파일 상수 = 다른 곳에서 참조 가능 (의도 누수)*.
- *enum 내부 companion = 응집 (단, 위 §1.1 시점 주의)*.

PR #22·#11 (vagebond95/galcyurio *상수 위치*) 결.

#### 1.3. *PR #22 (RightHennessy) 의 *enum 내 companion object 불가* 잘못된 가정* 반대 시점

학생 자가 *enum 인스턴스 생성 시점* 인식 = *Kotlin 어휘 깊은 자가 학습*.
